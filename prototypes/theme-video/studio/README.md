# Plunode 映像制作室

公開テーマを選び、日英の横長動画を手元で作り、場面を見ながら採用版を決めるための制作画面。通常の入口は [localhostの映像制作室](http://127.0.0.1:3269/)。サイドバーには、原資料・完成映像・改稿理由を見比べられるウォークマンの品質見本がある。

## 起動

今回動作を確認した環境はWindows、Python 3.11、FFmpeg、Pillow、NumPy、Windows標準フォント、日本語のVOICEVOXとローカルのCodex CLI。CLIはこの端末でログイン済みのアカウントを使う。制作画面で「脚本・編集モデル」を選ぶと、「推論の強さ」にそのモデルが対応する設定が出る。このPCではAstraとSolがともにUltraに対応している。新規案件と作り直しは「高」で開き、英語への翻案は元の日本語版の設定で開く。いずれも実行前に変更できる。

リポジトリのルートで実行する。英語音声の初回準備はKokoro-82Mと音声ライブラリのダウンロードを含む。このPCでは準備済み。

```powershell
python -B prototypes/theme-video/studio/setup_media.py
python -B prototypes/theme-video/studio/start.py
```

二回目以降は `start.py` で起動できる。既に起動中なら入口URLを表示する。日本語はVOICEVOXの青山龍星、英語はKokoroの `af_heart`。日本語は標準インストール先のエンジンを必要時に起動する。起動済みのエンジンを使う場合は `PLUNODE_VOICEVOX_URL`、実行ファイルを指定する場合は `PLUNODE_VOICEVOX_EXE` を設定する。

## 一件を作る

切り口を見比べたいときは、「新しい案件」でテーマとモデルを選び「動画案を生成して保存」を押す。候補は[保存した動画案](http://127.0.0.1:3269/#ideas)に残る。仮題・冒頭・見終わったときの発見を読み、気に入った案を「あとで作る」に置くか、その案から台本・動画の制作に進む。同じ案から何度でも独立した案件を始められる。それぞれが企画時点のテーマ版を引き継ぎ、台本、映像、採用判断は案件ごとに保管する。案から過去の制作にも戻れる。追加資料や絵が要る場合は、その内容も案と一緒に残る。

1. 「新しい案件」で公開テーマを選び、「日本語の動画を生成」を押す。初期設定は日本語先行。モデルと公開版は選択済みで、切り口は空欄でもよい。同じ案件の中で版を比較するときは「この案件に試行を追加」を開く。従来の日英同時制作も選べる。
2. 映像にする前に語りや読みを確かめたいときは「台本を先に確認」を選ぶ。日本語先行では、企画と大筋、初稿、狙いを伏せたAIによる初見読解、再構成と清書、清書稿と依頼・根拠の照合を進める。初めの企画は必要な絵から考え、使える素材を当てるのは初稿の段階。完成した稿は「台本を通して読む」で読める。「日本語台本の見直し記録」を開くと、初稿で残った疑問、改稿の理由、各要点がどの場面で伝わるかを確認できる。場面ごとの出典や読みも引き続き開ける。
3. 日本語の場面では、字幕の表記と読みを指定し、「この場面を試聴」で確認できる。たとえば「一日」は文脈に応じて「ついたち」「いちにち」を選ぶ。「語りの前」「語りの後」には絵を見せる秒数を入力する。空欄は自動、0秒ならすぐに次へ進む。複数の場面を直すときは「台本に保存して編集を続ける」で修正版を作り、最後の台本を一度書き出す。元の映像と修正理由は履歴から確認できる。
4. 日本語の映像を試写し、使いたい版を表示して「この日本語版から英語版を作る」を選ぶ。英語のモデルには選んだ版の場面・根拠・日本語原稿を渡す。英語の語り、図中の言葉と、実際の発話に合わせた間を持つ別の版ができる。「別の版と比較」で同じ場面を並べられる。
5. 観て選んだ版に言語ごとの採用理由を記録する。直すべき点が残る版には「要修正」と理由を付けて残せる。中断は工程の区切りで効き、再開時は保存した脚本・完成済みの言語版と音声キャッシュを利用する。初稿も修正版も後から再生できる。

脚本の生成中に見出しの字数や読み指定に問題が見つかると、制作室がその稿と指摘を同じ工程のモデルへ返す。そのまま待てば、該当工程で最大2回まで自動で修正する。「要改稿」で止まったときは、生成履歴の理由を読み、「改稿を再開」を押すと直近の稿の続きから改稿できる。原資料が足りない場合は自動でウェブを調べ、確認できた抜粋と掲載箇所を同じ試行に保存して台本を練り直す。生成履歴から追加資料と未確認の点を読める。「資料待ち」は、調査後も根拠や使える図版が足りない状態。「追加調査して再開」で前回の調査を引き継ぐ。

## データと素材

既定の保存先は `%LOCALAPPDATA%\Plunode\video-studio`。案件台帳は `studio.sqlite3`、成果物は `cases/<案件ID>/<試行ID>/<ja または en>/` にあり、映像・字幕・場面時刻・音声と画像の出典を保存する。別の保存先を使う場合は `start.py --data <ディレクトリ> --port <ポート>`。台帳と `cases` を一緒に保管すれば履歴から映像に戻れる。音声モデルと再利用できる音声キャッシュは別の `%LOCALAPPDATA%\Plunode\video-studio-media` に置く。

ウェッブの観測画像はNASAが公表したものを同梱し、各画像の掲載元とクレジットを記録した。ウォークマンは比較用の固定映像。その他のテーマでは、選んだ版の根拠と資料名を使う場面を生成できる。企画を支える画像や根拠が足りない場合は、制作に必要な素材と理由が表示される。[画像とクレジット](assets/webb.json) ／ [ウォークマンの比較用資料](../walkman/README.md)

指定モデル・推論設定と使用量を記録する。CLIが返さない内部の実モデルIDは不明と表示する。新しい脚本の試行では実際に送った資料・指示と出力形式も `editor-input.json` に保存する。Webbで初めて制作画面を通した時点の指示は第1版であり、その初稿では入力原文ファイルの保存前だった。前稿から直接直した場合は、親試行と修正理由から変更をたどれる。

この制作室はこのPCのループバックで動く。Plunodeとは公開資料の読取で接続する。YouTube配信とテーマページへの掲載は制作後の工程として設計している。[制作運用と配信の設計](../../../docs/design/THEME_VIDEO_OPERATIONS.md)

## このPCで通した制作案件

「ウェッブ、星の像で鏡を読む」の最新の日本語試写版は2分01.17秒。前稿で評価された六角形の写真、B3の像が右下から鏡と同じ右上に来る比較、続く模式図を活かし、同じ八場面から編集した。冒頭で、打ち上げ後に本格的な観測を準備している時期と、十八枚を一枚の大きな鏡として働かせる目的が分かる。結びの「調整中の変化を追うための地図」を、写真の右上を見れば右上の一枚の写り具合が分かるという具体例に置き換えた。[最新の日本語版を再生](http://127.0.0.1:3269/media/ec8bd467726e42d5a2723570bf0e175c/2eeed411bab243ecad7fb78ce5542cc1/ja/video.mp4) ／ [制作室で旧版と比較](http://127.0.0.1:3269/#case/ec8bd467726e42d5a2723570bf0e175c) ／ [NASAの観測準備と初期調整の記録](https://science.nasa.gov/blogs/webb/2022/02/03/photons-incoming-webb-team-begins-aligning-the-telescope/)

前稿では、比較図の語りが終わってから次の模式図で話し始めるまで約11秒あった。新稿は直前に「一つひとつの像をくっきりさせていきます」と予告し、模式図で変化を見る間を2.5秒取った。書き出した両版のAAC音声を同条件（10ms窓のRMS、−50 dBFS）で測ると、この境界は11.17秒から2.87秒、七つの境界の合計は39.30秒から8.66秒になった。1分22.42秒の映像では右上の光のにじみがすでに小さくなり、語りは1分22.71秒に入る。合成音声の速度設定を保ち、全23発話の読みと、字幕・書き出し音声の対応を照合した。 初見のAIは結びの「一枚」が鏡と写真のどちらを指すのか一瞬迷った。仕上げに二箇所の言葉を具体化した。比較図では鏡と同じ六角形に並べたものを「十八の光の点」と呼び、最後は「それぞれの鏡で星がくっきり写るのを確かめてから」と、写りを確かめる対象を明示した。

「ウェッブ、星の像で鏡を読む」は、第42版の資料から日本語先行・Astra／Ultra指定で制作した。8場面、2分40.58秒（末尾のクレジット7秒を含む）。六角形に並んだ18の像の観測写真から始まり、初期は右下に写ったB3の像が、並べた後は鏡と同じ右上にあると分かる。1分41秒からは、右上の像だけがくっきりする新作の模式図。作中に示す変化は使い道を試すための例である。最後に最初の写真を見ると、点の位置から鏡をたどれる。[日本語版を再生](http://127.0.0.1:3269/media/ec8bd467726e42d5a2723570bf0e175c/458ae43c00ed4676a067b2d6a5dff846/ja/video.mp4) ／ [台本・初稿・見直し記録](http://127.0.0.1:3269/#case/ec8bd467726e42d5a2723570bf0e175c) ／ [NASAによる配列の意図の説明](https://science.nasa.gov/blogs/webb/2022/02/18/webb-team-brings-18-dots-of-starlight-into-hexagonal-formation/)

素材を知らせずに立てた企画に「一つの像の変化から、どの鏡だったか探せる場面」が出た。初稿の段階で作画を挟み、変更した素材で初稿から再開した。企画意図を渡さずに初稿を読んだAIは、鏡と点の対応は並べる前に分かっていて、後の調整で変化を追いやすくするために同じ並びにした、と読み取った。清書では位置をそろえる段階と像を鮮明にする段階の違いを語りに加え、6つの要点を清書の台詞と絵に照合した。B3の読みを「ビースリー」にそろえ、完成MP4で全25発話の字幕・読み・音声の対応を確認した。完成映像を制作意図なしで見た別のAIには、B3の位置が変わったことで配列の理由まで伝わった。一方、模式図で右上の像が暗くなったようにも見えたため、図中の光の総量を保ち、明るい中心に集まる描写へ直した。台本と間を同じにした二つの版は台帳から比較できる。運営者による公開判断は未確定。

Webb第42版の別稿「鏡を一枚、動かすと」では、Astra／Ultraを指定し、日本語だけの五場面を生成した。鏡片を一枚ずつ動かして各星像と対応づける手順を、左の鏡が傾くと右の点が一つだけ動く模式図にした。図はこの稿のために制作し、移動の向きと距離は説明用。Ultraの初稿を保存し、冒頭と実際の観測写真に戻る二場面の語りを編集した。最終版は58.25秒。画面の見出しを「どの鏡が映した光？」にそろえ、26秒の「ひとつ、動きました」の前に一点の動きだけを観る間を置いた。全14区間で字幕と書き出し音声を照合した。試写では、鏡と点を見分けた先の「なぜ六角形に並べたか」が抜けたため、日本語版を要修正に戻した。改稿前に狙いを伏せてこのMP4の絵と焼き込み字幕を見たAIも「右下の点ならB3に指示を送る」と理解したところで説明を終えた。前稿とは絵と編集条件も異なる。[日本語試作を観る](http://127.0.0.1:3269/media/e5702e8e0aad4aee941ab3941576f3da/ed347672c7fc41718ffcc62fd11c14f2/ja/video.mp4) ／ [このPCの試写案件](http://127.0.0.1:3269/#case/e5702e8e0aad4aee941ab3941576f3da) ／ [NASAの識別手順](https://science.nasa.gov/blogs/webb/2022/02/03/photons-incoming-webb-team-begins-aligning-the-telescope/)

日本語先行の試作「右下の光を、もう一度」は、Webb第42版の写真に写った一点を追う。前回と同じAstra／高に日本語の初稿を依頼し、鏡の模式図、写真の拡大、同じ鏡を結ぶ線を今回のために作画した。場面ごとの語りを改稿し、初回の書き出しを試写して、結びで右下の点を囲う順番と「右上」の読みを直した。運営者の試写では、見直しの余地はあるが現状の品質での公開は見送り。日本語を「要修正」として台帳に記録した。英語は未生成。[日本語試作の案件](http://127.0.0.1:3269/#case/c72bcc143c924be3910d98c6a5a95a5d) ／ [試写用の日本語映像](http://127.0.0.1:3269/media/c72bcc143c924be3910d98c6a5a95a5d/cc688c772c124ac7b27f792b074bf85d/ja/video.mp4)

最終試作は75.29秒。書き出した日本語音声と字幕を全17区間で照合し、二度ずつ出てくる「十八」「B3」「右上」が「じゅうはち」「ビースリー」「みぎうえ」と合成されたことを確かめた。59秒には右下の一つだけ、62秒にはその周りにも輪が出る。初見でどこに目が行くか、合成音声の抑揚が心地よいかは試写で確かめる。

2026年11月25日、EdgeでWebb第42版・Astra／高を選び、6場面の「一つの星、十八の光」を生成した。試写した日本語版は54.25秒、英語版は51.46秒。いずれも1280×720・24fpsのH.264映像とAAC音声で、12区間の字幕を再生時刻、音声信号、台本の文と照合した。試写後は日英とも「要修正」。視聴者には内容がほとんど伝わらず、ウォークマン回との画面スタイルの差が大きかった。日本語には漢字の誤読もあった。指摘された語は特定していない。[このPCのWebb案件を開く](http://127.0.0.1:3269/#case/03378e586e40459b8d115396e0585971)

この案件で英語の結びを直す途中に処理を止め、制作室を再起動した。当時選択していた日本語と英語の旧稿を再生し、英語だけを再開した。試写中に別の場面へ修正が入った稿は理由付きで保管し、編集フォームでは修正先の版・言語・場面を固定するようにした。英語の第2・第6場面だけが初稿から変わり、日本語の試行は1本のまま。作品の再評価に使うのは、初見での理解、日英の実聴、ウォークマン回との見比べ。モデル別の初稿比較はこの条件を揃えて行う。

台本先行の動作は別の検証用台帳で確認した。Webb第42版・Sol／高の6場面でいったん停止し、Edgeで日本語の読みを試聴・修正してから映像生成を実行した。日本語51.625秒・英語49秒を再生でき、どちらも「確認待ち」で終了した。ウォークマン回の共通描画への移行では、日英の検証用44フレームが変更前の画素と一致した。旧案件は作成時の資料を固定しているため、後から補った資料の抜粋を使う場合は、同じテーマ・版で新しい案件を作成する。
