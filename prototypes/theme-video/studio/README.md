# Plunode 映像制作室

公開テーマを選び、日英の横長動画を手元で作り、場面を見ながら採用版を決めるための制作画面。ウォークマンと「キャベツ畑まで、2.5秒。」を品質見本として試写できる。[localhostの映像制作室](http://127.0.0.1:3269/)

## 起動

今回動作を確認した環境はWindows、Python 3.11、FFmpeg、Pillow、NumPy、Windows標準フォント、日本語のVOICEVOXとローカルのCodex CLI。CLIはこの端末でログイン済みのアカウントを使う。制作画面で「脚本・編集モデル」を選ぶと、「推論の強さ」にそのモデルが対応する設定が出る。このPCではAstraとSolがともにUltraに対応している。新規案件と作り直しは「高」で開き、英語への翻案は元の日本語版の設定で開く。いずれも実行前に変更できる。

このPCではWindowsにサインインすると制作室がバックグラウンドで起動する。[制作室を開く](http://127.0.0.1:3269/)。既存案件の保存先は `%LOCALAPPDATA%\Plunode\video-studio`。起動を担当するタスクは `Plunode-VideoStudio` で、WSLの準備中などで失敗したときは1分間隔で最大5回再試行する。Windowsやリポジトリの移設後は、Windows PowerShellでリポジトリのルートから次のコマンドで再登録できる。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\prototypes\theme-video\studio\install-logon-task.ps1
```

手動で起動する場合もリポジトリのルートで実行する。英語音声の初回準備はKokoro-82Mと音声ライブラリのダウンロードを含む。このPCでは準備済み。

```powershell
python -B prototypes/theme-video/studio/setup_media.py
python -B prototypes/theme-video/studio/start.py
```

二回目以降は `start.py` で起動できる。既に起動中なら入口URLを表示する。日本語はVOICEVOXの青山龍星、英語はKokoroの `af_heart`。日本語は標準インストール先のエンジンを必要時に起動する。起動済みのエンジンを使う場合は `PLUNODE_VOICEVOX_URL`、実行ファイルを指定する場合は `PLUNODE_VOICEVOX_EXE` を設定する。

## 外出先から開く

このPCの制作室は [外部用の制作室](https://c-movie.isinxnisi.com/) から開ける。Cloudflare Accessで許可したアカウントでサインインする。トンネルの転送先は `http://127.0.0.1:3269` で、元の公開ホスト名を渡す。Windowsで制作室とトンネルが稼働している間に利用できる。

移設時はWindowsの制作室用Pythonに `python -m pip install --user -r prototypes/theme-video/studio/requirements-access.txt` で認証用ライブラリを入れる。案件台帳と同じ保存先の `access.json` に `host`（外部ホスト名）、`team`（Cloudflare Accessのチーム名）、`audience`（対象アプリのAUDタグ）を文字列で保存し、制作室を再起動する。制作室は画面・API・動画の全リクエストで公開ホスト名とAccessの署名・発行元・対象アプリ・期限を検証する。外部の更新操作では同じHTTPS originも確認する。設定ファイルが無い場合はlocalhostから操作できる。

## 一件を作る

切り口を見比べたいときは、「新しい案件」でテーマとモデルを選び「動画案を生成して保存」を押す。候補は[保存した動画案](http://127.0.0.1:3269/#ideas)に残る。仮題・冒頭・見終わったときの発見を読み、気に入った案を「あとで作る」に置くか、その案から台本・動画の制作に進む。同じ案から何度でも独立した案件を始められる。それぞれが企画時点のテーマ版を引き継ぎ、台本、映像、採用判断は案件ごとに保管する。案から過去の制作にも戻れる。追加資料や絵が要る場合は、その内容も案と一緒に残る。

1. 企画から任せる場合は「新しい案件」で公開テーマを選び、切り口を空欄にして「テーマから日本語の動画を生成」を押す。案の一覧を経由せず、このテーマの資料から扱う発見と演出を選ぶ。保存案や停止した案件にある「このテーマから自由に企画」は、同じテーマと版を選んだ新規制作の設定を開く。設定を開いた時点では生成は始まらない。以前の案や制作記録も残る。
2. 既定の「題材から原画・動き・音を制作」では、演出家が場面を決め、作画者がその回の原画を描く。見せ場を絵や音だけで進めることもできる。「台本を先に確認」を選ぶと、書き出しの前に絵コンテと台本が開ける。各場面の最初・中間・最後の画を並べ、制作意図を伏せて絵を見た担当が何を読み取ったか、どこを直したかを確認できる。Webb用の観測写真など、登録済みの図版を使う場合は「既存の資料図版で制作」を選べる。
3. 日本語の場面では、字幕の表記と読みを指定し、「この場面を試聴」で確認できる。たとえば「一日」は文脈に応じて「ついたち」「いちにち」を選ぶ。「語りの前」「語りの後」には絵を見せる秒数を入力する。空欄は自動、0秒ならすぐに次へ進む。複数の場面を直すときは「台本に保存して編集を続ける」で修正版を作り、最後の台本を一度書き出す。元の映像と修正理由は履歴から確認できる。
4. 日本語の映像を試写し、使いたい版を表示して「この日本語版から英語版を作る」を選ぶ。英語のモデルには選んだ版の場面・根拠・日本語原稿を渡す。英語の語り、図中の言葉と、実際の発話に合わせた間を持つ別の版ができる。「別の版と比較」で同じ場面を並べられる。
5. 観て選んだ版に言語ごとの採用理由を記録する。直すべき点が残る版には「要修正」と理由を付けて残せる。中断は工程の区切りで効き、再開時は保存した脚本・完成済みの言語版と音声キャッシュを利用する。初稿も修正版も後から再生できる。

原画方式では、初見役が絵から読み取ったことを、編集者が企画・根拠・語りと照合する。監督は、前後の実画、現在の原画、過去の修正内容を見て、同じカットを直接編集できる。他の場面の素材も使える。作画が必要なときは、監督が狙いと使いたい原画を指定して依頼する。

「保存稿の場面を試写」で指摘の残るカットを選ぶと、「前後を含めて試写」で音・字幕付きで見られる。前後はそれぞれ最大1秒、対象カットは全編を収録する。試写の操作で映像生成モデルを呼ぶことはない。「改稿を再開」は、直近に試写した原画・初見の観察・未解決の指摘を読み、修正から始める。停止理由では中心の発見が届いたかと、各場面で何が残ったかを確認できる。

一度の実行で、新しい初見・編集照合は最大5回。ある場面を2回続けて現状維持とし、3回目の新しい照合でもその場面に指摘が残った場合は早めに区切る。過去の稿を往復した場面では、当時の選択と戻した理由を監督に渡す。同じ前後関係で同じ編集結果を繰り返そうとしたときは、別の手を検討する。

資料図版方式では初稿、初見読解、再構成と清書、独立照合を行う。冒頭の出典カードを白地にするなどの指定は台本・画・最終確認に渡る。同じ問題が繰り返される場合や、一度の実行で新たに5稿を照合しても通らない場合は指摘を保存する。

原資料が足りない場合は自動でウェブを調べ、掲載本文と引用が一致した資料を保存して台本を練り直す。文字入りPDFでは、引用を見つけたページも記録する。1回の実行・再開で調査は最大2回。生成履歴の調査記録で追加資料と残った問いを読める。

資料が揃いきらないときは、選んだ案で視聴者に何を約束したかを改めて読む。たとえば批評家の観察をその人の言葉として紹介したり、自作の図で技法を体験してもらったりして、その約束を果たせるなら同じ試行で改稿する。別の発見を届ける一本が成立しそうなら、元の試行に別案を表示する。「この別案で新しい試行を開始」を選ぶと元の試行と調査記録を残して制作できる。元の案を追う場合は「追加調査して再開」を使う。心当たりのある公開資料のURLを添えられる。

## 制作が止まったとき

停止した試行の説明は、案件の先頭と生成履歴の「停止理由と次の操作」で読める。テーマと選んだ企画に続いて、どの部分で止まったか、予定した視聴体験にどう影響するか、選べる操作を表示する。技術上の失敗や手動中断には、それぞれの再開手順を表示する。生成時の指摘や調査の詳細は履歴で確認できる。

「改稿を再開」は同じ試行の稿と指摘を引き継ぐ。「この台本をもとに新しい試行」は、保存済みの日本語台本がある試行で選べる。開いた制作設定には元の試行番号と題名が表示され、追加指示を入力して別の日本語台本を作れる。

### 制作中の案件と開発時の検証

不具合は保存済みの稿・審査記録・描画結果を読み、企画で求めた表現を台本に書けるか、書いた指定どおりに描けるか、審査にその画が届くかを調べる。修正は隔離した記録の複製、モデルの保存応答、ローカルの描画で確かめる。通常の開発検証で外部モデルの呼び出しや制作中案件の再開は行わない。実際の生成は運営者が画面から開始するか、その案件の生成を明示的に依頼したときに進める。

結果を報告するときは、保存応答で確認できた動作、実際のモデルで到達した工程、人が稿や素材を直した箇所を明記する。途中稿の確認と、ボタンから完成まで自動で通った実績は区別する。

2026年11月26日の原画方式では、開発用に紙の工作を題材に用意し、隔離台帳の新規作成から日本語MP4までを一度通した。Sol／高、4分49秒、完成16.25秒。依頼は「魚の色が変わったあとで、その後ろにある紙に気づく体験」。撮影に相当する原画、台詞、効果音は自動生成で、完成品にも手を加えていない。後半では魚の穴を通して色紙の境界が見える。冒頭は魚全体が茶色を経て変色し、帯を滑らせたときの横切る境界とは合わなかった。初見の観察にその茶色が記録されたが、当時の編集確認は通した。[そのままの試写映像](assets/paper-fish.ja.mp4)

この試写を受けて、原画を依頼する前に、一本を通して特に見てほしい場面と、どの時点で何が見えれば発見が伝わるかを決めるようにした。初見役はその狙いを知らずに画を見る。編集者には同じ実画と初見の観察を渡し、移動・境界・配置など、見せたい変化が実際に読み取られたかを照合する。途中の動きが合わず改稿に戻る経路は隔離したテストで確認した。この変更後に「紙のさかな」を再生成した実績はない。

## データと素材

原画方式では、直近に試写した全場面と初見の観察、残った指摘、実施済みの改稿を試行フォルダの `film-cut.json` にまとめて保存する。一つ前の方式でこのファイルがない試行は、工程記録から復元した全場面を当時の試写画像と照合して再開する。個々の依頼・応答と試写画像は `editor-stages`、運営者が試写した音付き抜粋は `cut-previews`、通過した絵コンテは `storyboard.jpg` にある。各言語の出力先には完成MP4から抜き出した `contact-sheet.png` を保存する。

固有名の綴りや資料名が見せ場なら、作画の上にその文字を組む。置く位置と大きさは場面ごとに指定し、英語版にも引き継ぐ。出典を紹介する場面だけ横に文字を置く、二つの名前を近くに置いて見比べる、ほかの場面では文字を引く、といった構成を選べる。

通常の入りではウォークマン回の4音を共通で使い、語りに重なる部分は音量を下げる。即座に語り始める場面や、ワイプの紙を払う音で始める場面は、その回で指定した入りを生かす。

既定の保存先は `%LOCALAPPDATA%\Plunode\video-studio`。案件台帳は `studio.sqlite3`、成果物は `cases/<案件ID>/<試行ID>/<ja または en>/` にあり、映像・字幕・場面時刻・音声と画像の出典を保存する。別の保存先を使う場合は `start.py --data <ディレクトリ> --port <ポート>`。台帳と `cases` を一緒に保管すれば履歴から映像に戻れる。音声モデルと再利用できる音声キャッシュは別の `%LOCALAPPDATA%\Plunode\video-studio-media` に置く。

ウェッブの観測画像はNASAが公表したものを同梱し、各画像の掲載元とクレジットを記録した。ウォークマンは比較用の固定映像。その他のテーマでは、選んだ版の根拠と資料名を使う場面を生成できる。企画を支える画像や根拠が足りない場合は、制作に必要な素材と理由が表示される。[画像とクレジット](assets/webb.json) ／ [ウォークマンの比較用資料](../walkman/README.md)

指定モデル・推論設定と使用量を記録する。CLIが返さない内部の実モデルIDは不明と表示する。新しい脚本の試行では実際に送った資料・指示と出力形式も `editor-input.json` に保存する。Webbで初めて制作画面を通した時点の指示は第1版であり、その初稿では入力原文ファイルの保存前だった。前稿から直接直した場合は、親試行と修正理由から変更をたどれる。

この制作室はこのPCのループバックで動く。Plunodeとは公開資料の読取で接続する。YouTube配信とテーマページへの掲載は制作後の工程として設計している。[制作運用と配信の設計](../../../docs/design/THEME_VIDEO_OPERATIONS.md)

## このPCで通した制作案件

「ウェッブ、星の像で鏡を読む」の最新の日本語試写版は2分01.17秒。前稿で評価された六角形の写真、B3の像が右下から鏡と同じ右上に来る比較、続く模式図を活かし、同じ八場面から編集した。冒頭で、打ち上げ後に本格的な観測を準備している時期と、十八枚を一枚の大きな鏡として働かせる目的が分かる。結びの「調整中の変化を追うための地図」を、写真の右上を見れば右上の一枚の写り具合が分かるという具体例に置き換えた。[最新の日本語版を再生](http://127.0.0.1:3269/media/ec8bd467726e42d5a2723570bf0e175c/2eeed411bab243ecad7fb78ce5542cc1/ja/video.mp4) ／ [制作室で旧版と比較](http://127.0.0.1:3269/#case/ec8bd467726e42d5a2723570bf0e175c) ／ [NASAの観測準備と初期調整の記録](https://science.nasa.gov/blogs/webb/2022/02/03/photons-incoming-webb-team-begins-aligning-the-telescope/)

前稿では、比較図の語りが終わってから次の模式図で話し始めるまで約11秒あった。新稿は直前に「一つひとつの像をくっきりさせていきます」と予告し、模式図で変化を見る間を2.5秒取った。書き出した両版のAAC音声を同条件（10ms窓のRMS、−50 dBFS）で測ると、この境界は11.17秒から2.87秒、七つの境界の合計は39.30秒から8.66秒になった。1分22.42秒の映像では右上の光のにじみがすでに小さくなり、語りは1分22.71秒に入る。合成音声の速度設定を保ち、全23発話の読みと、字幕・書き出し音声の対応を照合した。 初見のAIは結びの「一枚」が鏡と写真のどちらを指すのか一瞬迷った。仕上げに二箇所の言葉を具体化した。比較図では鏡と同じ六角形に並べたものを「十八の光の点」と呼び、最後は「それぞれの鏡で星がくっきり写るのを確かめてから」と、写りを確かめる対象を明示した。

「ウェッブ、星の像で鏡を読む」は、第42版の資料から日本語先行・Astra／Ultra指定で制作した。8場面、2分40.58秒（末尾のクレジット7秒を含む）。六角形に並んだ18の像の観測写真から始まり、初期は右下に写ったB3の像が、並べた後は鏡と同じ右上にあると分かる。1分41秒からは、右上の像だけがくっきりする新作の模式図。作中に示す変化は使い道を試すための例である。最後に最初の写真を見ると、点の位置から鏡をたどれる。[日本語版を再生](http://127.0.0.1:3269/media/ec8bd467726e42d5a2723570bf0e175c/458ae43c00ed4676a067b2d6a5dff846/ja/video.mp4) ／ [台本・初稿・見直し記録](http://127.0.0.1:3269/#case/ec8bd467726e42d5a2723570bf0e175c) ／ [NASAによる配列の意図の説明](https://science.nasa.gov/blogs/webb/2022/02/18/webb-team-brings-18-dots-of-starlight-into-hexagonal-formation/)

素材を知らせずに立てた企画に「一つの像の変化から、どの鏡だったか探せる場面」が出た。初稿の段階で作画を挟み、変更した素材で初稿から再開した。企画意図を渡さずに初稿を読んだAIは、鏡と点の対応は並べる前に分かっていて、後の調整で変化を追いやすくするために同じ並びにした、と読み取った。清書では位置をそろえる段階と像を鮮明にする段階の違いを語りに加え、6つの要点を清書の台詞と絵に照合した。B3の読みを「ビースリー」にそろえ、完成MP4で全25発話の字幕・読み・音声の対応を確認した。完成映像を制作意図なしで見た別のAIには、B3の位置が変わったことで配列の理由まで伝わった。一方、模式図で右上の像が暗くなったようにも見えたため、図中の光の総量を保ち、明るい中心に集まる描写へ直した。台本と間を同じにした二つの版は台帳から比較できる。運営者による公開判断は未確定。
