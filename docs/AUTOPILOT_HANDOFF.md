# 自動開発チェックポイント
- 状態：完了（既存KG参照と説明を保存する最小Capsuleのブラウザ内private prototype。人間受入とは別）
- 目的：自分が選んだ対象と関係を、説明と根拠を伴うひとつの文脈として読み返せるようにする。
- 前回の複数途中保存は完了済み。入口整理・対象への直接URL・最小Capsuleを比較し、保存の微調整より新しいコンテンツ体験を優先した。
- 検索／Graphの「Capsuleを作る・読む」から、表示中Entity／独立Claimを選び、題名・全体説明を保存できる。
- 初期選択は空。主張を選ぶと両端も選択済みと明示する。対象だけの構成・孤立対象も維持する。
- 個別の肯否・期間・三用途の限定・制作の刊行物・IDを確認して選ぶ。SPO表示束を保存単位にしない。
- 保存形式は独立keyのcollection v1。UUID・dataset・内容版1・題名・説明／言語・作成日時・Entity／Claim IDのみ。
- datasetごと10件、各30対象／60主張、題名80文字・説明4000文字、collection 300,000 bytes以内。知識本文・配置・通信は保存しない。
- 一覧・reload後の再閲覧・確認削除まで実装。説明をClaim／根拠へ変換せず、共存から関係を推論しない。
- 再閲覧では既存APIの現在データを同時4要求、全体60秒以内で取得。schemaとIDを検査し、404・通信失敗・構成外端点を区別する。
- 失敗した参照を消さず、取得成功分の詳細と再試行を提示。閉じる／切替では取消し、遅着応答を排除する。
- Capsule用adapterはprojectGraphを通さない。閲覧Graphは選択したClaimのみ描き、独立対象を保つ。縦長Canvasでは縦配置する。
- 個別ClaimCardとSourceへ進める。背景とのDOM IDを分離。元の探索の選択・枝・条件・座標・pan/zoomを維持する。
- 未保存内容は破棄確認を挟み、画面切替・削除確認にフォーカスを渡す。別タブ追加を保持し、削除対象の変更／消失は拒否する。
- 保存失敗・未知形式・破損を黙って上書きしない。localStorage完全同時writeは後勝ち。server認証・正本は未決。
- 採用契約：docs/design/LOCAL_CAPSULES.md。既存保存ビュー／途中保存の形式・キー・データを自動移行しない。
