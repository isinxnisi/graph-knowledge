# 自動開発チェックポイント
- 状態：完了（会員Capsuleの既存内容編集の初回。会員機能全体の完成・人間受入ではない）
- 目的：再訪した説明付き関係図を訂正し、競合・失効でも入力を失わず本人の保存へ戻れるようにする。
- 共有着手・プロフィール設定と比較し、前回から残る保存後の訂正経路を優先した。
- 採用契約はdocs/design/MEMBER_CAPSULES.md。API・DB/schema・KG意味・凍結datasetは不変。
- /memberの閲覧→題名・説明・既存対象／独立Claimの選び直し→同ID次版→reload→根拠を接続した。
- 新参照追加は初回対象外と画面に明示。取込元local Capsuleとの同期・自動反映はない。
- 未解決参照は保持。未解決Claimを残す間は元の対象全件を保持し、端点を推論しない。
- 更新は既存PUT・期待revision・期待利用者header。サーバーsession／ownerの認可を維持する。
- 競合・通信失敗では入力を残して最新版を再取得。最新版の構成・根拠を読み、明示続行後に再保存する。
- 自動mergeなし。応答消失後に現在内容が入力と一致すれば、余分なPUTを送らず閲覧へ戻れる。
- draftはこのタブのメモリだけ。非表示・401では描画せず、同じUserの再認可後に再開する。
- 再ログインは別タブ。別Userには入力を出さず、元のownerに紐付けたまま保持する。
- 非表示中の他タブ通知は再取得しない。遅い更新応答は無視し、復帰時に最新版を確認する。
- reload／タブ閉鎖で入力が失われる旨を表示。変更の取消は確認付き。削除後は入力を残して保存を止める。
- 通常単体20ファイル461件、追加UI最終3件、Lint・型検査込み最終build・差分検査が成功。
