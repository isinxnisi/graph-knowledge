# 自動開発チェックポイント
- 状態：完了・2026-10-10所有者による共有済み旧版の再閲覧。人間受入・実公開の完了ではない。
- 目的：内容を更新した後も、以前に共有した説明と同じ版の会話・根拠を読み返せるようにする。
- 前回の版別コメント実装を確認。新参照追加・失効後の本人投稿管理と比較し、旧版へ戻れない障害の解消を優先した。
- 採用契約：docs/design/CAPSULE_DISCUSSION.md「所有者が共有済みの版へ戻る」。関連する共有契約・現行設計・入口も更新した。
- 会員Reader→共有した版を選ぶ→一版の説明・Graph・コメント→個別Claim／Source→現在の保存へ復帰を接続。
- 所有者専用GET /api/member/capsules/:id/revisions。共有済みsnapshotのrevision・題名・内容更新日時だけを新しい版順で返す。
- 同APIのrevision指定で一版を読む。未共有版／非所有者／別datasetは404、sessionなし／停止User／期待User不一致は401。
- 所有者・dataset・activeを同一SQLへ含める。tokenだけでは読めず、共有停止後も本人は読める。削除後は一覧・本文とも404。
- 会員URLのcapsule＋revisionでreload・タブ復帰時も同じ版を再認可する。URLは共有権限を持たない。
- 共有時の説明・参照と現在KGを区別。旧版では編集・削除・共有発行を出さず、現在版へ戻ってから操作する。
- 一覧は明示取得。失敗時は本文へfallbackせず再確認できる。非表示・別User・取消後の遅い応答からprivate内容を出さない。
- コメント草稿・結果不明キーは本人＋Capsule＋版別のタブ内メモリへ保持。他版への送信成功でも消さず、画面外の入力にも離脱警告を維持。
- コメント受付は全共有版共通とUIに明記。KG／既存migration／凍結dataset／共有tokenの権限は不変。新migrationなし。
- 通常単体480件成功。その後の最終会員・共有・コメントUI22件も成功。別Userが草稿を書いた後も元の本人の入力が戻る。
- 実OIDC／一時PostgreSQL23件成功。共有1・3版／未共有2・4版、権限・失効・削除・不正queryを含む。
- 新規E2E --grep 共有済み旧版 は390／1440pxの2件成功。版別コメント・草稿復帰・共有停止後reload・出典・現在版復帰まで確認。
- 両幅の画面を目視し、横溢れ・page errorなし。KG応答はfixture、実Google／実KGの組合せと人間受入は未検証。
- 初回E2Eは復元済みtextareaのlabel完全一致検索で2件失敗。最小HTMLでも再現し、role/name検索へ直して成功。時間上限は緩めていない。
- 型検査、全体lint＋最終変更箇所lint、型検査込みbuild、差分検査成功。
- 本番smokeで既存3ページ200、無設定の新APIは503・no-store。一時PG・OIDC・Next dev・本番smokeを終了し検証portの解放を確認。
- 次の候補：リンク失効後の本人投稿一覧・撤回。既存DELETEは作者による既知post IDの失効後撤回に対応するが、発見できる一覧・UIは未実装。
- もう一つの候補は会員Capsuleへの新参照追加。版差分・通知・一般公開運営は今回含めない。
- 外部判断待ちはなし。実接続・公開・課金・実データの意味受入は別判断。runner・guard・設定・実credentialは不変、push／mergeなし。
