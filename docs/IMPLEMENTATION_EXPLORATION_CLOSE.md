GraphStateのcacheNodes / cacheClaimsと展開記録がセッション内の取得記録。nodes / claimsはprojectGraphで導出する表示対象で、独立に編集しない。rootsは配列境界だがUIは1起点。現在の無条件近傍では取得キーはEntity IDを使用し、フィルタ用の汎用条件キーはまだ作らない。

openは利用者の意図、activeは起点から到達した開いた展開、expandedはactiveかつ受理済みページあり。受理済み空ページも取得済みとして扱う。共有Claimは各展開に所属してよく、切断された循環は起点からの最小集合に入らない。

閉じるはopenを解除する。到達不能な子孫のopenと受理済みページは保持し、再到達で復元する。明示的に閉じた子孫は復元しない。詳細APIの結果はGraphに追加しない。新規ページ・復元候補は表示上限100 Entity / 200独立Claimで全体検査し、拒否時は表示とcursorを維持する。復元拒否時は開く意図も変更しない。閉じた後、上限停止を解除して明示的に再試行できる。

一時キャッシュ上限は400 Entity / 800 Claim。非active・非loadingの古い展開を所属とcursorごと破棄する。共有データは残し、破棄済みで画面に残るEntityには再取得の通知を出す。消失座標もキャッシュ破棄・世代リセットに追従する。

## 設計変更と残る制約

承認された復元契約の変更はない。初回取得中にも閉じられるようopenと受理済みを別にし、表示の差分と選択の整合を具体化した。キャッシュ破棄後だけ通常の一段階再取得になる。API・DB・fixture・Claim構造・predicate・日付・依存パッケージは変更していない。

- 閉じた枝の辺が別の有効な展開にも所属する場合、その辺は残る。強制的な個別非表示は今回未実装。
- 復元座標は優先するが、現存Nodeから200未満の距離になる場合は復元Nodeだけ既存の追加配置で調整する。常に完全一致する保証ではない。
- 起点の受理済みページだけで上限を使い切っている場合、他枝の閉鎖では余裕を作れない。中心の選び直しも利用可能。
- 現在の静的デモでは同一探索世代のキャッシュを再利用する。実データ更新時の鮮度・失効契約は次の設計事項。
- 過去の取得条件・複数起点・pin・時系列・探索状態の永続化は未実装。移行順序5以降へは進んでいない。
