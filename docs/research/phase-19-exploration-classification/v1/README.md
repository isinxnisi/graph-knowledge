## 1. 候補と仮付与の読み方

| 略号 | 候補ID | 名前／軸 | 検証結果 |
| --- | --- | --- | --- |
| 制 | relation.work-production | 作品制作への関与／関係種類 | 現CONTRIBUTED_TOへ解決できる狭い入口 |
| 組 | relation.organization-involvement | 人物と組織の関わり／関係種類 | 現AFFILIATED_WITHへ解決できる狭い入口 |
| 参 | relation.event-participation | 特定開催回への参加／関係種類 | 現PARTICIPATED_INへ解決できる狭い入口 |
| 学 | activity.academic | 学術に関する関係／活動領域・文脈 | 意味上は横断軸として成立。現在のAPI条件だけでは解決不能 |
| 仕 | candidate.work | 仕事関係／包含範囲未確定の入口仮説 | 定義未確定、今回は採用しない |

**適**＝狭い関係／文脈が候補に適合。**境**＝広い要約の可否、命題差、対象粒度等の境界を残す。**外**＝当該候補では扱わない。**未**＝対象・根拠・定義が未確定で判断を留保。単独の「適」は投入可能／人間受入済み／取得可能を意味しない。

仮付与の対象はR記録が述べる具体関係であり、人物全体・全経歴ではない。R12の多職能、R22の二Claim、R24の二人物は一研究記録で比較し、Claimへの一括付与や統合はしていない。新規の関係は構造化方式が未承認のまま。参加以外の学術関係も「学」に入れ得るが、「参」へは変換しない。

## 3. 仮付与で分かったこと

- 同じ学術文脈が組織関与（R01/R02/R17/R18）、特定回参加（R22）、未実装の招待（R23）へ横断する。relation facetとactivity facetは別軸が自然。
- R11は映画／音楽、R14は教育／非営利という複数文脈を持つ。一つの世界タグでは足りない。ただし多重所属の一般validatorを今回実装したわけではない。
- R19/R20は科学者の家族でも学術ではない。R13は映画祭の役職でも参加ではない。分類から参加・雇用を認定すると意味を過剰に主張する。
- R08の対象、R16の実在籍、R23の参加は留保する。未分類を無理に埋めない。
- 粗い関係探索なら既存Predicateだけで足りる（R01/R02/R22/R24）。立場・役割を指定して辿るなら現qualificationが必要。
- R17の具体語を発見するだけなら原語索引で足り、enum追加は不要。制度語の精密一致を約束する段階で意味対応が必要。
- 現候補と原語索引・既存限定だけでは表せない追加のcontrolled tagの責務は、今回見つからなかった。分類不足や対象同定不足をtagで埋めない。

## 4. 再実行できる小さい条件検証

[check.mjs](check.mjs)は研究用prototype。三つの入口を既存`neighborsInput`へ解決し、凍結JSONのコピーを現`matchesClaim`で検査する。DB全体の検索や新APIを作らない。Visiting Professorは親資料の語を使ったメモリ上の未正規化対照で、runtime Claimとしての受入・投影ではない。denied対照もメモリ内だけ。

```bash
node_modules/.bin/tsx docs/research/phase-19-exploration-classification/v1/check.mjs
```

既存Node要件を満たす環境で実行する。確認するのは、三入口の具体条件、ORと条件キー、未解決の拒否、Visitor三状態、原語と意味条件の違い、空集合／全値／null、他Predicateへの条件波及、肯否、入力拒否、cursor条件拘束、LIMIT前評価の順序対照。lexical部分は小さい文字列比較であり、語検索API・alias辞書・形態素検索を実装したものではない。

各JSONの全公開Claimに対する件数を比較し、中心Entityのneighbors実DB件数とは区別する。資料の意味・分類判断の正しさをスクリプトで認定しない。v1の結果を変更するときは次版へ判断・条件・親版を残す。
