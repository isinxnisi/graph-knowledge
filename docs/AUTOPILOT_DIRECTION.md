# 自動開発の現在の進め方

2026-10-08採用。自動実行時にrunnerがこのmain側文書を読み取り専用でpromptへ加える。自動側から変更しない。

目的は、関係を発見し、自分の関心に沿ってGraphを組み立て、根拠を確認し、必要なら保存・再訪・共有できる体験を育てること。現在の読み取り探索は成立しているが、将来像に必要な導線・機能も作りながら判断する。

- 各回、今前へ進める体験と今回触れるようにするものを短く決める。大きな計画書や「使いたいと証明する」関門を毎回設けない。
- 探索中の迷い・操作・根拠確認の改善と、保存・再訪・共有等の次の体験を候補にする。特定の機能順を固定せず、現行コード・構想と期待価値から選ぶ。
- 直近と同じ種類の微調整が続いたら、それが解消する具体的な障害を確認し、次の体験を触れる小さい実装／prototypeも比較する。見た目の改善だけへ限定しない。
- 可逆なprototypeは、その体験を試せる範囲まででよい。会員制度・汎用基盤・公開運用を一度に完成させない。人間の実データ受入をAI確認で置き換えない。
- 調査はPROJECT_CONTEXT、docsの入口、関連する現行契約・コード・直近差分から始める。毎回全archiveを読む、同じ資料を再調査する、巨大な将来設計を書くことを避ける。
- AI関連に触れる場合は、main側の [AI処理・共通Kev方針](design/AI_PROCESSING_DIRECTION.md) を読み取り専用で参照する。Kev本体は他プロジェクトとの共有資産であり、自動開発から変更しない。接続情報の共有自体はAI連携実装の承認ではない。
- 検証は変更の責務・リスクへ合わせる。新しい導線は実画面で触り、state・API・意味に触れる場合は必要な回帰を確認する。局所変更で毎回全dataset・全テストを繰り返さない。
- スマホ向けの既存6行報告を維持する。「目的」で進めた体験、「残り」で次に繋がる不足を短く示す。完成度・面白さの立証を報告条件にしない。

45分は一回の実行上限であり、機能全体の規模制限ではない。価値ある機能は複数回で実装してよい。専用worktreeの `docs/AUTOPILOT_HANDOFF.md` に、状態・目標・実装済み範囲・検証済み／未検証・次の一手・重要な判断を通常25行以内で残し、実装と同じcommitへ含める。次回runnerがpromptへ加える。継続中なら現コードと方針に照らして続きを優先し、完了・保留・方針変更なら短く更新する。履歴を積み上げず一件を置き換える。

終了予定時刻と締め作業開始時刻をrunnerが渡す。作業の区切りで時刻を確認し、通常は最後の5分を検証・commit・メモへ使う。機能途中でも既存動作を維持した検証可能な単位へ区切り、必要なら独立route・feature flagを使う。段階の完了と機能の完成・人間受入を区別する。安全な区切りが作れなければ変更を保持し、dirty検査で停止する。メモや時刻指示は強制中断時の正常終了を保証しない。

利用量上限は作業の不備と区別する。CLIが上限を明示したら途中変更を保持して終了し、runnerが当日の残りをスキップする。人による受入が完了した場合は、手動側の完了手順で休止を解除して次の予定で再試行する。翌日または受入後の再試行許可は利用枠の回復保証ではなく、再び上限なら改めて当日休止する。dirtyが残れば人による整理が必要。モデル切替・有料API・追加購入で回避しない。
