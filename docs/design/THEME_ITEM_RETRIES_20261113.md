# 運営テーマ登録の再試行制御（β）

対象は運営ChatGPT Appの未完了項目。一般投稿のAI審査・正式VPS・定期実行は変更しない。042の「URL変更後も項目の日次8回を一律継承する」待機契約だけを本設計で更新する。既存G07の入力・予定をこの開発で動かさず、運営者の明示的な操作後に通常Workerが再処理する。

## API

- `get_theme_registration_retry_status({registrationRequestId,itemKey?})`：副作用のない照会。入力版、現在状態、停止、現在の自動処理予定、手動再試行の最短可能時刻、待機コード／理由、旧準備回数、資料取得の入力版／URL／時刻／結果、操作履歴を返す。既存 `get_theme_registration.retryControl` からも取得する。
- `control_theme_registration_retry({requestId,registrationRequestId,operation,reason,items:[{key,expectedRevision}]})`。operationは `retry` / `pause` / `resume`。requestIdは操作固有のUUID。同じ内容の再送だけ同じUUIDを再利用する。受付全体・ThemeのIDは変更しない。最大10項目を一括で原子的に扱う。
- retryは通常の原資料／参照／版／重複確認を予約する。予約の成功と取得・公開の成功は別。停止中のretryは拒否し、明示resumeを要求する。処理中のretryは競合を返す。pauseは処理権を無効化し、ネットワーク中の旧結果は履歴としてのみ残る。
- 公開／適用済み・取消済み項目、完了受付は対象外。会員のactive・運営権限・受付所有者・Web送信資格・入力版を毎回照合する。既存 `themes:compose` の範囲内であり新しいOAuth権限は追加しない。

## 制限と履歴の単位

- 既存の日付境界（America/Los_Angeles）を継続。**項目＋正規化URL＋日**で失敗・結果不明を最大8回。正常に照合できた別の引用は失敗枠を消費しない（1項目最大20根拠を妨げない）。実際の取得は成功分もすべて全体／host枠と取得履歴へ計上する。入力版の変更や元URLへの復帰ではリセットしない。フラグメントと既知の追跡パラメータは同じURLとする。意味を持つクエリは保持する。
- 別URLは独立した枠。失敗は120秒から指数的に間隔を延ばし最大2時間。サイトのRetry-Afterが長ければ優先し、既存の取得実装同様24時間を上限にする。403 challenge／429／5xxの待機は取得先hostでも保持し、同hostの別URLで回避しない。別hostへの変更に旧hostの失敗は持ち込まない。
- URLだけ変えて連打できないよう、項目の通常検証は32回／日、サービス全体の資料取得開始は60回／分・10,000回／日、hostごと60回／分。これらはAIの無料枠・課金枠とは独立した取得保護。新しい操作で初期化しない。再試行操作は運営者ごと200回／24時間（停止は常に可能、既に停止した項目への重複停止は拒否）。
- 累積prepare_totalを保持し、実際の資料取得開始と終了結果を別の追記履歴で保存する。失敗・停止時も削除しない。開始後にプロセスが終了して結果が残らなければ `outcome-unknown`。成功を推測しない。操作履歴は別テーブルであり、成功した操作を取得成功として数えない。
- 導入前の取得履歴は細かい時刻が残っていない。残存する日次prepare回数を初回制御／処理時に元入力・保存済み旧入力の参照URLへ保守的に帰属する。修正後queuedの未実行新URLへは付け替えない。既にretry等へ進んだ入力で帰属を復元できない場合は現在URLにも保守的に計上する。旧回数を実測のHTTP履歴として創作しない。導入前の過去日まで累積を復元できるとはしない。

## 競合と保全

登録advisory lock→所有者操作lock→package→選択itemの安定順lock→共有source budget lock。Workerもpackage→item→共有budget lock。同じ操作IDの競合は1履歴だけ作る。取得前と適用直前にlease／入力／資格を再確認し、修正・停止された旧入力は公開しない。取得中のleaseとは別に50秒の資料取得枠を保持し、修正直後でも旧取得と同一項目の新取得を重ねない。基盤DBへcommit済みならACK消失時も再適用しない。

明示043 migrationは列と履歴表を追加するだけで既存項目の予定・状態・入力・公開Record・画像・商品を動かさない。未適用環境では既存処理を維持し、新APIはmigration要求を返す。旧000〜042のchecksumは不変。運営経路はAI送信処理に入らず、一般投稿の既存審査を維持する。
