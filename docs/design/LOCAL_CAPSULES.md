# ブラウザ内の最小Capsule

> 2026-10-29の現行契約は[Capsule文書・Graph上の編集](CAPSULE_EDITOR.md)。以下は2026-10-09の参照中心形式とその履歴。チェックリスト作成・localStorage保存・毎回の現在KG再解決／自動配置は新documentへ適用せず、documentなしの旧形式の互換読取に限って扱う。新documentは保存した内容・元断面・配置を読む。旧Capsule削除は許可済みで、完全移行を必須としない。[今回の検証・反映状況](../verification/CAPSULE_EDITOR_20261029.md)／[更新手順](../runbooks/CAPSULE_EDITOR_RELEASE.md)。

2026-10-09採用。既存KG参照と利用者の説明をまとめるprivate prototype。[Capsule構想](CAPSULE_AND_USER_CONTRIBUTION_VISION.md)の初回実装であり、会員保存・公開運用・Global受入制度ではない。

## 操作と範囲

検索またはGraphの「Capsuleを作る・読む」→表示中Graphから作成→対象／独立Claimをチェック→題名・全体説明→保存→一覧・再閲覧→個別Claim／Source→探索へ戻る。reload後は検索側の同じ入口から読む。モーダルの背後の探索・選択・配置・条件は維持する。

新規作成の候補はモーダルを開いた時の表示Entity／Claimに固定する。初期選択は空。主張を選ぶと両端も選択済みとして示し、主張を含める間は外せない。対象だけを明示的に選ぶこともできる。同じ対象の複数Claimは期間・限定・肯否を確認して個別に選び、画面上のRelation束を採用単位にしない。選択した主張を外した後も、独立に選んだ対象は保持する。

作成・保存・一覧・閲覧・確認付き削除に加え、下記の同ID編集を提供する。未保存内容がある時の閉じる／一覧へ戻る／編集取消には破棄確認を挟む。JSONの持ち運び、local Entity／assertion、会員同期、公開URL、discussion、AI、投稿・Global昇格は含めない。

## 意味・保存・認可

- 独立key `graph-knowledge:capsules:<dataset>`。collectionは`format: local-capsules / version: 2`。旧version 1も無書込で読め、次の書込成功時だけversion 2へ移す。保存ビュー・探索途中を自動変換しない。
- 各CapsuleはUUID、dataset、正の安全な整数`revision`、題名、説明、説明言語`ja`、作成日時、明示的な`entityIds`／`claimIds`。新規は内容版1、編集後は更新日時`updatedAt`を必須とする。内容版と保存形式のversionは別。
- IDは既存datasetの内部UUID v4参照。revisionはCapsule内容の版であり、KG・資料の保存時版ではない。本文スナップショット・cursor・開閉・取得ページ・表示束ID・座標を永続参照にしない。
- 説明は利用者のメモ。新Claim・Source支持・受入へ自動変換しない。対象の共存・配置から関係や同時在籍を推論しない。
- datasetごと最大10件、各30 Entity／60 Claim、題名80文字／説明4000文字。collectionはUTF-8で300,000 bytes以内。重複ID・異dataset・未知形式・不正値は拒否し、既存データを上書きしない。
- 作成・編集・削除直前に最新collectionを読み、他の追加を保持。編集・削除は確認したレコード全体と一致する場合だけ許可。破損・容量失敗では書込み成功としない。別タブ変更は一覧へ反映。localStorageにtransactionはなく、完全同時writeは後勝ちの限界がある。
- ブラウザ内privateという保存範囲であり、server認証・所有者認可の実装ではない。同一origin利用者からの隔離、サーバー正本、公開・共有URLは約束しない。

## 再閲覧・既存実装への影響

保存の参照を既存Entity／Claim APIへ再解決する。同時4要求・各要求は既存15秒制限・全体60秒制限。閉じる／一覧へ戻る／再取得では旧要求を取消し、遅着応答を無視する。本文schemaと返却IDを検査し、404（参照失効）・通信／不正応答・端点不一致を分ける。成功分を読めるようにし、保存参照は失敗によって削除・置換しない。再取得で確認し直せる。

表示は明示構成から作る専用adapterを使い、`projectGraph`の到達性・開閉に依存しない。取得成功した孤立Entityを残す。Claimの両端が構成内にない場合は主張を採用せず不一致を表示する。構成内の端点が取得できない場合、辺は描かず、Claim詳細と未解決の対象参照を別々に確認できる。

既存GraphCanvasは閲覧用配置・選択・pan/zoom・dragに再利用し、展開はしない。接続対象から先に配置して独立対象の線ラベルとの重なりを避け、縦長Canvasでは配置方向を縦へ合わせる。配置は毎回生成し、関係の意味を持たせない。線は選択したClaimだけのSPO集約。テキスト一覧からも各対象／Claimを開ける。ClaimCardで期間・限定・肯否・Citation／Sourceを独立表示し、関連Claimは自動取得／追加しない。背景詳細と同じCitationを表示しても、出典へ移動するDOM IDはCapsule内へ分離する。

KG schema・API・dataset・通常Explorerのstate契約を変えない。新UI文字列はlocale解決境界へ置く。旧版へ戻しても既存保存を変更しないが、Capsuleは旧UIで読めない。必要なら保存領域のJSONを保全して戻せる。将来のserver移行・知識履歴固定の方式は未決。

## 検証と段階

作成→保存→reload→再閲覧→個別Claim／Source→Explorerへ戻る縦経路を390/1440pxで確認する。単体テストは独立構成、選択・端点、永続形式と失敗、dataset分離、現在データ、欠落・不正応答・取消を対象にする。通常の開閉・条件復帰・途中保存の既存回帰を確認する。初回の完了と実データでの人間受入、会員保存・公開共有の完成は別である。


## 説明と構成を育てる編集（2026-10-09追加）

### 操作経路と採用理由

閲覧→「このCapsuleを編集」→題名・説明・構成を変更→変更を保存→次版を再閲覧→出典→探索へ戻る。初回のimmutable契約では、誤記の訂正や調査の追記に再作成・旧内容削除が必要だった。同じ文脈を育てるため同IDの編集を採用する。会員保存・直接閲覧の拡張も比較し、今回はこの具体的な作り直しの障害を優先した。会員保存の前提条件として編集の完全版を求める判断ではない。

編集候補は保存済みの参照と、Capsuleモーダルを開いた時点の探索Graphの参照の和集合。保存済み構成は現在データの再解決を優先し、取得失敗した参照を探索cacheの要約で成功扱いにしない。Graphの候補は自動採用せず、明示選択する。保存済みEntityは初期選択済みで、Claimを外しても自動削除しない。Claimの両端は選択済み・解除不可として示す。追加探索は一度Explorerへ戻って行う。編集内の検索・展開・local assertion生成は対象外。

未解決Entity／ClaimはUUIDを表示し、初期選択を維持する。確認できないClaimを残す間は端点を推論せず、保存済みEntity全件を保持する。Entityを外すには未解決Claimを先に明示的に外す。これにより通信失敗・404・端点不一致・全体timeoutでも、説明だけを訂正することで参照を失わない。読込中は編集を開始せず、完了または全体失敗の後に開始する。編集へ切り替えたら既存Readerの要求は取消す。

### 保存・競合・互換性

- 保存成功時だけ同じUUID／dataset／作成日時／説明言語のままrevisionを1進め、更新日時を付ける。最大10件でも置換できる。構成・題名・説明の変更がない時は保存ボタンを無効化し、版を作らない。選択順だけは内容差としない。
- 書込直前に開始時レコード全体を照合する。別タブで更新・削除されていれば上書きせず、入力を保持して競合を表示する。storageイベントでも検出し保存を止める。利用者が一覧へ戻って最新内容を開き直す。自動merge・強制上書きはない。
- 失敗した書込では編集を閉じず、成功扱いにしない。取消・Escape・一覧へ戻るには未保存差分がある時だけ破棄確認を行う。元の保存は変わらない。
- collection v1のreadは元bytesを変更しない。v2への書込で既存全件を保持し、未知形式やv1への新版混入は拒否する。旧アプリはv2を拒否し上書きしない。戻す場合は保存領域JSONを保全し、本実装へ戻すことで再読込できる。旧アプリで新版を読めるとはしない。
- 内容の過去版は保存しない。revisionは更新識別・競合検出用で、任意過去版URL・履歴復元・KGスナップショットを提供しない。将来の会員保存・版固定共有では別途不変版の保存方式が必要。
- localStorageのread/writeはtransactionではないため、完全同時書込の後勝ちという既存限界は残る。サーバーの所有者認可・原子的な競合制御の代用にはしない。

KG schema・API・凍結dataset・保存ビュー・途中保存・Explorer stateは変更しない。構成の追加／削除はこのCapsuleだけに作用する。主な回帰対象は旧保存読込、次版再訪、明示構成、未解決参照、更新／削除競合、容量失敗、取消、390/1440pxでの根拠・探索復帰。
