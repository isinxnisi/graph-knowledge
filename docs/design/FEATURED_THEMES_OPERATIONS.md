# TOPの紹介テーマを運営から選ぶ

2026-11-08。R1〜R6の本運用初版公開後の改善。テーマ作成（ChatGPT→API）と、サイトで紹介するテーマの編集を分ける。

## 利用体験

- 「サイト運営 → TOPの紹介テーマ」で、公開テーマを名前・説明／表示内容から探す。
- 選択したテーマは検索条件とは独立して保持し、上下移動で掲載順を調整、×で掲載から外す。内容やテーマ自体は削除しない。
- 「TOPでの見え方」はTOPと同じカード・横送りを使用する。カードは別タブで開き、編集中の選択を保つ。
- 「掲載を保存」で初めて反映。破棄と、未保存の離脱確認を用意する。0件保存は紹介欄を隠す。
- 新着テーマ、検索結果、資料収集計画には作用しない。3件は画面に並ぶ目安であり、選択数は入力保護の上限24件とする。
- 権限の再確認や一時的な通信失敗で編集中の選択を消さない。別の運営者による先行更新は競合として知らせ、勝手に上書きしない。

## 保存と公開境界

会員PostgreSQLの追加migration `037-featured-themes.sql` で `site_featured_themes` を作る。保存するのは順序付きTheme ID・設定版・更新者・日時だけ。知識原本やTheme構成版は変更しない。

未設定時だけ従来の配布設定 `data/theme-discovery.json` を使用する。空配列は明示的な非掲載として保持し、従来値へ戻さない。正式imageの初期値は既存の `data/theme-discovery.production.json`（空配列）を維持する。βのIDを本番に移さない。

TOPは公開カタログと設定を並行して取得し、初期HTMLの紹介・新着を同時に返す。設定したIDでも、現在の公開カタログにないものは掲載しない。未公開・停止したテーマを紹介設定から公開可能にはしない。従来選択の公開停止は管理画面に状態を示し、保持／削除を選べる。新規選択は現在公開中のIDのみ受け付ける。

設定DBの一時障害では過去の初期選択へ勝手に戻さず、紹介を空にする。新着・通常探索の取得は継続する。通常のHOME再取得は既存の30秒周期、再訪は初期HTMLで反映する。閲覧中のGraphは置換しない。

## 認可・競合・記録

`/api/site-operations/featured-themes` GET／POST。既存の運営ID設定・有効ユーザー・現在セッションで認可し、POSTは同一origin・X-Member-User・厳格schemaを検証する。公開カタログの取得も認可後に行う。

設定単位のDBロックと期待版を使い、request UUIDのreceiptにより応答消失時も二重保存しない。操作履歴は既存 `site_operation_request` の `homepage / set-featured-themes` として記録。過去の通報・会員対応の制約は維持する。適用済みmigrationは変更しない。

## 検証と反映

対象の結合テストは `node --import tsx scripts/test-member.ts --featured-themes`。専用一時PostgreSQLで000〜036から037への追加、旧checksum・ユーザー保持・再実行、認可、非公開排除、明示空選択、同時更新／再送を確認する。UIは絞り込み中の選択保持・並べ替え／解除・保存／破棄・認証再確認・競合表示を確認する。

main／3200／HTTPS β／正式URLへの反映結果は検証記録に残す。データの移送やseedは行わない。
