# Discovery：目的から選ぶ探索プリセット

2026-10-18。`a64dbf1` の[複数段探索](DISCOVERY_MULTI_STEP.md)を利用する実装。正式検索の3タブ・初期PLUTO／Princeton／NBI入口・自由検索・Graphを維持する。収集・受入・公開apply・会員データは変更しない。

## 採用した探し方

対象を選んだ後、関係記録の「見つけ方」に、対象のkindに合う小さい任意ボタンを出す。2〜3段機能を先に開く必要はない。選ぶと目的・実際の経路の形・関係／Role・段数と、現在の公開KGから取得した経路が同じ領域に現れる。次の質問を必須選択する手順や新規タブは追加しない。選ばず従来の関係一覧・自由な2／3段探索・名前検索も使える。

| ID／意味の版 | 表示と対象 | 検証する形・探索目的 |
| --- | --- | --- |
| other-works／1 | 同じつくり手の別作品（作品） | 作品 — 人物 — 別作品。同一人物の制作記録を介した別作品。著者限定ではない |
| work-creators／1 | 別作品のつくり手へ（作品） | 作品 — 人物 — 別作品 — 別の人物。既に知る作品から、別作品の担当者へ |
| co-creators／1 | 作品を介して別のつくり手へ（人物） | 人物 — 作品 — 別の人物。同じ作品に接続する別の制作記録を発見。共作・同時期参加の断定はしない |
| institution-bridge／1 | 人を介して別の機関へ（組織） | 組織 — 人物 — 別の組織。同一人物の所属記録から別機関へ。移動順序・現在の所属を推定しない |

カタログは `lib/domain/discovery-path-presets.ts` の小さい版付き定義。固定Entity、Graph URL、Neo4jのラベル文字列、収集テーマID、任意Cypherを持たない。同じkindの別対象に再利用でき、新しい公開接続も同じ仕組みで探索する。既存の初期プリセットは変更しない。

「つくり手」はCONTRIBUTED_TOの記録上の担当者。作者／原作者と同一視しない。「人を介して別の機関へ」は人物と組織の記録であり、研究者という分類を検索したと装わない。研究分野・組織の分類は今回補わない。

## 条件と実行の一致

既存 `GET /api/discovery/paths` に任意の `preset`／`presetRevision=1` を追加した。未知ID・未知版、片方だけの指定、矛盾する段数・predicate・対象kindは400で拒否する。プリセットのない旧要求は互換。応答にも解決したプリセットのID／版を返し、クライアントでも要求との一致・各段のkind・方向を再検証する。

制作3種では各Claimが正規方向person→work、所属ではperson→organizationであることと、指定の端点列を確認する。順逆の辿り方とClaimの矢印は区別する。異なるClaimのRoleや端点を合成しない。同じ2対象の並行Claimは、受理した独立記録として方向・肯否・Role・scope・期間・出典を保持する。肯否の双方を含むことを明記し、経路を新しい直接関係や因果関係と扱わない。

段ごとに異なるpredicate／Roleを指定する汎用機能は今回不要と判断した。制作では全段CONTRIBUTED_TO、機関では全段AFFILIATED_WITHを使い、必要な端点列・正規方向だけを追加した。大規模なDSL・分類モデル・DB schemaは増やさない。

## 上限と候補の範囲

以前の最大20記録／対象、24展開対象、128中間経路、12候補、2／3段を維持する。predicate／制作Roleは従来どおり同一ClaimのLIMIT前に評価する。経路の形・方向はサーバーの列挙中、**中間経路／候補数の上限前**に評価する。先に12件取ってブラウザーで不適合な経路を消す方式ではない。

探索元は既存Graphと同じ各対象の最初20記録。kindだけで別の20記録を読む方式は、Graphの最初のページに経路が含まれなくなるため採らない。上限で記録が未取得なら部分範囲と表示する。この取得範囲の宣言は全KGの条件検索・件数とは区別する。取得済み候補を固定例で置き換えない。

候補の上に常設する範囲表示：

- 制限なし：`10経路 · この条件の全候補`。対象・段数・条件に一致する循環しない公開記録の全経路であると説明する。世界全体の網羅とは言わない。
- 制限あり：`12経路 · 取得上限内の一部`。記録未取得／対象上限／中間経路制限／表示12件の理由を説明し、技術的な上限・実際の確認対象数も補助表示する。
- 0件＋制限あり：取得範囲で未発見であり、経路の不存在とは断定しない。0件＋制限なしも、その対象・段数・条件だけの結果とする。

公開revision、条件変更のAbort、古い応答の排除、Graphでの各Claimの再検証は既存機構を維持する。複数段APIが返した部分取得を、完成した固定Graphへ偽装しない。

## 条件変更・解除・Graph

- プリセット選択で既存の関係条件も制作／所属に合わせる。制作Roleは保持し、全段へ適用する。所属に変える際に制作Roleがあれば、ボタンに解除されることを事前表示する。
- 同じkindの別対象、同じ関係のRole変更には、選んだ探し方をそのまま再適用する。世界と名前のページ内絞込は独立した既存の文脈として保持し、名前条件が経路へ作用しないことを明記する。
- 関係・対象kind・段数を変えて元の形が適用されなくなる場合は、直接操作を受け付け、`探し方の制約を外して自由に探索中`と表示する。勝手に元の関係へ戻したり、不要な確認ステップを挟まない。
- `探し方だけ解除`はkind列の制約だけを外し、対象・関係・Role・段数を保つ。`経路の選択を解除`は見ている経路だけを外す。Undoはプリセットの選択・条件変更の前のContextと経路状態を戻す。
- 選択経路の見出し近くにGraphボタンを置く。既存workspace枝・版付きviaによる全段の再取得と根拠への到達、終点の選択、Graph詳細の選択経路と最短経路の区別を維持する。Backでプリセット・選択経路・条件を復元する。
