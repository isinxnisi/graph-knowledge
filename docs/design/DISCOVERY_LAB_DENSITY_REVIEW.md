# Discovery Lab：情報密度と操作の改善

**後続の画面改善**：[画面全体と探索操作の再構成](DISCOVERY_LAB_EDITORIAL_REVIEW.md)が現在のUI。以下は前回版の変更と比較記録。

2026-10-17。[探索モデル](DISCOVERY_MODEL_REDESIGN.md)・[初回試作](DISCOVERY_MODEL_PROTOTYPE.md)を維持し、`/discovery-lab` の画面とUI状態だけを改善した。既存Discovery Searchとは共存する。

## 採用した画面構成

入口タブ → 現在の選択と解除／Undo → 入口に応じた候補 → 関係・制作役割 → キーワード → 結果、の順にした。二タブを初期表示とし、「段階表示を試す」で共有Contextの別案も操作できる。段階表示では別入口へのボタンを一回押すだけで切り替わる。

- 世界は11個を文字主体のチップで一覧表示する。セレクトに収納しない。世界の選択は関心の印であり、分類検索を行ったようには見せない。
- 現在の条件は入口タブの直下に置く。対象・世界・問い・役割・ページ内名前条件を区別し、それぞれの×で一項目だけ外す。対象の名前を押すと、条件を保ったまま名前候補を探せる。
- 関係は常時直接選べる。制作を選ぶと役割も一覧になる。選択順は強制しない。役割を残して所属などへ変更した場合は、勝手に役割を削除せず、未対応理由と明示的な解除／関係変更を示す。
- 「すべての条件を解除」は常時見える一回の操作とし、確認のためのアコーディオンを増やさない。「取り消す：世界の解除」など、Undoが戻す変更を表示する。一件のUndoは、解除・対象変更・プリセット適用と名前検索のUI状態も復元する。
- 名前候補の入力と、取得済みページの相手の名前での絞込をUI状態として分離した。名前候補へ移るだけでは、対象・世界・問い・役割・ページ内絞込を破棄しない。戻る操作も検索欄の横に置く。

条件を最上段へ移して入口タブを下に置く案、世界／役割をセレクトにする案、解除や候補をアコーディオンへ隠す案は、ユーザーの実画面フィードバックを受けて不採用とした。単純な縮小や、操作を隠すことを情報密度の改善とは扱わない。

## プリセットとおすすめの強弱

初期プリセットは、迷った人が最初に選べる小さな入口として残す。「PLUTOのつくり手」「Princetonの人々」「研究所で出会う」の三つを、一行の小さなタイルにした。見出しと対象・関係の副題を持ち、名前だけの候補より内容を伝える。PCで高さ約62px、390pxで約75pxを基本とし、広告のような横長バナーにはしない。現在のAPIで対象と関係の記録を確認できたものだけ押せる。

プリセットは対象と関係を設定する。任意の世界の関心は維持する。対象や関係・役割を選択済みなら、プリセットは繰り返し表示せず、次の関連対象を小さなチップにする。「対象を変更」と表示し、押しても関係・役割・世界・名前の絞込を勝手に変えない。別の対象例も開閉操作なしで参照できる。

初期プリセットの魅力と、探索途中のおすすめの控えめさを分けた。プリセットも関連候補も一度も押さず、名前入力と条件の直接指定だけで検索・根拠閲覧・Graph移動が成立する。

## 結果と動き

PCは独立Claimを二列、スマホは一列で表示する。相手の名前・向き・関係・肯否・限定役割／立場・期間・出典数・刊行物の適用範囲を残した。根拠を開くと既存のClaim詳細を同じ本文で読め、PCでは二列分の幅を使う。

結果見出しに現在の対象のGraphリンク、各記録にも相手のGraphリンクを置く。「対象にする」「根拠を開く」「Graph」を異なる操作として分けた。関係記録からのGraphは関係と制作役割を引き継ぎ、名前候補のGraphは「全関係」と明示する。ページ内の名前絞込はGraph条件に変換しない。

選択色・輪郭と短い130msの反応を中心にし、演出完了を通信や操作の前提にしない。再取得中やエラー時の古い記録は薄く表示して操作不可にする。見出しへの初期フォーカス、Esc後のフォーカス復帰、GraphからBack、IME確定前の検索抑制、入口ごとのスクロール位置、reduced-motionを維持した。

## 検証と配置

- 公開API adapter／Discovery Searchの単体試験17件、lint／語彙・限定契約チェック、TypeScriptを含むpublic buildを確認。
- Playwrightでは日本語1440px／390px・英語320px、候補を押さない操作、単独解除／一括解除／Undo、役割の不整合、名前検索中の文脈維持、11世界と映画・ゲーム・音楽の未対応表示、PLUTO→長崎→別作品、Princeton→Nash／Pauliと根拠、各Graph導線を確認し、ローカル本番buildの10件すべて成功した。
- 遅い応答との競合、409と再取得、古い結果の操作抑制、既存検索との共存、IME、キーボードのタブ操作、二タブ／段階表示の文脈維持、390pxのタッチ座標による選択も試験対象とした。

実機相当のブラウザ画面とタッチ中央座標を確認したもので、物理スマホでの親指操作や読字快適性まで保証した評価ではない。320×650pxの英語表示では、役割候補の折返しによってPLUTOの結果見出しが本文上端から669pxになり、スクロールが必要。文字サイズ、隣り合う小さな×、初期プリセットを選びたくなるか、二入口の自然さは、引き続き人間が評価する。

UIと試作のe2eだけの変更で、Contextの意味モデル・公開API・収集CLI／ジョブ・公開KGを変更していない。現在のページ限定、世界全体の収録／正式な収集予定が未確認、方向／期間／分類／受賞条件が未対応、という能力境界を維持する。

ローカル3200／betaに本番buildを反映済み。beta経由でPLUTO・別作品・研究機関の代表2件も成功した。最後の見出し改行調整後に、betaで日本語1440px／390px・英語320pxの3件を再確認し、すべて成功した。比較画像の「後」と測定値はこの最終beta確認から採った。`/api/dataset` は200、revision `82b01515-594c-48ca-b4b6-515eefac83ca` を維持している。VPSは独立試作の比較段階であり、今回の変更は未配置。正式 `https://plunode.net/api/dataset` は200／revision `5e2a94af-9061-4087-bb7a-045a3c0133f4`、`/discovery-lab` は404である。[確認環境の更新契約](PRODUCTION_DEPLOYMENT.md#確認環境の更新契約)の必須工程・稼働版の不具合修正に該当する変更ではない。次の実データ拡張は既存adapter／resolverへ対応能力を追加する形とし、今回のUIに合わせて条件やAPIを作り替えない。
