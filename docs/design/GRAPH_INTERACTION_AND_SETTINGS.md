# Nodeのクリック操作と今後の設定

2026-10-03作成、2026-10-04 Phase 08の概要接続、2026-10-07 表示中対象への移動を追記。Node再クリックの開閉は実装済み。設定画面・ユーザー設定の永続化・管理設定は検討事項であり未実装。

## 今回の操作

- 未選択Nodeは即時に選択し、必要なら通常の一段階展開／受理済み枝の復元を行う。
- 選択中Nodeの単クリックは300ms後に開閉する。選択は維持する。
- 同じNodeへ300ms以内に二度目のクリックが来たら待機中の開閉を取り消す。ダブルクリック動作は独立したコールバックに渡すが、Phase 08ではEntity関係概要を開く。
- 未選択Nodeのダブルクリックでは最初の即時選択・展開は残す。二度目のクリックによる開閉は行わない。選択の応答性を保つため、初回展開の巻き戻しはしない。
- 他Node・Edge・背景の操作、ドラッグ、選択変更、中心変更、Canvas破棄で待機中の開閉を残さない。最初の選択変更でも連続クリックの記録は保持し、二度目を誤って単クリックとして扱わない。
- テキスト一覧の「選択・展開」はトグルにしない。詳細と一覧の明示開閉ボタンは判定待ちなし。

GRAPH_INTERACTION_DEFAULTS.doubleClickMsを300にした。クリック判定はcreateNodeClickHandler、実際の開閉はuseGraphExplorer.toggleEntityで分ける。GraphCanvas.onEntityDoubleClickはPhase 08の概要モーダルへ接続した。Cytoscapeの別のdbltap判定とは併用しないため、異なる閾値で単クリックとダブルクリックが両方発火しない。

入力イベントの時刻を基準に判定し、描画で処理が遅れた時もハンドラー実行時刻の差だけで判定しない。判定はアプリ内の300msが基準で、OSのダブルクリック速度への追従は追加していない。今後別動作を変更する場合も、同じ判定処理に接続する。

## 表示中の対象への移動（2026-10-07追加）

探索を広げた後、現在の選択に隣接しない対象にも直接戻れるよう、Graph上部に折り畳みの移動パネルを置く。通常のNodeクリックや隣接一覧の「選択・展開」とは別の、**選択と表示位置だけを変える操作**とする。

- 候補は現在表示されている `graph.nodes` のみ。取得済みでも閉じた枝の中にある非表示対象や、未取得対象は含めない。左側のデータセット検索とは独立する。
- 名前・説明のNFKC／小文字化後の部分一致で絞り、名称・内部ID順で表示する。近傍応答にない別名は検索対象にしない。種別と説明を添え、それも同じ候補には内部IDを表示する。
- 選ぶとEntity詳細と隣接一覧の対象を切り替え、Canvasの中央へ移動する。小さく縮小されていた場合はzoomを1まで戻し、既に拡大されていれば倍率を維持する。Node座標は変更しない。
- 起点・条件・受理ページ・cursor・開閉意図・復帰用snapshotは変更しない。近傍取得や枝の復元は行わない。Entity詳細は既存の読取処理で取得する。展開したい場合は詳細の明示ボタンを使う。
- 待機中のNode再クリック判定を取り消す。同じ対象への再移動でも開閉しない。移動後・Escapeでパネルを閉じ、開閉ボタンへキーボードフォーカスを戻す。
- 同じ探索世代では表示対象の増減に追従する。新探索・条件変更・起点切替・復帰で世代が変わると絞り込みとパネル開閉をリセットする。保存・履歴の対象にはしない。

単体テストで未展開／閉鎖枝・非表示キャッシュ・snapshotの維持、候補の増減・同名識別・正規化を確認する。API応答を固定したブラウザテストでキーボード移動、実Canvasの中央表示・座標維持、追加近傍通信なし、閉鎖後の候補更新を確認する。

検証結果：`npm test` 236件、`npm run typecheck`、`npm run lint`、`npm run build`、`git diff --check`が成功。`tests/e2e/graph-navigation.spec.ts`も成功し、移動パネル閉鎖後のCanvasクリックを確認した。ブラウザは初回に共有ライブラリ不足で起動できず、検証用ライブラリを作業ディレクトリの無視対象へ展開し、`LD_LIBRARY_PATH`指定で再実行した。DB/APIの実装・datasetは変更していない。

## 設定モーダルは今必要か

現時点では不要と判断する。調整対象が少ない段階では、値とその適用責務を分ける方が効果がある。設定画面を先に作っても、未定義の項目や永続化を先行させることになる。独立した操作・表示設定が増え、試行・リセットしたい要求が具体化した時に設定モーダルを追加する。

| 分類 | 候補 | 現在／将来の責務 |
| --- | --- | --- |
| 利用者の操作設定 | クリック判定時間、将来のダブルクリック動作、操作方法 | 今回は判定時間の初期値を一か所へ。将来は型付き設定をイベント判定へ渡す |
| 利用者の表示設定 | ライト／ダーク・配色、ラベルの大きさ、ズームの好み | 配色は既存React stateとCSS変数。必要な項目から設定モデルへ移す |
| 開発用Graph調整 | 曲率、間隔、配置の評価係数 | 利用者設定と混ぜない。現在はpresentation／layoutに属する。調整用パネルは必要時のみ |
| 管理ポリシー | API取得上限、公開可否、認可、サーバー予算 | サーバー側の検証が正本。利用者の設定画面から上書きさせない |
| 探索状態 | 起点、展開・閉鎖、cursor、選択、座標 | セッション状態。設定の保存／リセットと一緒に消さない |

利用者用と管理用は同じモーダルへ継ぎ足さない。UI部品は共有可能だが、適用先・権限・保存先が違う。表示上限と一時キャッシュ上限は既存graph-stateの定数を維持し、操作の好みと同じ設定オブジェクトへ移さない。

## 後で大変になりやすい部分

1. ハンドラーへ値を直接埋め込む、単クリック／ダブルクリックで別の判定値を使う。今回、初期値と判定処理をまとめて回避した。
2. 設定変更のたびにCytoscape Coreを作り直す。今後はstyleやイベント設定を更新し、座標・選択・pan/zoomを維持する。判定時間を実行中に変更するなら旧タイマーを取消し、ハンドラーを差し替える。
3. 設定を変更すると探索stateまでリセットする。テーマ変更と同様に設定と探索を分ける。
4. 永続化の値を無検証で読む。導入時に既定値・型検証・範囲・旧値の移行を決める。localStorageとアカウント設定の優先順位もその時に明示する。
5. 管理設定をブラウザだけで検証する。管理ポリシーはサーバーで検証し、認可と保存処理を別に設計する。
6. モーダル表示中も背面のGraph入力・待機タイマーを動かす。モーダル導入時は待機ジェスチャーを取り消し、背面操作を止め、フォーカスの移動・Escape・閉じた後の復帰を設計する。設定モーダルを閉じただけで枝を展開しない。

ダブルクリックの有効／無効を設定にする時は、無効時に単クリックを即時確定するのか、連続クリックをどう扱うかまで決める。未使用のbooleanだけを先に追加しない。

今は汎用設定レジストリ、設定ごとの権限エンジン、localStorage／DB保存、doubleClickEnabledの未使用フラグは作らない。具体的な用途が決まってから必要な型と項目だけ追加する。

## 検証

単体テストでは即時選択、300ms前後、選択中／未選択のダブルクリック、選択変更・別Node・取消を検証。実ブラウザでは選択中の起点クリックで閉じる／復元、選択中ダブルクリックの抑止、未選択作品へのダブルクリックで選択・展開したまま維持を確認する。既存の開閉・出典・テーマの回帰も実行する。
