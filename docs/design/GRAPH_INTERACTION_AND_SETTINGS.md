# Nodeのクリック操作と今後の設定

2026-10-03作成、2026-10-04 Phase 08の概要接続、2026-10-07 表示中対象への移動、2026-10-08 狭い画面の領域切り替えを追記。Node再クリックの開閉は実装済み。設定画面・ユーザー設定の永続化・管理設定は検討事項であり未実装。

## 今回の操作

- 未選択Nodeは即時に選択し、必要なら通常の一段階展開／受理済み枝の復元を行う。
- 選択中Nodeの単クリックは300ms後に開閉する。選択は維持する。
- 同じNodeへ300ms以内に二度目のクリックが来たら待機中の開閉を取り消す。ダブルクリック動作は独立したコールバックに渡すが、Phase 08ではEntity関係概要を開く。
- 未選択Nodeのダブルクリックでは最初の即時選択・展開は残す。二度目のクリックによる開閉は行わない。選択の応答性を保つため、初回展開の巻き戻しはしない。
- 他Node・Edge・背景の操作、ドラッグ、選択変更、中心変更、Canvas破棄で待機中の開閉を残さない。最初の選択変更でも連続クリックの記録は保持し、二度目を誤って単クリックとして扱わない。
- テキスト一覧の「選択・展開」はトグルにしない。詳細と一覧の明示開閉ボタンは判定待ちなし。

GRAPH_INTERACTION_DEFAULTS.doubleClickMsを300にした。クリック判定はcreateNodeClickHandler、実際の開閉はuseGraphExplorer.toggleEntityで分ける。GraphCanvas.onEntityDoubleClickはPhase 08の概要モーダルへ接続した。Cytoscapeの別のdbltap判定とは併用しないため、異なる閾値で単クリックとダブルクリックが両方発火しない。

入力イベントの時刻を基準に判定し、描画で処理が遅れた時もハンドラー実行時刻の差だけで判定しない。判定はアプリ内の300msが基準で、OSのダブルクリック速度への追従は追加していない。今後別動作を変更する場合も、同じ判定処理に接続する。

## 表示中の対象への移動（2026-10-07追加）

探索を広げた後、現在の選択に隣接しない対象にも直接戻れるよう、Graph上部に折り畳みの移動パネルを置く。通常のNodeクリックや隣接一覧の「選択・展開」とは別の、**選択と表示位置だけを変える操作**とする。

- 候補は現在表示されている `graph.nodes` のみ。取得済みでも閉じた枝の中にある非表示対象や、未取得対象は含めない。左側のデータセット検索とは独立する。
- 名前・説明のNFKC／小文字化後の部分一致で絞り、名称・内部ID順で表示する。近傍応答にない別名は検索対象にしない。種別と説明を添え、それも同じ候補には内部IDを表示する。
- 選ぶとEntity詳細と隣接一覧の対象を切り替え、Canvasの中央へ移動する。小さく縮小されていた場合はzoomを1まで戻し、既に拡大されていれば倍率を維持する。Node座標は変更しない。
- 起点・条件・受理ページ・cursor・開閉意図・復帰用snapshotは変更しない。近傍取得や枝の復元は行わない。Entity詳細は既存の読取処理で取得する。展開したい場合は詳細の明示ボタンを使う。
- 待機中のNode再クリック判定を取り消す。同じ対象への再移動でも開閉しない。移動後・Escapeでパネルを閉じ、開閉ボタンへキーボードフォーカスを戻す。
- 同じ探索世代では表示対象の増減に追従する。新探索・条件変更・起点切替・復帰で世代が変わると絞り込みとパネル開閉をリセットする。保存・履歴の対象にはしない。

単体テストで未展開／閉鎖枝・非表示キャッシュ・snapshotの維持、候補の増減・同名識別・正規化を確認する。API応答を固定したブラウザテストでキーボード移動、実Canvasの中央表示・座標維持、追加近傍通信なし、閉鎖後の候補更新を確認する。

検証結果：`npm test` 236件、`npm run typecheck`、`npm run lint`、`npm run build`、`git diff --check`が成功。`tests/e2e/graph-navigation.spec.ts`も成功し、移動パネル閉鎖後のCanvasクリックを確認した。ブラウザは初回に共有ライブラリ不足で起動できず、検証用ライブラリを作業ディレクトリの無視対象へ展開し、`LD_LIBRARY_PATH`指定で再実行した。DB/APIの実装・datasetは変更していない。

## 起点から選択対象への表示中経路（2026-10-08追加）

探索を広げると、隣接一覧だけでは起点から遠い対象への繋がりを読み取りにくい。Entity詳細に「起点からの経路」を追加し、表示中Graphの最短経路を一つ確認して各Relationの主張・根拠へ進めるようにする。新しい探索体験として採用し、取得・知識モデルとは独立した表示機能とする。

- 対象は現在の `graph.nodes` と `displayRelations(graph.claims)` だけ。未取得・条件外・閉じた枝のキャッシュを使わず、追加通信で経路を探さない。表示上限100 Entity／200 Claimの範囲で計算する。
- 起点から選択Entityまで、Relationを一歩とする幅優先探索を行う。両方向を辿り、同じ長さの経路が複数あればRelation IDの辞書順で一つを選ぶ。応答順・名称・出典数・肯否による順位付けはしない。操作履歴や全データ中の最短経路ではない。
- 矢印は辿る順ではなく元の主張の向きを示す。逆に辿る箇所は左矢印を使い、Graphと同じ具体語・否定／肯否混在ラベルを保持する。否定だけの線も探索対象であり、経路から直接の関係・因果・同時期の成立・主張の真偽を推論しないことを表示する。
- 初期は関係数の要約のみで、展開すると起点から順に各線を読める。同名対象は既存のEntity補助ラベルで区別する。起点自体の選択時は表示しない。経路がない時は「表示中のGraph内」にないと示し、未取得・閉じた枝を含めていないことを説明する。
- 各線のボタンは既存のRelation詳細へ進む。表示中Claim全体と関連Claim／Sourceを既存の範囲区分で読み、近傍取得・開閉・cursor・起点・条件・座標・pan／zoom・復帰snapshotは変更しない。詳細の先頭へフォーカスとスクロールを移し、狭い画面でも詳細領域に留まる。
- 同じ選択内で表示Graphが増減したら経路を再計算する。取得の進行で短い経路へ変わることがある。対象選択・探索世代の変更時は折り畳みに戻す。経路の永続化・履歴・共有・Graph上の強調表示・全経路列挙はこの範囲に含めない。

検証：`npm test -- --no-file-parallelism` 270件（経路の追加7件を含む）、typecheck・lint・本番build・`git diff --check`が成功。API応答を固定したPlaywrightは経路2件（390px／1440px）と既存の対象移動・詳細端点操作5件、計7件が本番ビルドで成功した。初回の既存回帰で検出したEntity詳細とのReact key重複を修正し、全7件を再実行して確認した。経路のキーボード開閉・逆向きの否定／肯否混在・Source確認・対象詳細への往復、Graph件数・近傍通信・座標・pan／zoomの維持、両画面幅の表示を検証した。API・DB・datasetは変更しておらず、DB integration・実データ全件のE2Eは実施していない。

## 狭い画面での領域切り替え（2026-10-08追加）

従来の三列固定では、スマートフォン幅で検索・Graph・根拠詳細の往復に横スクロールを要した。800px以下では「検索」「Graph」「選択の詳細」の常設ボタンで一領域ずつ表示する。これは同じ探索セッションの表示変更であり、別routeや永続設定ではない。幅の境界は可逆なpresentation上の判断として800pxを採用した。

- 初期表示は検索。候補／開始例を選ぶとGraphへ移る。既存の条件維持／条件解除の違いはそのまま。
- GraphのNode選択／再クリックはGraphに留まり、展開を続けられる。Entity詳細は常設ボタンから開く。線または一覧の「主張と出典を見る」を選ぶと詳細へ移る。
- Entity詳細／概要から明示的に起点を切り替えるとGraphへ移る。既存の直前探索への復帰を維持する。
- 切り替えだけでは探索state・通信・選択・条件・cursor・開閉意図を変更しない。各部品をmountしたまま、検索語／候補、資料情報の開閉、各領域のスクロール位置を保持する。
- CSSのvisibilityで非表示領域をキーボード／アクセシビリティツリーから除外する。Canvasは同じgrid領域の寸法を保つため、非表示中に初回近傍取得が完了してもゼロ寸法で配置しない。表示切り替えでは自動fitしない。
- 表示先をプログラム上のフォーカス先にする。常設ボタンは押下状態と操作対象を公開する。デスクトップではこのフォーカス移動を行わず、三列を維持する。
- 狭い画面ではCanvasの手動高さ変更と詳細幅変更を隠す。datasetの区別・収録範囲の説明、条件編集、概要、根拠確認は維持する。

`tests/e2e/compact-explorer.spec.ts`はAPI応答を固定し、320px／390px幅の検索→Graph→主張と根拠、横溢れなし、フォーカス、検索候補・資料情報の開閉・Graph座標／pan／zoomの維持、デスクトップ幅との往復、非表示中の初回取得と線選択、条件編集の取消・起点切替・直前探索の復帰を確認する。DB・API・意味モデル・凍結dataset・配置アルゴリズムは変更しない。

検証結果：`npm test` 240件、`npm run typecheck`、`npm run lint`、`npm run build`、`git diff --check`が成功。Playwrightは上記4件と既存のGraph移動・関連主張取得の2件、合計6件が成功。Chromiumのviewport変更による検証であり、実機のタッチ操作は未確認。

## スマホのGraph・詳細・隣接一覧（公開β step10）

- Canvasは`clamp(360px, 56dvh, 560px)`、最小360px。中央カード全体だけがスクロールし、隣接一覧に独立スクロールを設けない。「隣接一覧へ」「Graphへ戻る」は中央の読取位置とフォーカスだけを変え、選択・取得・座標・pan/zoomを変えない。desktopでは提示しない。

## 隣接一覧からの追加取得・再試行（2026-10-08追加）

Graphを辿る最中に詳細領域へ切り替える負担を減らすため、隣接一覧からも未取得ページの追加取得と失敗時の再試行を行える。狭い画面ではGraph領域に留まったまま操作できる。

- 一覧が対象にしているEntityの展開状態を使う。2026-10-14に詳細選択との結合を解消した。Entityを選択した時に一覧の対象を変更し、Claim／Relationの詳細を読むだけでは直前の一覧対象を維持する。新しい探索世代では起点へ戻し、対象がGraphから消えた場合も起点へ戻す。一覧見出しに対象名を示す。初回にClaim／Relation選択しかない場合は主体側を初期文脈とする。
- 開いている枝に続きがある場合、未取得部分の存在と「隣接関係の続きを表示」を一覧の上部へ表示する。読み込み中は取得状態を示し、追加取得を無効にする。表示上限で拒否された場合も追加取得を無効にし、既存のエラーと再試行導線を使う。
- 初回失敗は初回ページ、続きの失敗は最後に受理したcursorから再試行する。失敗・読み込み中も取得済みの一覧を残す。エラーを空結果や孤立Entityとして表示しない。
- 閉じた枝では続きの取得を出さず、既存の「展開を再開」で受理済みページを復元してから続きへ進む。再試行・追加取得だけでは選択・起点・条件・表示領域を切り替えない。
- Entity詳細の既存操作も維持する。両方から同じ`useGraphExplorer.expand`へ接続し、同時要求の抑制、条件付きcursor、世代、表示上限、閉鎖／復元の処理を共有する。API・DB・dataset・知識モデルは変更しない。

単体テストでClaim選択中の取得先、通信中／上限時の無効化、初回／続きの再試行、閉鎖枝の復元優先を確認する。`tests/e2e/neighbor-loading.spec.ts`は390pxと1440pxのAPI固定ブラウザ検証で、初回503→再試行→追加取得503→同一cursorでの再試行、取得済み一覧・選択・座標・pan／zoomの維持、閉鎖／キャッシュ復元を確認する。

検証結果：`npm test` 243件、typecheck、lint、build、`git diff --check`が成功。上記2件に既存の狭い画面4件・Graph移動1件・関連主張取得1件を加え、本番ビルドの`next start`をPlaywrightで起動・終了して8件成功。開発モードでの初回検証は6件成功／2件失敗（初回近傍通信が中断され、Graphが取得中のまま残る）。失敗した関連主張取得と新規2件を開発モードで再実行し、3件とも成功した。中断の根因は未確定で、開発モードの初期化と入力の競合は別途再現性を確認する。DBは使わずAPI固定応答で検証し、実機のタッチ操作は未確認。

## Graphの表示操作（2026-10-08追加）

Graphを縮小・移動して見失った時や、ホイール／ピンチ操作を使えない時も、配置と探索を維持したまま読み直せるようにする。Canvas上部に拡大・縮小・倍率・全体表示・選択表示をまとめる。

- 拡大・縮小はCanvas中央のモデル座標を固定し、1.25倍／その逆数で倍率だけを変える。既存の15〜200%の範囲を守り、端では該当ボタンを無効にする。倍率表示はホイール・ピンチ・対象移動・snapshot復帰にも追随する。
- 「全体を表示」は現在表示中の要素を収める既存操作。「選択を表示」はEntityなら中央へ移して縮小時だけ100%に戻す。Relation／個別Claimなら表示中Relationと両端を収め、過大な拡大を避けるため115%を上限にする。個別Claimの選択をRelationへ変更しない。
- いずれも座標・選択・起点・条件・開閉・受理ページ・cursor・復帰snapshotを変えず、通信しない。閉じた枝や未取得対象は対象外。待機中のNode再クリック判定を取り消す。表示倍率の下限により極端に離した要素をすべて収められない場合は、対象への移動も併用する。
- Graphが空の時は無効。概要モーダルを開いている間も無効にする。操作は標準buttonとしてTab／Enter／Spaceで利用でき、44px以上の高さ・幅を確保する。狭い画面では折り返し、Graph領域に留まる。永続設定は追加しない。

検証は`tests/e2e/graph-viewport.spec.ts`で320px／1440px幅のキーボード操作、倍率上下限・外部zoomイベントへの追随、画面外からの選択復帰、関係両端・全体表示、座標・選択・取得件数の維持と横溢れなしを確認する。

## 設定モーダルは今必要か

現時点では不要と判断する。調整対象が少ない段階では、値とその適用責務を分ける方が効果がある。設定画面を先に作っても、未定義の項目や永続化を先行させることになる。独立した操作・表示設定が増え、試行・リセットしたい要求が具体化した時に設定モーダルを追加する。

| 分類 | 候補 | 現在／将来の責務 |
| --- | --- | --- |
| 利用者の操作設定 | クリック判定時間、将来のダブルクリック動作、操作方法 | 今回は判定時間の初期値を一か所へ。将来は型付き設定をイベント判定へ渡す |
| 利用者の表示設定 | ライト／ダーク・配色、ラベルの大きさ、ズームの好み | 配色は既存React stateとCSS変数。必要な項目から設定モデルへ移す |
| 開発用Graph調整 | 曲率、間隔、配置の評価係数 | 利用者設定と混ぜない。現在はpresentation／layoutに属する。調整用パネルは必要時のみ |
| 管理ポリシー | API取得上限、公開可否、認可、サーバー予算 | サーバー側の検証が正本。利用者の設定画面から上書きさせない |
| 探索状態 | 起点、展開・閉鎖、cursor、選択、座標 | セッション状態。設定の保存／リセットと一緒に消さない |

利用者用と管理用は同じモーダルへ継ぎ足さない。UI部品は共有可能だが、適用先・権限・保存先が違う。表示上限と一時キャッシュ上限は既存graph-stateの定数を維持し、操作の好みと同じ設定オブジェクトへ移さない。

## 後で大変になりやすい部分

1. ハンドラーへ値を直接埋め込む、単クリック／ダブルクリックで別の判定値を使う。今回、初期値と判定処理をまとめて回避した。
2. 設定変更のたびにCytoscape Coreを作り直す。今後はstyleやイベント設定を更新し、座標・選択・pan/zoomを維持する。判定時間を実行中に変更するなら旧タイマーを取消し、ハンドラーを差し替える。
3. 設定を変更すると探索stateまでリセットする。テーマ変更と同様に設定と探索を分ける。
4. 永続化の値を無検証で読む。導入時に既定値・型検証・範囲・旧値の移行を決める。localStorageとアカウント設定の優先順位もその時に明示する。
5. 管理設定をブラウザだけで検証する。管理ポリシーはサーバーで検証し、認可と保存処理を別に設計する。
6. モーダル表示中も背面のGraph入力・待機タイマーを動かす。モーダル導入時は待機ジェスチャーを取り消し、背面操作を止め、フォーカスの移動・Escape・閉じた後の復帰を設計する。設定モーダルを閉じただけで枝を展開しない。

ダブルクリックの有効／無効を設定にする時は、無効時に単クリックを即時確定するのか、連続クリックをどう扱うかまで決める。未使用のbooleanだけを先に追加しない。

今は汎用設定レジストリ、設定ごとの権限エンジン、localStorage／DB保存、doubleClickEnabledの未使用フラグは作らない。具体的な用途が決まってから必要な型と項目だけ追加する。
