# 利用者投稿の重複対策

2026-11-05。request IDの再送防止・連投制限とは別に、公開原記録の重複を防ぐ。U5の限定βに接続し、既存データをまとめ直すmigrationや本番切替は行わない。

## 利用者への結果

- 同じ具体的意味の再投稿は、既存Recordを使う。追加がなければ「登録済みの知識です」と既存の公開先を示す。Record・内容版・貢献活動を増やさない。受付と照合の記録は残す。
- 独立した新資料なら同じRecordへ根拠を追加する。既存本文・限定・原資料pinを勝手に置換しない。元資料の未取得の引用は一度補える。
- 別テーマへの追加は同じRecordの参照を追加する。その操作で選んでいないTheme、既に保存・共有したCapsuleの断面は変更しない。
- 同じRecordを明示的に訂正する操作では、文言の改善に加え、引用だけ／記載箇所だけの訂正も次の内容版として認める。本文の意味が同じでも、訂正を根拠追加用のappend処理へ変換しない。変更なしの訂正は内容版を増やさない。「別の新知識としての言い換え投稿」と「既存記録の編集履歴」を区別する。[引用訂正の回帰検証](../verification/KNOWLEDGE_QUOTE_CORRECTION_20261105.md)。

## 照合と受理

正本ID（現在有効な同一性判断のある別IDも含む）・情報の形・向き・肯否・構造化時期・補足対象の取得版を境界にする。自由文の本文・関係名・範囲は具体的意味を比較する。表記だけの正規化による完全一致と、既存Gemini無料枠での意味比較を併用する。意味分類の概念への対応づけを重複判定の代わりにしない。

共通知識DBの同じ対象と、公開中の旧KGの同じ向きの両端から候補を取得する。公開読取条件を通らない候補はAIへ送らない。共通知識側の公開停止を旧KGからの再発見で迂回しない。候補は最大20件、共通知識の同じ対象の取得上限は100件。旧KGも21件目を検知したら完了扱いせず、既存知識を指定するよう案内する。

比較は既存の根拠支持の評価とは別の軸。候補本文を根拠に使わず、AIが返せる照合先を渡した候補IDに限定する。通常の原資料照合・参照再確認・受付版digest・同意・現在会員状態の確認を省略しない。比較の追加も同じ永続quota ledgerへ記録し、追加の課金・鍵変更・共通Kev変更はしない。

意味比較入力と候補版・digestは送信wireと結果へ固定する。原資料照合後に候補が変わっていれば確認し直す。最終transactionでも再確認し、同時投稿を二重作成しない。現在の小規模βでは知識更新のtransactionを共通advisory lockで直列化する。AI・HTTP取得中にはこのlockを保持しない。並列性能が必要になった時点で対象別lock等へ細分化する。

根拠の独立性は資料本文を単位に扱う。既知の追跡パラメータとfragmentを取り除き、残るqueryは順序をそろえる。資料IDなど意味のあるqueryを一律に削除しない。同じURLの題名・箇所・引用を変えるだけでは根拠を増やさない。既存の受理記録にある本文hashと同じ取得本文も、新しい独立資料に数えない。原本・旧引用のID／pinを保持する。

受理receiptには`created / updated / existing / theme-linked`を記録する。`existing`では投稿者の新たな貢献活動を作らない。追加資料やテーマ参照には本人／匿名の既存帰属契約を使う。既存の受理済みdecisionは同じrequest IDから回復し、私有草稿を後から新しい対象へ付け替えない。

## この単位で保証しないもの

意味比較は有限候補に対するAI補助であり、自然言語の同一性を完全に証明する機能ではない。曖昧な別の知識を強引に統合しない。新規Entityを毎回別IDとして作る場合の同一性、同名別人の判定はU6のEntity同一性工程へ残る。同名だけで自動mergeしない。

今回接続するのは利用者投稿の受理経路。既存の重複Recordの統合、収集Worker／Chat取込経路全体への意味重複対策の適用はU6の残件として明示する。今回の対策を全経路の重複解消、本運用一般開放、U6全体の完了と扱わない。

検証は[重複対策の検証記録](../verification/KNOWLEDGE_DUPLICATES_20261105.md)へ残す。


## R1bの接続と残件

現在の版・公開範囲に結び付くEntity同一性を、検索と重複候補取得で共用する。比較用のID解決だけを行い、既存Recordを再利用した場合も元端点を保持する。判断の解除・訂正・停止、候補の増減は最終受理で再検査する。

資料比較は共通関数へまとめた。URLと書誌の比較keyを区別し、documentを選ぶquery parameterは残す。取得時のrequested URLとredirect後URLを保持し、抽出方式と有効な本文hashの組で照合する。URL比較は取得先の安全性の代わりにしない。

**現時点は会員投稿経路の接続であり、全経路の重複防止は未完了。** 共通の取得証明台帳、収集／外部packageへの接続、既存の重複整理はR1〜R3へ残る。[取込契約](KNOWLEDGE_IMPORT_CONTRACT.md)のAPIは未実装。[検証と配置](../verification/KNOWLEDGE_R1B_IDENTITY_DUPLICATES_20261105.md)。
