# Plunode 本運用初版：文脈照合と実装の再計画

2026-11-05。今回の依頼は、追加要件を含む経緯・計画・実装を突き合わせ、無断で完成範囲を小さくせず、次の実装を進められる状態へ立て直すこと。本書を**現在から先の実装順・残件・完了条件の入口**とする。各機能の詳細契約、過去の検証記録は残すが、過去の段階制限を初版全体の除外へ転用しない。

## 1. 判断と完成目標

**共通原本・版管理・公開投影・Worker・既存Capsuleを活かし、分断した処理をつなぐ。全面的な作り直しは勧めない。一方、従来の「U6の残りを少し実装してU7で確認」だけでは不足しており、工程と完成判定を組み直す。**

利用者は人物・作品・関係・出来事・背景を、対象と根拠を保って登録・訂正できる。運営者はテーマ・調べる範囲・利用上限を設定すれば、その後の資料探し・定期収集・読解・登録・公開が進む。登録済みの知識データ全体も継続的に巡回し、意味整理・同一性・重複への処理を進める。通常分の結果に管理者の個別承認や毎回の対象選択を要求しない。

閲覧者は、既存KGと新しい記録、原語と採用した訳名を検索し、通常Graph・テーマ・年表・根拠を同じ対象の文脈で往復できる。Capsuleは固定断面と独自編集を持ち、訂正を比較して取り込み、作者の意図した時点で同じ共有URLへ反映する。投稿者は帰属・公開匿名・結果と訂正履歴を確認できる。

| 進め方 | 判断 |
| --- | --- |
| 現在の小分け実装をそのまま続ける | 各画面の成功が、全件自動化・横断検索・多言語利用の完成を代替してしまう。採らない |
| 共通契約の不足を先に閉じ、自動化と入力・利用の接続を組み直す | 既存の根拠・版・receipt・認証・描画を利用できる。**推奨** |
| 新DB・新UI・新Workerへ全面再実装する | 今の不足が全面置換を必要とする根拠は得られていない。保全・回帰・ユーザー再確認の負担を増やすため採らない |

## 5. 先行して揃える設計

### 5.1 登録・整理・検索の共通契約

Entity、具体的なRecord、Source原本、意味対応、同一性の関連付け、原語、訳文を別に保持する。通常の入力・収集・取込・訂正・後追い整理は、同じ参照／版／根拠照合と受理処理を使う。公開の条件は入力元ごとに明示し、投稿者を運営収集者に偽装しない。

「同じ対象」「同じ意味の事実」「同じ資料」「同じ処理の再送」を別々に照合する。対象の別IDを関連付けた場合は重複候補の探索にも反映するが、原Recordの端点や旧CapsuleのIDを一括置換しない。単語や訳語一致だけで統合せず、肯否・限定・時期・文脈・根拠を保持する。

同一性は別名検索と別登録リンクだけで完成とせず、対象選択・近傍・経路・重複照合・通常Graphの表示に共通の解決層を使う。確認された同一組を一つの対象として読める投影と、元の登録・根拠へ辿れることを両立する。関連付けの解除・元版の訂正／停止で現在の解決が変わっても、過去の固定断面は付け替えない。

原語metadataの訂正、事実訂正、引用訂正、訳文訂正、意味対応、同一性の変更を、それぞれ正しい版・帰属へ記録する。いずれの入口でも無変更判定と重複判定を混同しない。過去の投稿／訳文を読む導線は固定版と現在版を区別する。

翻訳生成・意味一致確認にも、対象短文だけでなく必要量に絞った公開周辺文脈（対象・関係・資料箇所等）を固定して渡す。対象原文と文脈の版／hash、用語方針・prompt／modelを再利用条件へ含め、無関係な私有内容を送らない。原文が同じでも文脈が変わった訳を無条件に再利用しない。全量・全言語の翻訳を一度に行う前提は置かないが、未決であることを理由に検索・表示の多言語接続を後続へ落とさない。生成の対象言語・起動条件・自動採用の範囲は、既存の明示依頼と通常の収集運転を分け、R1/R4で方針と実評価を示す。

### 5.2 二つの自動運転を分ける

**テーマ収集**は「テーマ・核となる対象・調べる問い／範囲・資料の条件・頻度・上限・停止条件」を永続計画として設定する。期日到来から、候補資料の発見、取得、前回hashとの差分、読解、支持確認、重複照合、登録・Theme追記・公開を進める。資料ごとの追加承認や毎回のURL入力を要求しない。テーマ専用コードは増やさず、取得先の方式差は再利用可能な取得器へ置く。

**登録済みデータの巡回**は、旧KG由来を含む対象台帳を安定順に小分け走査し、意味未対応・古い対応・同一性・重複の候補を作る。全件の初回一巡と更新追従を区別し、原語・表記違いでも対象へ入る。全候補ペアを一度にAIへ送るのではなく、ID・別名・根拠・近傍・語義の索引で候補を絞り、文脈を検証する。

両方とも、job・作業項目・試行・lease世代・checkpoint・固定入力hash・適用receiptを持つ。既存の配送／利用量処理は共通化するが、巨大な汎用workflowエンジンは先行構築しない。予約枠不足・PC停止・429から通常再開し、結果送信の再試行で推論を繰り返さない。解除した候補を同じ根拠で即再適用しない。未解決が一件あることで正常分や次の巡回を止めず、保留の再評価条件も持つ。

自動適用には、対象版と根拠が固定された結果、適用方針版、サーバー側の現在参照・公開範囲・競合確認を要求する。通常の意味対応と同一性関連付けは自動反映の対象。AI処理を人が確認した事実とせず、理由と由来を保持して取り消せるようにする。手動画面はこの例外的な介入に使い、全件承認待ち箱にしない。

### 5.3 資料発見と無料枠の接続条件

現コードの確認modelは `gemini-3.5-flash-lite`（`knowledge-review-queue.ts:19`）。Google公式の[料金表](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)では、このmodelの検索Groundingは無料API枠では利用不可と記載されている。AI Studioで試せること、課金tier内に無料件数があることを、現free projectから無料で呼べる証拠にしない。11月5日に公式文書を確認したが、**実projectで検索を呼ぶ試験・課金有効化はしていない**。

従って、今の審査APIに検索toolを付けるだけ、モデルの記憶からURLを生成するだけ、という案は採らない。最初の能力確認で、追加課金なしの検索可能な接続・公開検索API／サイトのfeed等を候補として比べる。対象テーマに必要な資料を実際に発見できるか、取得と引用支持まで接続できるかを確認する。取得器を増やすこととテーマごとの意味コードを増やすことは分ける。

既存のmodel／審査設定は無断で差し替えず、検索の実行主体と用途別利用量を分離して比較する。[Googleの上限説明](https://ai.google.dev/gemini-api/docs/rate-limits)はproject単位の上限とmodel／tool差を明示しているため、別keyで枠を迂回しない。検索・整理・収集・翻訳が投稿確認枠を使い切らない配分、modelの終了／条件変更も扱う。無料で成立する接続が得られなければ、具体的な試験結果・代案・費用・体験への影響をユーザーへ提示し、自動収集を手動に縮めて完了とはしない。

### 5.5 リンクとAI入力の最低限の安全性

利用者の追記要件。専用の完全なフィッシング判定器や新しい有料監視サービスを先行構築せず、既存対策を共通化して不足を埋める。「HTTPSで取得できた」「根拠を支持した」を「遷移先が安全」の保証として表示しない。

| 場面 | 初版で揃える最低限 |
| --- | --- |
| 利用者が外部リンクを開く | 共通URL検査・リンクUIを使う。実行系scheme、埋込資格情報等を拒否し、表示タイトルとは別に遷移先hostを確認可能にする。国際化ドメインや表示名との不一致等で見誤りを招く場合は実hostを明示。外部遷移の識別・必要な場合の短い確認・別タブのopener/referrer対策を統一する。全クリックへ大きい確認画面を強制しない |
| ユーザー入力・AI結果の表示 | HTML／scriptとして実行せずテキストとして描画。Markdown／自動リンクも同じURL規則を通す。資料の題名・説明・プロフィール等が公式ログイン導線を装わないよう、外部hostとの区別を保つ |
| 自動の検索・取得・再取得 | 検索結果・AI出力のURLも未信頼として扱う。既存の`publicSourceDocument`を再利用し、認証不要HTTPS、公開IPのみ、DNS結果を接続先へ固定、各redirectの再検査、容量・時間・転送回数・形式の上限を守る。会員Cookie／秘密headerを転送せず、内部ネットワーク・metadata endpoint・local file等へアクセスさせない |
| AIによる読解・整理・翻訳 | 投稿文・資料・検索結果・引用・既存自由文を指示ではなく未信頼dataとして渡す。systemでの説明だけに依存せず、出力schema・許可参照・根拠hash・対象版・適用条件をサーバーで検査する。資料中の「承認しろ」「このURLへ秘密を送れ」でactor・予算・登録先・取得先・権限が変わらないようにする。AIに任意shell／SQL／私有データ読取・送信の権限を渡さない |
| 不審なリンク・資料への対応 | 該当URL／資料／taskだけの拒否・保留理由と、通報・停止・取消の既存運営経路を利用する。通常分は進め、管理者の全件URL承認へ戻さない |

既存根拠：資料schemaは`lib/domain/knowledge-foundation.ts:21`等でHTTP(S)に制限する。`lib/server/knowledge-source-verification.ts:17–48`はURL・IP・接続先固定・転送先の検査、`:57–65`は非実行のテキスト抽出、`gemini-knowledge-review.ts:17–32`は未信頼dataの扱いと厳格出力を持つ。主要な外部リンクには`noreferrer`等もある。現在これらが全くないという監査結果ではない。元URLと取得後の最終URLを記録・表示し、取得検査済みを安全認定と表示しない。新しい資料発見・パッケージ・自動整理も同じ取得器／適用境界へ接続し、別の弱いfetchを増やさない。これらは全攻撃への完全防御の証明ではない。

検証は通常の安全な資料と併せて、不正scheme、資格情報付き／紛らわしいhost、公開URLから私有IPへの転送、DNS差替え、巨大・連続転送、本文中の承認指示・権限変更・秘密送信要求・偽の根拠を含める。リンク遷移のUIとサーバー取得制限、AIの意味判断と権限制限は別々に確認する。標準対策・攻撃例・残る限界を記録し、「フィッシング／インジェクションを完全防止」とは報告しない。

## 7. 全体の完了条件と後続の扱い

次をすべて満たすまで、本運用初版完成としない。

- テーマ専用コードを追加せず、関係中心・年表中心の二実テーマとThemeなしを、実入力／取込／収集経路から作れる。資料探し・人の判断・入力の実作業時間、機械待ち、再試行を分けて記録する。
- テーマ設定後、通常の管理者操作を挟まず資料発見・次回収集・公開が進む。初回だけ手でjobを作った成功を定期運転の実証にしない。
- 一ページ上限より多い全対象を巡回し、追加・訂正・公開停止・解除・予算不足・PC再起動に追従する。対象総数・走査済み・残り・候補・適用・未解決と理由を追え、未解決を処理済みに偽装しない。
- 同表記別義・異表記同義、同名別人、別IDの同一対象、別言語、肯否・限定・期間差、URL違い・同一本文を通す。誤適用と見逃しを分け、評価用・未見例・実資料で確認する。完全無誤判定を待って全件手動へ戻さない。
- 外部リンクの遷移先を見誤りにくくし、ユーザー入力から危険なschemeやHTMLを実行しない。取得先・転送先・DNSの制限と、資料中のAIインジェクションで権限や適用条件を変えられないことを攻撃例で確認する。完全防御基盤の先行構築ではなく、既存の標準対策と不足の修正を受け入れる。
- 直接／Graph選択／Capsule選択の投稿を公開まで通す。人物・関係・出来事・背景・根拠追加・訂正が到達先を持ち、非匿名の活動と匿名除外、当時の内容版、未読対象が分かる。
- 原語metadataだけの訂正、異言語の事実訂正、訳文だけの訂正とその帰属を保持し、語検索・Graph・テーマ・保存断面まで確認する。
- 通常探索→Theme→年表／関係辺／根拠→Capsule編集→保存再訪→共有→原本訂正→選択取込→元探索復帰を、PC／スマホ・実Googleで通す。年表だけのCapsule、原精度・曖昧さ・時期なし情報も含む。
- 同URL反映、更新前コメント、固定コミュニティ掲載、現在の停止とOGPの認可を保つ。meta／画像をサイトが返す確認とSNS上のカード実表示を区別する。
- 既存KG全件の対応表、会員・独立コミュニティ・旧保存・旧収集成果、migration checksum・別DB復元・二重書込防止を照合する。仮想ケース・βの秘密値・会員データを本番へ混ぜない。

年表のドラッグ等による直接作図、年表同士の比較／マージ・2対1／異軸対応は、ユーザーが明示した後続／保持構想として残す。この「関係図と年表の並列表示」の完成を、年表同士の比較の完成としない。

ChatGPTスケジューラから任意の本番APIへ認証付きで送信する接続は、能力の実証待ちとして残す。今回確認した自動収集をその接続に依存させず、ローカルWorker＋本番APIで成立させる。自由なテーマ発案、多provider自動最適化、共同テーマ編集、課金制度等の未決／従来後続を、通常の定期収集・全データ整理まで除外する理由にしない。
