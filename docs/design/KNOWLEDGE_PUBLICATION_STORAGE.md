# 知識DBの公開投影と巡回台帳の保存

## 参照と保持契約

| 保存機構 | 実際の読取 | 保持 |
|---|---|---|
| 知識原本・公開実績 | 構成版、Record旧版、根拠、訳文、Capsuleに使う。現在の公開権限も照合 | 原本版、操作履歴、公開実績は既存の保持契約 |
| PostgreSQL公開世代 | 公開APIの検索・対象一覧・関係フィルタ・詳細・Graph・隣接・経路。検索／対象／隣接カーソル、通常探索の履歴とセッション復元が世代を指定 | 現役と切替後の猶予期間。暫定72時間。固定Record版が使う初回公開文脈は独立保存 |
| Neo4j公開投影 | 隣接探索で関係IDを取得。経路は同じGraphの完了を確認してPostgreSQL上の権限付き関係をたどる | 生きている公開世代または再試行可能なstaged／failed世代が参照する間 |
| 巡回一覧 | 自動巡回の走査・キュー・完了位置、内部の台帳CLI。対象消失は完全な一覧を処理した後に確定 | checkpointと現行対象が参照する間。整理の暫定候補は7日。実行・対象状態のヘッダと監査は別に保持 |
| Capsule・共有版 | 会員DBの固定スナップショットと知識原本の版。共有時の認可は原本版の公開実績・現在の状態を照合。更新比較だけ現役の投影を読む | 保存・共有・失効の既存契約 |

通常探索のURLは対象・RecordのIDを開き、ThemeのURLが固定するのはTheme構成版。通常探索の公開世代はブラウザ内の履歴・セッションに保持する。固定Record版APIと翻訳生成文脈は初回ready投影を使う。既存の受け入れ状態や投稿の索引反映チェックは現役世代を参照する。

## 採用した構造

- 世代ごとの全件複製は直接読めるが、本文・検索索引・Graphが世代数とともに増える。72時間を導入した場合も、入れ替わる世代数と知識量に比例した再書込みが続く。
- 差分を連鎖させると変更件数に近い書込みにできる。中間世代の復元、長い連鎖での索引検索、スナップショットの切替と障害復旧に追加処理が要る。
- 採用案では、検索用Record投影を本文・検索列・許可判定の固定参照ごと共用する。Entity投影も共用し、世代はIDと投影キーの対応を持つ。検索で原本の多数の版を再結合する負担を避け、旧テーブルも読めるビューで既存のAPIを維持する。世代メンバーシップは世代ごとに残る。件数×世代数の増加は小さな参照行に限られる。
- 公開範囲の正しい照合を優先して、Repeatable Readで全件を照合する。Record、対象、根拠、意味付け、旧KG型情報、対象Record／Themeへの依存を含む完全な投影キーを比較し、変化がない場合は確認した変更IDを現役世代に結び付ける。内容が変わった場合の検索列作成と本文書込みは新しい投影キーに限る。全件照合やメンバーシップ作成のCPU・I/Oは残る。
- Neo4jは対象IDの集合と関係のID・端点が同じとき、検証済み投影を共用する。内容版、現在の公開権限、参照の再検査はPostgreSQLの世代に従う。Graphを共有する世代間で本文は変わり得る。強制再投影は新しいGraphを作れる。
- 共通巡回は原本の変更番号をwriterロック下で照合し、旧KG巡回は整合検証済みの公開releaseを照合する。版が同じ完成一覧を再利用し、同じ巡回方針で処理済みのrunはキューを再走査しない。版が変わったstale一覧の途中行は取り除ける。巡回のPKと同一の補助索引を012で整理する。

## 切替・期限整理

Publisherの既存排他の下でPostgreSQLのstaged→Neo4jの完了確認・構築→PostgreSQLのready／現役ポインタ／変更ID確認を行う。承認後の原本変更や低い番号の遅着は、取得したcommit済みの変更ID集合で扱う。エラーは元の現役ポインタを保ち、同じstaged投影を再使用できる。

既存世代に012の適用時点から猶予を与える。以後の猶予は現役から外れた時点が基準。整理する旧世代が初回公開Record文脈を持つ場合は、内容・版・意味付けを先に保存する。新しい世代は有効化時に必要な文脈を確定する。保全済み文脈の読取でも現在の公開権限を照合する。

Graph読取の共有ロックはPGの読取スナップショットを開く前に取得する。整理側は専用の短い排他を取得できる場合にPGで失効を確定する。失効した既知の公開世代は410と `GENERATION_EXPIRED` を返す。検索は先頭から再検索、旧い探索状態は同じIDと条件を最新世代で読み直す。失効後にNeo4jの共有参照を再確認して対象を整理し、その後PGの不要な行を消す。世代ヘッダを残すためキャッシュや再開時も失効を判定できる。

公開と巡回の自動整理は既存Workerの設定で独立して有効化する。公開世代や巡回一覧を期限整理しても、公開済み原本・Theme構成版・Capsule固定版の履歴は同じ契約で読み取る。[移行と運用](../runbooks/KNOWLEDGE_PUBLICATION_STORAGE.md)。
