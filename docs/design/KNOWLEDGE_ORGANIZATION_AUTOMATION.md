# U6 全データ巡回と後追い整理の自動化

現在から先の工程・他機能への接続は[文脈照合と再計画](PLUNODE_IMPLEMENTATION_REPLAN_20261105.md)を優先する。本書は登録済み知識データの巡回を扱い、今回別途明示された「設定後の資料探し・定期収集」と混同しない。安全なリンク・取得先・未信頼AI入力の境界も新経路へ共用する。

2026-11-05。ユーザーの指摘によるスコープ訂正。**未実装の完成条件とコード調査であり、巡回・自動整理を実装済みとする記録ではない。**

## 要件の扱い

全データ巡回を初版から外す合意は確認できない。11月2日の統合計画は「人が指定した小さい記録群」と「全データの自律的な概念分割／統合」を記載していたが、前者を恒久的な必須手順とし、後者を巡回・候補生成・通常の自動整理全体の対象外へ広げた説明は誤りだった。後から足された要件も引き継ぐ。実装の区切りや工数見込みを、完成範囲の縮小理由にしない。

初版の完成条件は、管理者が毎回対象を選んだり、結果を一件ずつ承認したりしなくても、知識データ全体の巡回から整理候補の生成・根拠確認・条件を満たす適用まで進むこと。手動の比較・訂正・解除は任意の介入手段として残す。

巡回・自動判定・自動適用・公開反映を区別して進捗を報告する。「候補を並べて人に選ばせる」だけで自動整理完了にしない。概念体系の全面再編などの未決事項を理由に、これらを一括して後続へ送らない。

## 巡回と適用の境界

- 登録済みの知識データ全体を対象にする。旧KG由来と新しい共通原記録、テーマ有無、原語・訳文の違いで対象を黙って限定しない。旧KGの読取り・移入との接続はU7と照合し、未接続部分を対象外ではなく未完了として残す。
- 一度に全件をAIへ送る方式は不要。永続cursor、内容版・hash、走査世代、更新追従を持ち、上限のある小分け処理で全体を覆う。既存・新規・保留再評価のいずれかが永久に後回しにならない順序とする。
- 意味対応の不足・古い対応、同一対象の候補、意味の重複等を検出する。名前や具体的関係語の一致は候補条件であり、同一性・同義性の証明にはしない。対象・資料・肯否・限定・時期・言語を含む文脈を確認する。
- 検証した適用方針に合う結果は、人の個別承認なしで意味対応・同一性の関連付け等へ反映する。根拠・入力版・方針版・実行主体・判断を残し、訂正・解除と追跡を可能にする。AI処理を人間による確認として記録しない。
- 原文、具体的関係、既存ID、投稿者の帰属、旧版、保存済みTheme/Capsule断面を上書きしない。現在検索・Graphへの反映と、保存した断面の更新は区別する。
- 判断できない項目は理由と再評価条件を記録し、通常分の処理を止めない。期限・新資料・対象版更新・方針更新などによる再評価を設け、同じ不確実な判定を無制限に呼び直さない。保留が大量・恒常的になるなら自動化未達として報告する。
- 会員の私有内容を外部AIへ送る許可へ拡張しない。外部送信の対象・資格・公開停止を確認し、既存の利用量台帳と枠予約を使う。PC停止・429・枠切れ後の再開を管理者の再依頼に依存させない。共有Kevや課金サービスの変更許可とはしない。

## 実装と完了判定

### 2026-11-06 合意：成立を裏付ける検証で区切る

全登録データを巡回・整理する機能範囲は維持する。開発の完了判定は、構造・処理の成立をコードと境界テストで確認し、実データの機械的な全件走査と、少数の代表例の実AI処理で裏付けることとする。「理論上できる」という説明や架空データだけで済ませる意味ではない。

- 全件走査は、実際の対象数・重複や欠落・永続cursor・更新追従を安価に確認する。全件を外部AIへ送る必要はない。
- 意味対応・同一性の確認から自動適用／公開は、代表例と意味を区別すべき反例で確認する。全対象のAI処理完了や全出力の人手確認、複数日の利用枠消化を開発完了条件にしない。
- 再開・二重適用防止・対象更新／停止・枠待ちは、重要な境界を小さいテストで確認する。既に通った検証を、変更や失敗などの理由なく繰り返さない。
- 巡回済み・候補生成済み・確認待ち・適用済み・未解決は区別する。検証負担の削減を、未接続の自動整理を完成扱いする理由にしない。

実装はR2a（周期巡回・差分追従・整理作業の永続化）→R2b（文脈付き候補確認・自動適用・公開）の順で進める。R2aだけではR2全体完了ではない。これは作業の区切りであり、通常分の管理者操作を必要にしたり、旧KGを対象外にしたりする方針変更ではない。

1. 巡回台帳・世代・cursor・小分け候補キューを追加し、人の対象指定なしで初回一巡と追加・訂正への追従を通す。
2. 既存の原本・証拠・言語・公開範囲へ結び付いた候補生成／確認を接続し、実AIで意味・同一性判断と自動適用の品質を確認する。適用はサーバーが固定版と現在認可を再確認する。
3. PC再起動、送信結果不明、枠切れ、並行訂正、公開停止、解除後の再提案を確認する。receiptを保持し、再送で判断版や公開操作を増やさない。
4. 既存の意味整理・対象整理は任意管理として残し、走査済み／残り／候補／適用／未解決／待ち理由を確認できるようにする。見える一ページだけで全件完了と表示しない。
5. 一ページ上限より多いデータ、同表記別義・異表記同義、同名別人、同一対象の別資料、肯否・限定・期間差、多言語、古い対応、旧KG由来を含めて確認する。仮想パターンと二つの実テーマの双方を用いる。
6. 管理者操作を一切挟まない経路を実行し、巡回対象の網羅率、候補・適用・未解決の件数、誤適用と見逃し、待ち時間、利用量を記録する。課題を人の全件承認へ置き換えて合格にしない。

実装上の不成立が判明した場合は「どの対象・処理が、どの実測または制約で成立しないか」「代案と利用者への影響」を示す。通常の技術判断は進めるが、初版の利用者能力を削る代案を無断で採用しない。
