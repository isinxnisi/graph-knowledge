# テーマ動画を選び、生成し、観て決める

2026年11月25日。日英のウォークマン試作を受けた制作運用の設計。最初の実装目標は、担当者が手元のブラウザで公開テーマを選び、一つの企画から日英の横長動画を作り、観たうえでそれぞれの採用版を決められること。モデル比較と配信には、この工程で残る実物と記録を使う。[チャンネルの編集方針](THEME_VIDEO_CHANNEL.md) ／ [ウォークマン日英版・脚本・改稿記録](../../prototypes/theme-video/walkman/README.md)

同日、②のローカル制作室でWebbの公開第42版から日英を生成し、英語だけの修正と中断・再開を通した。試写では「内容の意味がほぼ分からない」「ウォークマン回と映像スタイルが揃っていない」「日本語の漢字に誤読がある」という反応があり、Webbの日英をともに「要修正」に戻した。旧版と判断の履歴は制作室で開ける。[Webb回の制作記録](http://127.0.0.1:3269/#case/03378e586e40459b8d115396e0585971)

### 次の一本で確かめること

**日本語一本で演出を決め、英語は試写した版から起こす。** ウォークマン回では、声を届けたい側と受け取る側を同じ画面に置き、声がどこを通るのかを視聴者が目で追えた。Webbの日英同時試作では同じ書体に揃えても、観測写真の隣で語りが進み、視聴者が自分で確かめる行為が乏しかった。次の日本語試作では、最初の写真に一度目を慣らし、一枚の鏡が作った像を別の写真でもう一度見つける。その間は語りを待たせる。こうした対応関係を担う絵と、もう一度その絵に戻る理由を、題材ごとに制作する。

制作室の新規・再試行は日本語先行が初期設定。英語を制作するときは試写した日本語の試行を選び、場面の順番、動き、根拠を固定して翻案する。台詞の長さと動きの秒数は英語の声に合わせる。今回の比較は前回と同じAstra／高を指定し、言語の分け方、根拠の渡し方、描画素材、編集を変えている。作品の差からモデルの優劣や同時生成の影響だけを判定することはできない。Ultraを検討するときは、同じ日本語企画・素材・編集時間を渡し、初稿の映像で差が出る場面を比べる。

台本で一度止め、作り手は「冒頭の問い」「答えに至る仕組みと、それを知る意味」「画面のどこで確かめられるか」を先に読む。たとえばWebbの初期調整では、十八の点が同じ星だと分かっても、話は半分しか伝わっていない。点を鏡の区画と同じ配置に並べると、どの区画を調整しているか追える。二枚の画像でその対応を見せ、次に何をできるようにしたのかまで語れるかを検討する。共通の編集メモを読むのは制作担当で、初見の視聴者には映像から見てもらう。[固定資料に使うNASAの記録](../../prototypes/theme-video/studio/assets/webb.json)

画面にはウォークマン回のロゴ位置、書体、紙色と暗色、字幕帯と出典位置を共通で使う。その上に題材固有の絵を載せる。日本語は字幕に自然な表記を残し、文脈で読みが変わる語に場面単位でかなを指定する。試聴には本編と同じ声・区切り・読み指定を使う。

**作品を選ぶ時間を、制作画面を開発する時間から分ける。** 次の初見試写では、一度観た人が「何がどう変わったか」「なぜそれが必要だったか」を自分の言葉で話せるかを聞く。迷った場面、気になった読み、ウォークマン回と見比べて浮いた箇所を記録し、採用の判断に使う。機械検証の結果は制作記録に残す。初見試写を経るまで、日英の書き出し成功やモデル変更を理由に作品を採用しない。

案件には固定した原資料、使った素材、採用した日英の編集表・音声・MP4・字幕、改稿した箇所と理由を残す。初見の感想、作者や依頼者の感想、音声・字幕の機械照合はそれぞれ出所を記す。ウォークマンの15発話、秒数、二人を並べる構図は、この作品の解法として参照できる。別の題材でも、見慣れた画面の中で「自分で見て関係に気づけた」という体験を届ける。

生成担当に渡すのは、チャンネルの約束、今回の問い、根拠の使える範囲、利用できる素材。どこから入りどの絵で結ぶかは提案の余地を残す。初見レビュー担当は完成候補を先に観て、迷った時刻や残った印象を記録してから台本と根拠を開く。この順序なら、台本どおりに作れたかと、初めて観た人に伝わるかを別々に判断できる。[初回の企画と試作手順](THEME_VIDEO_FIRST_PILOT.md)

## 一件をどう生成するか

1. **テーマから企画を起こす。** 公開テーマを検索し、題材と固定版を選ぶ。一つのテーマに複数の企画を作れる。担当者が切り口を指定するか、候補を出して一つを選ぶ。企画には「誰が何に気づけるか」「どの資料と絵で支えられるか」を残す。適した切り口がなければ候補のまま保留できる。
2. **形式・言語・モデルを選んで実行する。** 横長・日本語先行を初期設定にする。両言語の初稿を同時に見たい場合は日英同時制作を選べる。脚本・編集モデルはこの端末で利用できる Astra／高、Sol／高から選ぶ。指定したモデル・推論設定を残し、取得できない実モデルIDは不明と表示する。音声合成、素材、描画は別に記録する。
3. **映像を試写し、英語の元版を決める。** 場面ごとの発見と、そのために何が映る必要があるかを先に固める。日本語の語り・声・絵を揃えて一本を観る。英語では選んだ日本語版にある絵と根拠を使い、同じ発見が起きるように言葉と間を編集する。Webbには撮影された光点と鏡の位置を結ぶ演出素材があり、他の題材でもその企画に足りない写真や図を明示できる。[ウォークマンの絵](../../prototypes/theme-video/walkman/render.py) ／ [Webbの絵](../../prototypes/theme-video/webb/boards.py)
4. **観て、必要な箇所だけ直す。** 詳細画面で完成映像をすぐ再生でき、必要なときに台本・根拠・前稿・同じ場面の他言語版を開ける。修正は場面と理由を記入する。英語の一文を直したら英語の音声・字幕・映像を更新し、共通事実の訂正なら両版を再確認に戻す。旧版は比較に残し、担当者が言語ごとの採用版を選ぶ。

画面は「テーマから新規作成」「案件一覧」「案件詳細」の三つで一巡できる。一覧にはテーマ・切り口・日英それぞれの状態・最終更新を表示する。詳細の実行はローカルのバックグラウンド処理へ渡し、閉じて開き直しても進捗・最終成功工程・失敗理由を読めるようにする。二重クリックは同じ実行を返す。失敗時は完了済み素材から再開し、別モデルでの再実行は履歴に新しい試行を加える。採用版を後続の失敗で上書きしない。

保存は初版ならローカルのSQLite台帳と案件ごとのファイルで足りる。企画には参照テーマと版、試行には入力資料・指示の版・モデル・素材・手直し、出力には形式・言語・ファイル識別子・結果、採用には選んだ出力と確認理由を持つ。ジョブの状態（待機／実行／完了／失敗）と作品の状態（確認待ち／要修正／採用）は独立させる。運営テーマ登録と一般投稿のAI審査は既存の責務を保ち、動画生成には専用の実行経路を用いる。[既存のAI処理の責務](AI_PROCESSING_DIRECTION.md)

最初の通し確認では、英語だけを再生成する途中で処理を止め、画面を開き直して再開する。日本語の採用版と英語の旧稿の両方を引き続き再生でき、新しい英語版が別の候補として並べば、やり直しを含めた一件の運用が通ったと判断できる。

## 横長とショートは企画段階で選ぶ

| | 横長 | ショート |
| --- | --- | --- |
| 選ぶ理由 | 二つのものを同じ画面に保つ、複数の資料や時点を見比べる、人の行動が意味を持つまで待つ。 | 一つの動作・変化・問いを、縦画面で目を移しながら最後まで味わえる。ショートから初めて来た人にも答えが届く。 |
| ウォークマンで試すなら | 二人が友人の妻のピアノを聴く。隣にいるのに会話のたびに外す。その経験がボタンに結び付く。 | 「二人に音楽は届く。隣の声は？」。本体、ボタン、相手の耳を縦に配置し、声が届くまでを一度追う。歴史的経緯を語る場合は、その根拠や帰属が分かる尺を取る。 |
| 制作と確認 | 企画から横長の絵コンテを作り、二人や資料の対応が残るか通して観る。 | 同じ出典・素材から縦の絵コンテと語りを起こし、実機サイズで文字・視線・操作表示との重なりを確認する。回ごとにショートのみ、横長のみ、両方を選べる。 |

役割は先に決め、縦版を作るのは最初の横長案件が一巡してから。短くても横長の試作は横長として扱う。YouTubeの一般チャンネルでは縦長・正方形の3分以内がショートの対象。配信時に同じチャンネルの公開・限定公開動画を関連動画にできる（上級者向け機能）。横長への誘導がなくても、一本として面白い企画を選ぶ。[ショートの形式](https://support.google.com/youtube/answer/15424877?hl=ja) ／ [関連動画](https://support.google.com/youtube/answer/14075157?hl=ja)

## 公開先を決めるとき

今回の日本語版は89.79秒、英語版は78.79秒で、図中の文字も異なる。この組み合わせなら**一つの企画に二つの完成映像・二つの動画ID**が自然である。YouTubeの多言語音声は同じ映像におおむね同尺の音声を載せる方式で、対応する企画では有力な選択肢になる。[YouTubeの複数言語機能](https://support.google.com/youtube/answer/13338784?hl=ja)

日英の投稿を継続でき、それぞれの言語で登録フィードやコメントを運営したいなら、**言語別2チャンネル**が第一候補。二題目で日英別々の仕上げと概要欄の準備時間を記録し、公開後に両言語の投稿とコメント対応を継続できるかで判断する。少ない本数で始めるなら、1チャンネル＋言語別の再生リストでも別々の映像を配信できる。台帳では言語版と配信先を独立させ、チャンネル構成を変えても脚本や映像を作り直さずに済むようにする。[YouTubeの言語別チャンネル運営](https://support.google.com/youtube/answer/6070467?hl=ja)

将来は、採用済み出力を選び、対象チャンネル・言語・形式を確認してアップロードし、戻った動画IDと公開状態を保存する。最初はStudioで手動アップロードしたIDも同じように扱える。試写や非公開アップロードとサイト掲載は別の操作。送信結果が不明なら再送前に既存動画を照合する。テーマ側には企画単位で複数本を関連付け、公開・埋め込み可能と確認した版だけを表示する。[YouTube動画のアップロードAPI](https://developers.google.com/youtube/v3/docs/videos/insert?hl=ja)

テーマページでは表示言語と同じ版を初期選択し、「日本語／English」で切り替える。片方だけなら「日本語版を観る」のように明示し、自動再生せずに選べる。両版の秒数が違うので初版の切り替えは冒頭から。テーマの訂正・非公開化、動画の削除・埋め込み停止では該当する関連を外せる。後日のテーマ改版で根拠が変わったときに判断できるよう、作品の制作に使った版を保持する。[テーマの言語別表示](THEME_LOCALE_PUBLICATION_20261117.md)

## 着手順と完了の見分け方

| 順序 | 実際に行うこと | 次へ進める目印 |
| --- | --- | --- |
| ① 完了 | 比較用の作品を固定し、出典・編集上の判断・日英の違いを実ファイルに結び付ける。 | ウォークマンの同じ場面を日英で参照でき、何を直したか、誰の反応やどの検証を根拠にしたかを説明できる。 |
| ② 完了 | localhostの制作画面と実行経路を最小構成で作る。見本を再生し、Webbの「一つの星が十八の点に写る」で別題材を生成した。 | 担当者が画面からテーマ・モデルを選び、新しい企画の日英の音声付きMP4・字幕・根拠を確認する。英語を一箇所直してその版だけを再生成し、再起動後も前稿と採用版を開ける。固定見本の再描画と新規生成の成功を区別して表示する。 |
| ③ 運用が通った後 | 同じ根拠・素材・音声エンジン・描画条件で、基準設定とSol／高に同じ編集工程を任せる。ウォークマンは既知の問題の再発を調べ、別題材は新しい判断を試す。ショートは適した一本で別に試す。 | モデル名を隠して初稿を観る。誤った意味・失った見どころ・人が直した箇所と修正時間、取得できた利用量を対にして残す。どの工程なら任せられるかを決める。Sol／高は検証目標で、Sol／中への展開は対象外。 |
| ④ 公開準備 | チャンネル構成を決め、採用版をYouTubeに送る運用、テーマとの紐付け、サイトでの日英切り替えをつなぐ。 | 選んだ言語・チャンネルの動画を試写し、対象テーマに正しい版が出る。片言語のみの状態、掲載解除、再読み込みでも表示を確かめられる。 |

最初の開発で重視する指標は、担当者が一件を迷わず完成まで運べたか、違和感に気づいた場面に戻れたか、修正にどれだけ人の手を使ったか。日英の制作量が見えてから、更新頻度と二つのチャンネルを継続できるかを判断する。
