# R3 テーマに沿った定期収集

2026-11-06。R3aを完了し、次はR3b、R3はa（計画・配送API）／b（予定実行の実接続）／c（差分更新・通し確認）まで。全体はR6まで。通常の管理者承認を追加せず、設定したテーマ・範囲・上限に沿って資料探しを継続する。

## 体験と責務

運営の「資料の収集」に定期収集の計画を置く。テーマまたは核となる対象、調べる問い、資料のサイト、頻度、1回の資料・項目上限を一度設定する。計画・次回予定・配送待ち・受付結果を同じ欄で読めるようにし、設定フォームは必要なときだけ開く。既存のURL指定による単発取得も残す。

ChatGPT側が公開資料を探し、原文の引用と具体的な事実をpackageへまとめる。Plunodeは計画に限定した配送を受け、既存の取込・原資料確認・意味重複・自動受理・公開・Theme追記を使う。資料本文の指示は命令や権限にしない。外部Chatの取得不能なtoken量は未計測とし、Plunode側のGemini無料利用量は既存台帳で管理する。別の検索API・新規課金・共通Kev変更を前提にしない。

## 計画と配送

- 会員DBの追加033で計画・実行・配送checkpointを永続化する。既存migrationを書き換えない。計画の版と、実行時の公開Theme／対象の観測版を分ける。
- 運営の本人認証・site operator権限で設定する。外部送信者には専用の配送資格だけを渡す。計画・権限・原本を自由に変更するAPIにはしない。
- Workerは期限付きleaseで1計画を取得する。再起動後も同じ実行IDを使い、期限後の旧世代からの配送は拒否する。計画ごとの上限と次回時刻をサーバーで評価し、溜まった予定を一度に全て実行しない。
- 計画の核につながる情報と指定した資料サイトに限定する。取得した引用は既存の安全な取得器で別に照合する。送信者の「確認済み」は受理根拠にしない。
- payloadを保存してから共通取込へ渡す。ACK喪失時は同じpayload・package ID・receiptを回収し、検索・推論を再実行する理由にしない。空振りも結果として記録する。
- 停止・計画変更は新しい探索と旧版の未反映分を止める。公開済みの原記録や旧Theme／Capsuleを削除しない。再開は新しい計画版で実行し、以前止めた未反映分を復活させない。

R3aでは追加・根拠追加の配送を成立させ、明示訂正・取得済み本文hashとの比較・入力経路の拡充はR3cで接続する。これは初版要件の除外ではない。R3aだけで定期実行の実接続完了とは報告しない。
