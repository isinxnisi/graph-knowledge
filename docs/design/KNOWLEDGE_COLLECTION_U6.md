# U6：有限収集と後追い整理

2026-11-04。採用済み[統合計画](PLUNODE_PRODUCTION_INTEGRATION.md)のU6/P3。U5の投稿審査と区別し、既存の収集Workerを切り替えず、新経路をHTTPS βの専用データへ段階接続する。

## 今回の実装：資料取得まで

運営画面の「資料の収集」で依頼名、調べる内容・範囲、公開HTTPS URL（最大5つ）を指定する。PCの新しいWorkerがAPIをpollし、資料ごとに取得本文・抽出テキスト・取得日時・hashを保持する。未起動は「PC側の処理待ち」、取得中・完了・取得不可・取消を区別する。

この段階は資料取得まで。AI読解・知識の登録・公開・テーマ追加・後追い意味整理を完了とはしない。資料取得を公開承認として扱わず、次工程は取得済み本文から再開する。通常の運営収集結果に一件ずつの承認や利用者投稿の審査を挟む方針へ変更しない。

### ここで区切る理由

資料取得と結果配送の停止復旧を、AI費用・登録の意味判断から独立して実証する。Webの入力からPC取得、API再送、private artifact保持までの実経路を先に固定すると、次の読解で取得済み本文を再利用できる。将来の構想を縮小するための区切りではない。

## job・権限・保存

- jobは運営セッションの現在認可・Origin・期待本人を検査して作る。タイトル・範囲・URL・source-capture-v1をサーバーで固定する。本文からactorを指定できない。
- 専用Worker credentialはclaim／complete／failだけに限定する。DBの接続値、会員の私有投稿、公開書込、shell命令を渡さない。Webへはtoken hashだけを置き、PCのtokenとcheckpointは所有者限定の0700/0600で保存する。既存認証・他Workerの資格と共用しない。
- 会員DBの独立schema knowledge_collectionへ追加027を明示適用する。jobs／items／commands／workers。取得本文はprivate PG volumeのbytea artifact、抽出テキストとhashはmetadata。公開検索・会員の公開活動へ出さない。既存000〜026のchecksumを変更しない。
- 原資料のURL・redirectの各段階で、匿名HTTPS・公開IP・TLS・容量・時間を確認する。既存U5の取得器を共用する。HTMLはscript等を除いてテキスト化し、元bodyと抽出値のhashをサーバーでも照合する。資料中の命令を実行しない。
- 今回は同時進行5job、24時間で20job、各job5資料、各資料2MB／抽出120000文字、取得試行3回、lease10分。失敗の再試行は最低2分待つ。AI呼出・課金予約はこの段階では0。次の読解を既存Gemini枠と別台帳で無制限に回すことを認めた意味ではない。

## 再開・部分結果・取消

job、資料item、lease世代、request ID、取得artifact、配送checkpointを分ける。claimのACKが消えた場合も同じrequestを再送して同じleaseを得る。本文を取得したらAPI送信前にPCへ保存し、completeのACKが消えても同じpayloadを再送する。送信待ちを新しい取得失敗で置き換えない。

期限切れは新世代で再取得でき、旧世代の遅着を拒否する。PCに取得artifactが残っていれば、新世代も同じURLの本文を再利用する。URLごとに完了するので、取得不可の一件が他の完成資料を捨てない。取消は未完了itemのleaseを失効させ、取得済みartifactと操作履歴を残す。公開済み知識を取り消す操作へ流用しない。

一覧は20件のkeysetページングで、同時刻の依頼もUUIDを含むcursorで欠落させない。表示だけで新しいjobやAI利用を発生させない。入力と送信結果不明のrequestは、再認可中にも同じcomponent内へ保持する。
