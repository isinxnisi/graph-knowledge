# 制作中テーマの非公開化と承認公開版（2026-11-17）

## 今回の境界

ユーザー確認：共通知識としてのRecord／Entity／Sourceとその公開は維持する。テーマ固有の編集本文・構成・Theme訳文・専用画像は、制作／独立見直し中は運営者だけに返す。工程phaseを公開可否として流用しない。一般投稿のAI審査、収集計画、ChatGPT予定を別基盤へ置換しない。

現行はTheme構成の通常登録完了を一般公開と同じ扱いにしており、制作案件の独立見直し完了と公開境界が接続されていない。既存テーマ版・共通知識原本・Capsuleを保持し、公開可否と承認された提供版を追加管理する。

## 永続化と提供版

知識DBへ追加010を作り、Themeごとの公開headと、一般閲覧を許可した正確な版のrelease台帳を置く。新規Themeは公開headなしのdraft。既存の公開Themeと過去の公開版はbackfillして維持するが、指定の制作中ドラゴンクエストは全版をbackfill対象から外す。既存SQLのchecksumを変えない。

一般向けの一覧・検索・関連Theme・直接URL・版指定・OGP・サイトマップ・共有参照確認は、この同じhead／releaseの照合を通す。更新中は最後の承認版を返し、承認されていない中間版への直接指定は拒否する。現在の非公開化／原資料・参照の撤回は承認履歴より優先する。言語別提供版の保持も、承認された版の範囲を越えない。

Theme固有訳文は公開版に使う訳文参照版を保持する。既存公開Themeの訳文表示は初回移行で変えず、制作・訳文編集の開始時に既存表示を固定する。共通知識の訳文とは分ける。画像は一般公開releaseからの参照または独立した公開商品の参照がある場合だけ一般配信し、運営者プレビューには認証付きno-storeで返す。

## 完了と公開の安全な接続

member DBへ追加045を作り、既存制作案件に公開の完了意図／証明を保存する。現在のlease・状態版・review phase・現在対象digest／ガイドのwhole-theme pass・未反映なし・未完作業なしを既存completeで検査する。正常完了と公開意図を同じmember transactionで確定し、その後に知識DBの公開headをCASで切り替える。DBをまたぐため「公開してから案件commit」は行わない。

知識側の切替直前にも、知識の通常書込ロックと対象版・参照／訳文・ガイド／商品を再照合する。失敗時はdraftのまま、または前の承認版のままにする。応答喪失は同じcompletion request／証明の再送で回復し、一般のgetは公開処理を勝手に開始しない。正常完了前の期限切れ実行・古い評価・未反映／不合格からの公開は拒否する。新しいMCPツールを乱立せず、既存案件更新／読取へ状態と再送情報を追加する。

## プレビューと運営表示

既存の会員session＋有効な運営者資格を使う専用プレビューURL／APIを設け、通常Theme readerに近い画面を再利用する。匿名・一般会員は拒否し、noindex／no-storeを付ける。秘密URLだけで認証を省略しない。運営一覧に制作中／見直し中／公開済みと、自分の制作案件の進捗／残件を表示する。他運営者の非公開案件進捗は既存所有者境界を維持する。

read_theme／update_theme／訳文／受付照会は、認証済み運営者の編集中最新版を扱えるようにする。一般公開APIを認証Cookieだけでプレビューへ変化させず、公開読取は運営者であっても承認版だけを返す。

## 検証・移行・残存キャッシュ

隔離DBで初期draft、日英・全旧版・API／OGP／画像／sitemapの拒否、運営者のみのプレビュー、承認公開、改訂中の旧公開版維持、訳文だけの改訂、競合・中断・再送・期限失効・撤回を検証する。既存登録・翻訳・Capsule／一般投稿を回帰確認し、PC／スマートフォン相当幅をβで先行確認する。

正式はバックアップ・復元試験と追加migration後、Webと必要な処理imageを整合させる。公開境界導入後に旧コードを機械的に戻すとdraftを再公開するため、その復旧は行わない。ドラゴンクエストの構成や共通知識を消さず、公開許可だけを移行する。既に第三者へ渡った本文・画像や検索Indexの即時消去は保証せず、現在URLの拒否・サイトマップ除外・Cache-Controlと実際のCDN応答を確認し、削除要求等が必要なら別に報告する。

## 実装時の補足（2026-11-18）

- `theme_releases` は承認公開可能なTheme内容版、`theme_release_approvals` は同一Theme版に対する訳文更新も含む追記専用の承認履歴。公開済み訳文の過去版／Capsule参照も保持する。Theme固有訳文の作業更新は公開headの `draft_updated_at` で表示・公開確認へ伝え、同文再利用で不要な再見直しを要求しない。
- `read_theme` のMCP入力へ `includeImages`（既定false）を追加。成功した運営者読取結果に紐づく最大2言語のテーマ挿絵だけをimage contentとして返す。非公開の画像URLを匿名で取得可能にせず、ChatGPTの見直しも継続可能にする。商品画像の公開契約は維持。
- 通常画面に近い運営者プレビューは既存Explorerを再利用し、Theme読取・関連商品取得だけを認証付き専用APIへ接続。公開APIはCookieの有無にかかわらず承認公開版を返す。制作案件の進捗表示は本人所有分に限定し、他の運営者の非公開案件を開示しない。
- 背景note追加の取込準備／最終適用は、既存 `operatorThemeIntake` が実際の受付・所有者・運営権限を照合した時だけ非公開の作業Themeを参照できる。外部パッケージやnamespaceの自己申告をこの権限に使わない。一般収集のActor種別・冪等digest・AI経路は保持する。
- 稼働ガイド第9節の正規GET条件は「公開前の認証プレビューによる全体見直し→承認公開切替→公開後の正規GET確認」に整合させる必要がある。本文の正本は各環境のDBであり、コード反映でガイド本文を自動コピーしない。
