# Discovery：公開KGの2〜3段探索

2026-10-17。M3の初回実装。暫定採用した正式検索・既存プリセット・3タブ・一覧検索を維持し、対象の関係記録から任意に開く「2〜3段先の接点」を追加する。収集処理・受入判断・公開KG・会員データは変更しない。

## 採用した単位と意味

対象UUID、段数2または3、既存Graphと同じpredicate／制作Roleを受ける読み取り専用 `GET /api/discovery/paths`。すべての段で、同じ公開ClaimにpredicateとRoleをLIMIT前に評価する。Roleは既存Graphどおり制作Claimだけを限定する。世界は編集的文脈であり、DB分類へ変換しない。名前のページ内絞込は一段一覧の表示だけに適用し、経路には適用しないことを画面に明示する。未知条件・未対応条件・同名パラメータの重複は400で拒否する。

辿る順番とClaimの正規方向を区別する。両方向・肯定／否定を含む「記録間の経路」であり、新しい直接関係・因果関係・影響関係・共作事実を生成しない。各接続の独立Claim、Role、肯否、刊行物scope、期間、出典数を保ち、既存の根拠表示でCitation・locator・原資料へ戻れる。所属記録の期間不明や受賞時点の限定を、現在の同僚関係へ読み替えない。

同じ2対象間の並行Claimは候補を増殖させず、経路の各段にClaim ID配列を保持する。詳細では一般的な制作Claimと刊行物別の限定Claimを独立に併記する。同一対象を再訪する循環、自己循環、同一経路・同一Claimの重複は除外する。異なる中継点の経路は残す。

## 有界取得と公開版

可変長Cypherで全組合せを作らず、対象別にソート済み近傍をまとめて読み、アプリ側で幅優先探索する。初回は次の固定上限とする。

| 制約 | 上限 |
| --- | --- |
| 対象ごとの公開記録 | 20件。21件目で未取得ありを検出 |
| 近傍を読む対象 | 全段で24対象 |
| 中間経路 | 128件 |
| 提案経路 | 12件 |
| 段数 | 厳密に2段／3段。短い末端で水増ししない |

記録UUID順、端点列による経路キーで同一revision・同一条件の順序を安定させる。経路の追加ページング・全経路列挙は未実装であり、候補12件を「全件」と表示しない。取得制限の理由（neighbors／expansions／prefixes／results）、制限された対象、読んだ対象数を返し、画面に部分範囲と上限を表示する。0件でも未取得があれば「経路なし」と断定しない。

APIの取得前後、クライアントの取得前後、Graph復元の前後で公開revisionを照合する。条件変更や段数切替の古い通信は中止し、旧結果を操作可能なまま残さない。版の衝突は409、画面は記録と経路の再取得を提示する。公開KGを書き換えて版変化を作る検証は行わない。

## DiscoveryとGraph

既存の関係記録の見出し直下に控えめな開閉操作を置く。開くまで経路APIを呼ばず、検索の必須手順にしない。小さい文字主体の候補、2／3段の直接切替、候補の再クリックまたは明示的な経路解除で操作できる。経路解除は対象・世界・問い・Role・名前を消さない。選択状態は既存Discoveryの履歴snapshotに保持し、GraphからBackで復元する。条件が変わった場合はその条件の経路を改めて開く。タブ・検索入口・初期プリセットを追加／置換しない。

Graphへは既存workspace URLの枝を使って全段を再取得する。端点列・各段のClaim ID・公開revisionを小さい `via` パラメータで渡し、復元したGraphに全記録が実在することを確認した後だけ適用する。版不一致・記録欠落・壊れた経路は部分適用しない。最後の対象を選択し、Graph詳細に「Discoveryで選んだ経路」と各独立Claimの根拠ボタンを残す。Graph既存の「表示中の最短経路」と選択経路は別の表示とし、近道に置き換えない。

経路だけの孤立Graphではなく、各中継対象の最初20記録も含む既存Graphを開く。Graph操作・条件変更・戻る操作を保つ。`via` は初回の復元検証用で、成功後のURL更新・保存・共有は既存のGraph workspace形式を使用する。「選んだ経路」注釈自体の永続保存・Graphでの線の専用強調は今回の範囲外。根拠を読むボタンから通常のClaim詳細へ進める。

## 未対応と次の拡張

- 初回は対象必須の、全段に同じ関係・制作Roleを適用する探索。段ごとに「原作→作画」等を別指定する検索、終点指定、経路名の全文検索、組織立場／Event Roleの限定、期間の共通部分、肯定だけの限定、4段以上、全件ページングは未対応。新しいDSLは作らない。
- 同じRoleをすべての段に指定すると途中の制作Claimが一致せず0件になることがある。別ClaimのRoleを合成して経路を作らない。
- 次に価値が高い能力は、利用者が選んだ中継対象を優先して部分範囲を広げること、および既存の型で段ごとのpredicate／Roleを明示指定すること。高次数組織の大量組合せを先に増やす方式は採らない。
- 任意長・最短経路だけのAPI、全タブ再設計、事前計算したおすすめ専用KGは代替案として見送った。既存の一段API・Graph・独立Claimの根拠を維持できる小さい単位を採用した。

## 収集側へ返す短い要求

[a95420bの経路共有ルール](COLLECTION_THEMES.md#データ収集とdiscovery-modelの報告連携)に従い、検索能力と公開データの不足を分ける。

1. [漫画r0003の4代表経路](MANGA_R0003_ACCEPTANCE_REVIEW.md)は現在の公開KGには揃っていない。最新の記録では正式受入済み・公開未適用であり、今回の機能評価では公開経路として使わない。追加収集や再承認ではなく、将来の公開後に同じUUID・Claim・Citation・刊行物scopeを維持した経路共有を求める。公開applyは本作業の範囲外。
2. 「大場つぐみ→DEATH NOTE／バクマン。」等の作者から別作品への経路は公開接続が揃えば同じ2段機能で扱える。「赤坂アカ→【推しの子】←横槍メンゴ→クズの本懐」等も3段機能で扱える。別名や人物間の直接Claimを探索都合だけで追加する必要はない。
3. 段ごとの異なるRole限定は検索機能の不足であり、収集側の欠損と扱わない。科学の研究成果・理論・実験から人物への接続は、公開Entity／predicate／根拠の有無を個別に確認すべき別課題。所属経路で代用しない。
