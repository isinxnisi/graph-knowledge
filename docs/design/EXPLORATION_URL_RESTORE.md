# 探索GraphのURL復元・共有

2026-10-14採用。起点・確定条件・枝・配置をブックマーク／共有する。Capsuleの永続ID・版・権限・公開判断とは別機能。

## 形式と保存境界

`/explore/<Entity UUID v4>?s=<base64url(DEFLATE(JSON))>`。内部形式v1。dataset、起点、四条件、枝UUID／open意図／受理ページ数、ノード座標、zoom、初回配置済みフラグを保持する。座標は小数桁を丸めずJSON numberとして往復する（符号付きゼロは通常の0）。Panは保存せず、復元時の画面へ中央配置する。閉じた枝と休止子孫も対象。

検索語・条件draft・選択・詳細の読書位置・端末のlocale／theme・Graphの手動高さ・直前探索の履歴・通信状態・cursor・Entity／Claim本文・Source本文・ローカル保存名・時刻を含めない。選択は起点へ戻る。API応答をURL内の知識として使わない。過去時点の事実や同じClaim集合の固定を保証しない。

`s`なしは追加条件なしで起点の一ページから始める。`s`ありの不正値・重複・未知版・起点不一致・別datasetは復元エラー。未知条件語彙・UUID・非有限座標・不正倍率・枝重複・既存40ページ／400枝上限等は既存途中保存schemaでも検証する。復号前の長さとストリーム展開後100,000 bytesを制限する。

URLは暗号化ではない。条件と対象UUID・配置を含み、共有相手・ブラウザ履歴・アクセスログから読める。会員のprivate内容やCapsule本文は含まない。URLは認可・公開範囲・datasetを解除しない。同じdatasetが公開される同じ実行環境へのリンクであり、別環境へ自動接続しない。

## 自動更新とコピー

通常の探索state変更と、ドラッグ終了／zoom／pan／layout後350msに現在状態をcaptureし、Native History `replaceState`で更新する。履歴を操作ごとに増やさない。ブックマークを識別しやすいようページtitleも現在の起点名へ更新する。Pan自身は保存しない。コピー押下とpagehideでも同期capture／圧縮を試みる。復元中・近傍通信中・直接閲覧dialog中は更新しない。直接閲覧dialogを明示的に閉じた後は、現在GraphのURLへ戻す。通信中に離れた場合は直前に確定した状態となる。読み込み中の応答や未受理ページを保存したようには扱わない。

4,000文字を実用目標とする。originを含めて超えた場合は共有先の制約に注意を出す。現在の実装上限はpath＋query 8,000文字で、普遍的なHTTP／SNS上限とはしない。超えたら枝・座標を黙って削らず、コピーを止め、URLが前の状態であることと途中保存／JSON書出しの利用を画面へ表示する。40ページ上限等でも同様。小さく戻せば自動更新が再開する。先頭だけのURLへ勝手に縮約しない。一時キャッシュの退避等で起点から受理ページを辿れない休止枝が残った場合も、再現可能なURLとして発行せず、更新停止を明示する。

## 現在のKGからの復元

既存の途中保存再構成を再利用し、現行Entity APIとneighborsから現在のcursorだけで再取得する。保存open意図から表示を導出し、全体の検証成功後だけ新世代として適用する。v1のページ数は現行API既定の20 Claim/pageを前提とし、既定サイズを変える際は途中保存と本形式の互換性を検討する。保存されたページ数を取得できない、枝が辿れない、保存座標のEntityがなくなった場合は、URL復元では正常成功にしない。既存のローカル途中保存の「除外件数を表示して再開」は変更しない。

枝数・ページ数・座標対象が維持されても、現在のKGでClaimや説明が変わることはある。新しい相手が取得範囲に加わった場合は通常の配置補完を行い、保存済み座標を維持する。取得中のrevision不一致は既存409で失敗し、再試行へ戻す。知識版そのものをURLに固定しない。

全体60秒と既存要求単位15秒の制限を使う。キャンセル／unmount後の応答は適用しない。起点404は「起点が現在見つからない」、枝欠損・取得失敗等は「完全に復元できない」と区別する。途中のGraphは表示しない。再試行または明示的な復元中止→検索を提供する。不正URLを条件なしの正常復元へ自動変換しない。

## OGP

起点名・説明文だけをサーバーmetadataへ反映する。Graph構図画像は保留。圧縮形式はブラウザ／Nodeで解釈可能だが、構図画像には現行KGからの枝再取得・画像用描画・日本語フォント・複数要求の制限と失敗時対応が追加で必要となる。今回その基盤は追加しない。Nextの画像metadata routeは実装手段として使えるが、長い探索URLがSNSで保持・再取得される保証にはならない。

noindex／nofollowを継承し、公開範囲は変更しない。現在のVPS preview認証やクローラー側の取得／キャッシュにより、SNSプレビューは利用できない場合がある。SNS各社の実カード表示は未確認。OG画像が出ることを今回の完成条件にしない。

参考: [fflate公式](https://github.com/101arrowz/fflate)、[Next画像metadata](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/opengraph-image)。実装時はインストール済みNext 16.3.8のpage／metadata guideも確認。

## 既存機能・将来境界

名前付きビュー、途中保存collection v2／file v1、Capsule／会員保存の形式と保存領域を変えない。既存直接閲覧URLも維持する。URLを将来の永続identityや履歴モデルとして固定しない。多段の探索履歴、ブラウザBackによる探索操作単位の巻戻し、短縮URLのサーバー保存は今回追加しない。
