## プリセットと実行

`presetApplication` は既存の対象指定有無プロパティから共通条件を解決し、プリセットの親子階層を作らない。

| 区分 | 対象・操作 |
| --- | --- |
| 対象指定済み3件 | PLUTO／Princeton／NBIの固定UUIDとadjacent条件を検証して直接Graph。小さい「対象を変更」から同じ条件の対象検索へも進める |
| 共通pattern対応2件 | other-worksと著者Role版。代表対象を選ばず、条件の成立する作品そのものをPOST検索し、ユーザーが選ぶ |
| 旧経路方式3件 | work-creators／co-creators／institution-bridge。「従来の経路探索」と明記し従来の探索・名前指定・明示例を維持。新しい共通条件対応とは表示しない |

カタログの分野・関係・Roleはプリセットを探す条件で、KGの条件に流用しない。patternは全段肯定。Roleのnullは限定なし、空配列は一致なしを維持する。不適合なkindは自動修正せず、種類か関係条件の変更を案内する。patternから一段への明示変更にはGraphと同じ `freeRelation` を使い、Role・肯定条件を保持する。

## API・Graph・戻る契約

- 対象検索は既存POST `/api/discovery/entities` を使用。条件／cursor／revisionを束縛し、Abortした遅着応答は受理しない。timeout・409は未確認のまま再検索を提示する。
- Graphへ既存URL v2の共通条件・Entity枝・必要証拠を渡す。新しい一時 `match` v1は検索時revisionとMatchWitnessを保持し、条件key・root・参照との一致を確認する。Graph復元前に元Entity／Claimを直接読み、正規方向・Role・肯否・非再訪・撤回を検査する。復元後も公開版を照合し、変化時は部分Graphを適用せず対象再検索を案内する。近傍の上限外の証拠も直接検証する。
- patternの完全証拠を内部保持し、初期表示は起点の最初の段だけ。以降は受入済みの通常Graphと共通のEntity操作をそのまま使う。新しいpattern操作や経路開閉UIは追加しない。
- 成功後の共有URLは既存codecが通常のURL v2として更新し、一時 `match` を除去する。旧URL／via／保存View／Workspaceの意味や形式を変更しない。通常の保存復元は従来どおり現在版で再検証する。
- 独立した `connectionsWorkspace` v1を既存history snapshotへ追加し、カタログ条件・並び順、対象の名前・種類・関係条件、cursor・結果cache、各画面のscrollを保持する。Graph遷移前に同期保存する。Back復帰cacheは公開版を照合し、Graphで編集した条件から対象検索を上書きしない。「プリセット検索へ戻る」はUndoと別の画面移動。

主な実装は `DiscoveryConnections`、`discovery-connections`、`use-discovery-targets`、`discovery-relation-navigation`。APIやGraph状態管理の新方式は追加していない。
