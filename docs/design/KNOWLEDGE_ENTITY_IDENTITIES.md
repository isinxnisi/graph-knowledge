# U6d 同じ対象の関連付け

2026-11-05。対象は独立した登録IDを持つ共通原本Entity。通常の登録・収集を待たせる承認工程は増やさない。名称が同じだけでは同一としない。

## 利用体験

`/operations#identity` で公開中の対象を名前・別名から探す。基準を選ぶと、正規化した名前・別名の完全一致候補に絞る。一致は証明ではなく、条件解除で異なる表記も探せる。候補の全体にSQLで条件を適用し、総数と25件ずつの一覧を表示する。

比較する相手を選び、分類・説明・別名・ID・現在公開できる関連記録（最大5件）と資料の固定版を比較する。運営が確認したHTTPS資料、該当箇所、理由を記録して確認後に適用する。名前の類似度による自動統合、AI照会、課金サービスの追加は行わない。

探索のEntity詳細には折りたたんだ「同じ対象の別の登録・現在の関連付け」を出す。関連付け先へ移動し、他方の記録を読める。名前検索では、有効な関連付け先の原語名・別名も手掛かりにできる。検索結果の文・元のEntity IDは変えない。関連付けの取得失敗で探索本体を消さない。

## 保存・安全性

- migration `006-entity-identities.sql` を追加。既適用migrationは変更しない。二つのIDの順序を正規化したペアと、追記のみの判断版・操作の再送記録を分離する。
- 両Entityの内容版と、比較時の関連付け版を照合する。現在公開されている内容版だけに適用できる。対象が訂正されるとその接続は要見直しとなり、検索・同一組の算出から除く。非公開／停止した対象は公開導線へ出さない。
- 運営権限、activeな本人session、同一Originを確認する。操作中は会員行・sessionをロックし、認証状態を再確認する。Webからmigrationは実行しない。
- 全ての関連付け書込みを専用transaction advisory lockで直列化し、両対象をID順にロック。比較後の訂正、同時更新、同じrequest IDの別内容を拒否する。同じ要求の再送は同じ結果を返す。
- 関連付けは無向。同じ組は有効な接続の到達範囲で、最大20件。直接の接続を解除しても別経路があれば同じ組に残ることを表示する。解除も新しい判断版となり、理由と確認資料を保持する。
- 検索カーソルはその時点の関連付け検索ID集合にも結び付ける。途中で関連付けが変わったページを無言で混在させない。
- 原文・Recordの両端・旧Entity版・Theme構成版・Capsuleの固定断面・訳文参照は書き換えない。関連付け自体を事実の関係線として描画しない。

## R1b：現在の同一性を投稿照合へ接続

検索と投稿の重複候補取得は同じresolverで、現在公開中・確認時のEntity内容版が一致する接続だけを解決する。共通原本と、関連付け先に含まれる旧KG UUIDを対象とする。名前の一致だけで意味比較へ同一IDを渡さない。比較時だけ代表IDへ置換し、再利用するRecordの元端点・旧断面を書き換えない。

最終受理は同一性の書込みと共有／排他のadvisory lockで排他し、候補と現在参照を再確認する。訂正・停止・解除で有効な接続が消えた場合は、以前の照合結果だけで適用しない。[R1b検証](../verification/KNOWLEDGE_R1B_IDENTITY_DUPLICATES_20261105.md)。

## 残す範囲

「同じ対象」は運営の根拠付き判断であり、URLだけから機械的に証明するものではない。人物と作品など基本分類が明確に矛盾する場合は内容を先に確認・訂正する（人物/person等は同等）。「対象」と「宇宙望遠鏡」など、未指定・自由な細分類の違いだけで再定義を強制しない。同一組内に矛盾した否定制約を管理する機能、Graphのノードを畳む表示、既存IDの一括置換は含めない。既存KG由来で共通原本へ未取得の対象は、共通原本に取得してから扱う。

外部取込はU6e、二テーマを用いた通し確認はU6fへ接続する。関連付けだけで意味重複検出が全経路へ適用済みになったとはしない。正式VPSは変更しない。
