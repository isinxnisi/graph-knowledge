## 設計判断

| 判断 | 理由・境界 |
| --- | --- |
| 案Bを起点に具体的な記録と任意の意味対応を分離 | 未整理でも主張・関係名・根拠・範囲を表示・検索できる。意味の訂正に根拠の書換えは不要。 |
| 専用PostgreSQLだけで構成 | 同じ現行記録から検索と図を作る。Neo4jとの二重更新・再投影の運用を増やさず、登録体験を評価する。既存Neo4jには書かない。 |
| 現行状態と追記履歴 | `theme75.state` はJSONBの読取モデル、`events` は入力と結果、`receipts` は再送照合。1行ロックで更新を直列化する小規模な初版。大規模運用の最終構成ではない。 |
| 入力原本と採用した根拠箇所を保存 | URL・資料名・locator・要約／抜粋・確認日・hashを保存。実際の入力もeventsに残す。リンク先全文のアーカイブや将来の再現は保証しない。 |
| 文字列検索と意味条件を区別 | 名前・具体文・関係名・範囲・根拠要約を検索。意味条件は対応付け済みだけ。「招待」から「参加」を推論しない。既存の意味は他テーマでも選べる。 |
| 識別と名称を分離 | 任意IDと自由な分類。同名の既存対象は分類とIDを候補へ併記し、名前だけで暗黙統合しない。グローバル同定・重複統合は未実装。 |
| 既存CapsuleStudioを再利用 | local originの文書として表示しKG IDを捏造しない。テーマID・観測内容版・意味版・根拠は別snapshotへ保持。隔離版では既存KG検索追加を非表示。 |
| 固定断面と明示取込 | 原記録の訂正で私有図・共有図を置き換えない。元のままのフィールドを更新し、独自ラベル・メモ・配置を維持。端点訂正では必要な新ノードを補う。 |
| 意味対応は内容版に結び付く | 内容訂正後は意味を再確認。意味だけの訂正は原記録・根拠の版を変えない。同じ意味IDの異なる定義への再使用は拒否。定義は対応付けと別に保持し、最後の対応が外れても次の記録で再利用できる。 |
| 明示した共有版のコピー | 同じトークンの対象コピーだけを更新。開いている画面は自動差替えしない。停止後は404、再開時は新トークン。 |
| 再送ID・期待版 | 同一入力の再送は同じ結果。違う入力でのID再利用・古い版の上書きは409。フォーム入力を残して理由を示す。 |

## 保存・運用上限

専用DB `plunode_theme75`、schema `theme75`。初回DDLをtransaction advisory lockで直列化し、同時アクセスの初期化競合を防ぐ。会員DBのmigrationは変更しない。

- 入力2MB、現行状態25MB、100テーマ。1テーマ200対象・400記録。
- Capsule既存上限は200対象・400関係・100テキスト・1000根拠。上限超過は拒否し元記録を残す。
- Entity名・具体文・抜粋はCapsuleに対応する入力上限で検証。テーマの長い題名・説明はCapsule欄の既存上限に合わせる。
- 訂正理由・内容版・意味版・入力・結果を保存。原本履歴の一覧UIは未実装。Capsule差分では観測時の文脈を確認できる。
- 初期パッケージの確認日は2026-11-01。`retrievedAt` の00:00:00Zは日付を表す準備値で、取得時刻の実測ではない。

横断検索は現行記録の走査。大量データと高並列性は未計測。必要な規模が判明した段階で、原本を保持したままrecord/revision/mapping/read-modelの別表と索引へ分離する。Neo4j投影は多段経路探索の実要求・計測に基づき再判断する。

## 訂正・初版の制限

保存した選択範囲の既存記録を追い、新規記録を既存Capsuleへ自動追加しない。関係からエピソード等への**種類変更**は既存図を勝手に変換せず、新しいCapsuleを作るよう明示して取込を拒否する。

取込時の文書を `sourceDocument` として保存し、独自編集との比較基準を固定する。表示処理の将来変更で独自編集と誤判定しないためのもの。初期の確認用Capsuleにこの値がない場合だけ、保存したsnapshotから比較文書を復元する。

元テーマのEntity名称・分類編集、グローバルEntity統合、概念の一括分割／統合・辞書改名UIは未実装。記録への意味の付け直し・解除はできる。意味の同一性・根拠の正しさは資料の文脈を読む判断であり、アプリの形式・参照・版検証と区別する。

## 年表

初版は「時期から読む」のグループと日付順一覧。完成した年表グラフではない。保存型は年月日／期間、周期（軸・周期長・座標・折返し）、定性軸（座標の意味・始終点）、時期なしを区別する。周期・定性軸はパッケージ入力、フォームは日付を編集する。10月→2月を逆転日付へ変換せず、エピソードへ仮の日付を補わない。

比較・重ね合わせ・2対1・連結・複数レーンは未実装・未決。一本の尺度への変換は前提にしない。ID・型付き時間値・snapshotを保って拡張できるが、複数軸合成・軸間対応・多重時間注釈は別設計と検証が必要。全構想が現在の型だけで成立するとはしない。
