# テーマ動画の配信・掲載と制作室の運用

2026-11-28の設計。対象は[テーマ動画の運用](THEME_VIDEO_OPERATIONS.md#着手順と完了の見分け方)の④公開準備。[実装の到達点と残り](../PLUNODE_PROGRESS.md)。

## 運営者の動線

制作一覧 → 完成動画の言語と試行を試写 → 投稿情報を編集 → 対象チャンネルを確認して投稿 → YouTubeでの処理結果を確認 → テーマTOPでの見え方をプレビュー → 掲載。差し替えと掲載解除は、案件の詳細とテーマ別の掲載管理の両方から対象のテーマ・言語を選んで操作できる。

- 制作室が完成MP4、字幕、試行履歴、評価、投稿を管理する。YouTubeは動画の配信、Plunodeのサイト運営はテーマごとの掲載と順序を管理する。
- 一作品に、日英で異なる完成映像・尺・YouTube IDを持てる。元動画から作ったショートは現行どおり別の制作案件。横長版は初稿が短くても横長として扱う。
- 投稿と掲載は別の確認操作。アップロード成功時にテーマには出ない。「限定公開」はリンクを知れば誰でも観られ、公開テーマへの掲載は訪問者が視聴できる状態を作る。掲載確認画面に対象サイト、テーマ、言語、動画、限定公開時の説明を出す。

## ④a 制作一覧・評価・ゴミ箱

現行の [Ledger](../../prototypes/theme-video/studio/ledger.py) は案件・試行・言語を保持し、言語ごとの採用版と改稿履歴を管理する。既存サイドバーとURLを入口として使い、主画面に検索できる制作一覧を足す。

| 項目 | 表示・操作 |
| --- | --- |
| 一覧の粒度 | 1行1制作案件。サムネイル、作品名、テーマ名、横長／ショート、モデルと生成時間、★評価、日英それぞれの「YouTube」「テーマ掲載」、作成日時。動画の生成中は行に「生成中」を表示し、一覧を開くときと更新ボタンで状態を取得する。行を開くと試行・言語・採用版を確認。投稿済みの版と掲載中の版が異なる場合はラベルと版番号で分かる。 |
| 検索 | タイトルとテーマ名を一つの欄で検索。言語の有無、横長／ショート、評価、配信・掲載状態で絞り込み。案件の作成が新しい順を初期値とし、更新順・評価順・テーマ順にも並べ替え。検索条件と一覧位置を詳細から戻ったときに復元。 |
| 画面密度 | PCは小さめの文字、短い行、横長の小さなサムネイルを使い、見出しを固定。スマホはタイトル・テーマ・評価・日英の状態を2〜3行にまとめたコンパクト行、収まらない場合は同密度のカード。操作は行を開いて行える。サイドバーは直近の作業と一覧への入口を担う。 |
| サムネイル | 採用版、未採用なら最新の完成版のポスターを使い、無ければ既定画像。クリックで同じ映像を拡大試写でき、試写しながら評価を保存できる。背景クリック、Esc、閉じるボタンで一覧に戻る。日英・縦横の縮尺を維持し、一覧でMP4を読み込まない。YouTubeのカスタムサムネイルとは独立。 |
| 評価 | 作品単位で1〜7の☆と未評価。案件画面と一覧の拡大試写で入力・解除し、一覧に即時反映。評価操作では案件の作成日時・更新日時を更新しない。採用／要修正と独立して保存し、試行を増やしても評価を失わない。比較時は既存の版別レビューを引き続き使う。 |
| モデルと生成時間 | モデルは言語ごとに採用版、最新の完成版、最新試行の順で選ぶ。新しい試行はワーカーが実際に処理した時間を表示する。旧作は映像ファイルの書き出し時刻が分かる場合、待ち時間を含む受付から完成までの目安を表示する。 |
| ゴミ箱 | 捨てる単位は案件。通常一覧から外し、ゴミ箱で検索・復元。試行、日英の媒体、採用、評価、元版や保存案との参照は復元できるよう保持。処理中は対象と状態を表示し、処理の完了または明示的な中断後に移動する。 |
| 完全削除 | ゴミ箱から容量と影響を確認し、ローカルの媒体・編集素材を明示操作で削除する。別案件が元資料を参照中なら、参照先の保全が済んでから実施。掲載中や送信結果確認中の案件は、相手先のIDを失わないよう先に解決する。YouTube動画・テーマ掲載は各機能で操作する。品質見本は閲覧専用。 |

SQLiteに評価・ゴミ箱・配信の状態を追加し、従来案件は未評価で表示する。一覧と詳細を同じ判定で絞り、採用・試行・案・ショートの親子リンクも照合する。完全削除と送信予約の競合は台帳トランザクションで防ぎ、ファイル整理は対象パスを検証して状態を記録し、途中で停止しても再実行できる形にする。過去のファイルや動画の再生成を前提にしない。

## ④b YouTube投稿と日英の接続

### 事前準備と必要なタイミング

| いつ | 運営者が行うこと | 実装側が用意すること |
| --- | --- | --- |
| 設計と画面・模擬API検証の段階 | 作業なし。既存チャンネルを前提に進められる。 | 投稿前画面、模擬応答、掲載プレビュー。 |
| 最初の実投稿試験の前 | Google Cloudの配信用プロジェクトで YouTube Data API v3 を有効化。Google Auth Platformで同意画面、利用者、Web OAuthクライアントを設定。External／Testingなら両チャンネルを操作するアカウントをテストユーザーに追加。 | 確定したリダイレクトURLと登録手順を提示。制作室の外部URLで既存のアクセス保護を通して接続できるコールバックを用意。クレデンシャルをサーバー側設定に登録する手段を用意。 |
| 日英それぞれの最初の実投稿前 | 制作室の「日本語チャンネルを接続」「英語チャンネルを接続」からGoogleに同意し、対象チャンネル名・@ハンドルを確認。同じGoogleアカウントでも両枠で行う。 | 接続結果のチャンネルIDを記録・照合し、同じチャンネルが両枠に入ったら警告して確定せず、アカウント／チャンネルの選び直しを案内。 |
| 英語版で15分を超える投稿やカスタムサムネイルが必要になったとき | YouTube Studio → 設定 → チャンネル → 機能の利用資格 → 中級者向け機能 → 電話認証。現在は15分以内・自動サムネイルで運用可能。 | 確認できた資格または運営設定をチャンネルごとに表示し、資格を要する操作にだけ案内。既定で動画を短縮する処理は置かない。 |
| 運用開始後、Google認証が切れたとき | 該当言語の「再接続」から本人が同意。External／Testingではリフレッシュトークンが7日で失効する。継続運用に入るときは、同意画面の公開状態とGoogleが求める確認を判断する。 | 再接続後も編集した投稿情報、送信先、送信途中の記録を保持。 |

コールバックは既存のCloudflare Accessと制作室の運営者認証の両方に従い、短命・一度限りのstateとPKCEを使う。投稿は利用者のOAuthで行い、チャンネル単位でトークンを保管。接続・投稿前の `channels.list(mine=true)` と投稿応答の `snippet.channelId` を設定済みのチャンネルIDと照合する。アップロードと照合に必要な権限を実接続時に確認し、投稿後の公開範囲変更に追加権限が要るときは、その操作で同意を求める。Googleトークンとアップロード再開URLはWindows上の制作室の保護された保存領域に置き、公開サイトや制作エージェントへ渡さない。[GoogleのWeb OAuth](https://developers.google.com/identity/protocols/oauth2/web-server) ／ [チャンネルの照合](https://developers.google.com/youtube/data/reference/rest/v3/channels/list) ／ [トークン失効](https://developers.google.com/identity/protocols/oauth2#expiration)

2026年11月2日のYouTube仕様変更で、未監査のAPIプロジェクトを非公開投稿に固定する扱いは撤廃された。既定の割当内で限定公開を選べる。Google OAuthの同意画面と、チャンネルの機能資格はそれぞれ別に確認する。概要欄の長尺動画の外部URLをクリック可能にするには上級者機能が必要で、Shortsの概要欄URLはクリックできない。テーマへの導線の有無と投稿の可否は画面でも区別する。[API変更履歴](https://developers.google.com/youtube/data/revision_history#november-2-2026) ／ [機能の利用資格](https://support.google.com/youtube/answer/9890437?hl=ja) ／ [概要欄リンク](https://support.google.com/youtube/answer/13748639?hl=ja)

### 投稿フォーム

- 対象ファイル・言語・版・尺・向き、接続済みのチャンネル、編集できるタイトル（100文字以内）、説明（UTF-8で5,000バイト以内）、タグ（APIの合算規則で500文字以内）、カテゴリ、動画・題名の言語を表示。作品名・テーマ名・出典と音声クレジット・正式の言語別テーマURLから編集可能な下書きを作る。タグは今後の直接制作で作者が言語版ごとに任意で添えられる。追加のモデル呼び出しは不要。新規下書きでは作品情報と作者の候補からタグを入れ、既存の下書きでも「作品情報からタグを入力」で補える。カテゴリは日英とも「教育」を初期値とし、必要なときだけ詳細設定で編集する。下書きと送信した内容を別に保存する。
- 初期設定は「限定公開」。投稿時は個別に「非公開／限定公開／公開」を選べ、選んだ値をAPIに明示して送る。既定値を変更すると新規投稿フォームの初期値に反映する。既存動画の公開範囲は対象IDと変更内容を表示して個別に変更し、公開済みのURLを変えずに更新する。YouTube Studioで行った変更も同期する。
- 視聴者指定は「子ども向けではない」を既定とする。必要時の合成・改変コンテンツと有料プロモーションの申告、埋め込みの許可と登録者への通知をガイド付きで確認。限定公開の初期値では通知をオフにする。YouTube指定の投稿告知を表示し、利用規約・プライバシーへの案内、接続解除を用意する。
- 投稿前に実際に送るMP4を試写し、映像内の字幕を確認する。添付できるYouTube用字幕は、対象言語とタイミングを確認して同じ動画IDに登録できる。カスタムサムネイルは対応チャンネルで処理完了後に送る。英語チャンネルは当面、自動サムネイルでも投稿できる。字幕・サムネイルは個別に再試行できる。[投稿UIの要件](https://developers.google.com/youtube/terms/required-minimum-functionality#uploading_videos) ／ [動画の項目と制限](https://developers.google.com/youtube/data/reference/rest/v3/videos) ／ [サムネイル](https://developers.google.com/youtube/data/reference/rest/v3/thumbnails/set)

### 映像内の字幕とYouTubeの字幕

- **投稿するMP4に映像内字幕を入れることを基本とする。** YouTubeの字幕設定がオフでも、ミュートで見ても、場面の意味と主な発見が伝わるようにする。日英はそれぞれの仕上がりの言葉と間を使う。ウォークマンの縦版のように、台詞の吹き出しや場面内の文字で意味が伝わるところは、その表現を字幕として生かせる。発話の短縮、位置、改行、間は場面に合わせて決め、声が聞き取れた瞬間などの演出は文字の出る時刻でも表現する。
- 作者が字幕を絵と一緒に配置し、完成MP4に描画する。横長では図や資料の文字と重なる位置を避け、縦版では実機に近い幅でShortsの右側と下部の操作表示も含めて確認する。画面の文字を二言語同時に重ねる運用は避け、各チャンネルとテーマ表示に対応する版を使う。
- 新作の制作依頼にこの字幕方針を渡す。作者が通常の編集で決めた発話と最終タイミングを映像内字幕とSRTの両方に使う。字幕専用のモデル呼び出しやAI審査、書き出し後のAI文字起こしは通常の工程に加えない。ファイル形式と時刻の検査はコードで行い、視認性は既存の試写で確認する。
- SRTは同じ版の実際の発話と最終編集の時刻で保存し、制作室での参照、翻訳、必要に応じたYouTubeの切替式字幕（CC）に使う。YouTubeでの読みやすさを調整したい人向けに、音の手がかりも必要に応じてトラックに記せる。CCを付けるときは視聴者の設定で重ねて表示されうるため、実機で両方が読めるかを確認する。SRTの保存と制作開始前の台本承認は別の操作。[YouTube字幕の表示設定](https://support.google.com/youtube/answer/100078?hl=ja) ／ [字幕ファイルの登録](https://support.google.com/youtube/answer/2734796?hl=ja)
- 投稿画面の専用プレーヤーは、実際に投稿するMP4を消音で開く。プレーヤーに切替式字幕は重ねない。元のMP4とSRTから字幕を追加したMP4を同じ欄で切り替えて試写し、選択中のファイルを投稿する。既存作に字幕を追加するかは、絵に組み込まれた文字も含め実画で判断する。字幕の確認を申告するチェック欄は設けない。

投稿画面の案内例。「英語チャンネルに接続されていません → Googleで接続」「中級者機能が必要です → 自動サムネイルで投稿／YouTube Studioで電話認証」「アップロード済み・YouTubeで処理中 → 完了後に埋め込み可否を確認」「限定公開でテーマに掲載すると、テーマ訪問者が視聴できます → 掲載プレビュー」。停止理由は実際に失敗した段階と次にできる操作を示す。

### 再開と状態の扱い

投稿ジョブは制作キューと分け、選んだ案件・試行・言語、チャンネルID、ファイルの同一性、投稿メタデータの確定値を固定する。同じ動画とチャンネルへの二重操作は既存ジョブを返す。再投稿が必要なときは新しい動画IDができることを確認する。中断時は再開URLに受理位置を問い合わせ、最終応答を失った場合は「YouTube側の結果を確認中」にして投稿済み一覧や運営者の動画ID確認で照合する。同じ操作で新規アップロードを始めない。[再開可能なアップロード](https://developers.google.com/youtube/data/guides/using_resumable_upload_protocol)

一覧の「YouTube」は未投稿／送信中／処理中／限定公開／公開／非公開／要対応。「テーマ掲載」は未掲載／日英・環境別の掲載／確認待ち。YouTube側で削除・非公開化・埋め込み禁止になると掲載の再生を停止し、運営画面に操作を返す。ネットワーク障害時は取得失敗と動画の削除を区別し、取得結果に鮮度期限を持たせる。正式サイトの確認は、その環境のサーバーから行えるようにする。限定公開の状態取得とOAuth切断時の扱いは実接続で検証する。取得したAPIデータは規約に従って更新または削除し、制作情報と運営者が行った掲載操作の記録とは保存期間を分ける。YouTube Studioで先に投稿した既存動画も、動画ID・チャンネル・言語・埋め込みの確認を通じて同じ台帳へ紐付けられる。[YouTube APIデータの保存](https://developers.google.com/youtube/terms/developer-policies)

## ④c テーマTOPのアイキャッチと掲載管理

### 視聴画面

- テーマ画面に掲載素材があるときは、タイトルの直後に導入文とアイキャッチを一つの欄にまとめる。PCは左にテーマの問いと導入文、右に横長の映像や資料画像を置き、後続の年表と関係図が早く見える高さに収める。横幅に余裕がある場合だけ隣の資料を脇にのぞかせる。スマホでは導入文の次に映像が続く。掲載素材がない場合は従来の導入を使い、テーマ画像は既存の導入・サムネイルで使う。動画を押すと拡大して試写できる。
- **混在できるスライドショーを初回から扱う。** 一つの先頭位置を動画または画像にでき、複数の作品と画像を並べ替えられる。一枚なら送り操作を表示せず、候補がなければ従来の導入へ。自動送り・自動再生を使わず、矢印やページ位置はプレイヤーの外側。隣のスライドはポスターのみ。再生の意思表示で選択中のYouTubeプレイヤーを一つ読み込み、スライドや言語を変えたら元を止める。読み込み・再生失敗時は案内と利用可能ならYouTube視聴リンクを表示。
- サイト言語と同じ言語の動画を初期選択。日英が揃う作品は一つの位置で「日本語／English」を切り替える。片方だけなら、その言語の動画を勝手に同じ言語版として表示しない。現在の言語に合う別スライドを先に出し、片言語の作品には「日本語版を観る／Watch in English」と明示して選べるようにする。各版の尺と編集が異なるので切替後はその版の冒頭から。
- ショートも登録・掲載可能。先頭には自動選出しない。動画カードには縦型と分かるポスターを用い、明示操作で縦の試写面を開く。本文幅に引き伸ばさず、必要な再生領域を確保しながら導入・年表・関係図を押しのけない寸法をβのPCとスマホで確かめる。
- 画像候補は、そのテーマの公開版に紐付く年表・個別記録の画像などから重複を除いて抽出する。出典・表示条件・許諾とクレジットを確認できる資料を運営者が個別に選び、画像のキャプションで題材との関係を伝える。テーマ表紙用の PlunodeOriginal は新規の掲載候補から外す。以前の掲載は差し替えや解除で整理できる。既存のalt、出典、クレジット、焦点を使い、由来が不明なものは表示条件を確認する。[既存の画像と公開版の契約](THEME_LOCALE_PUBLICATION_20261117.md)
- iframeは検証済み動画IDから公式埋め込みURLを生成し、任意HTMLの保存を受け付けない。再生前の画像はPlunodeが表示できるものを使う。サイトの通信・Cookie選択、Referrer、プレイヤー最小寸法、操作・ロゴを覆わない要件は実ブラウザで確認する。[埋め込みの方法](https://support.google.com/youtube/answer/171780?hl=ja) ／ [プレイヤー仕様](https://developers.google.com/youtube/iframe_api_reference)

### データと操作の境界

- サイト側は公開テーマとその版に対して、順序付きの掲載枠を保存する。各枠は画像のIDと出典・対象版、または作品に属する日英の動画ID・タイトル・尺・向きと可視性。動画枠にはテーマ全体か、テーマに含まれるEntity・RecordのIDと版を対象として指定する。TOPとノード詳細への表示は掲載位置として選べる。同じ作品を複数箇所に使っても一つのYouTube動画を参照する。映像とノードの関連を公開知識の主張や検索用の関係エッジにはしない。
- 公開データの正本は掲載先サイト。制作室のローカルDBだけに載る案や未公開動画をサイトの公開レスポンスへ含めない。PCが停止しても正式サイトが公開データとYouTube再生にアクセスできるようにする。実装時は既存のサイト運営認可を土台に、動画掲載だけを扱う認可と監査を追加する。制作室からは接続済みの固定環境を選び、トークンに書ける操作・環境を束縛する。
- テーマ検索から対象の公開版を開き、日英の作品を名前・テーマ名で検索し、サムネイルと投稿状態を見て選べる。日英個別の付替え・解除、作品枠の追加削除、順序・先頭の変更、ノードへの関連付け・解除、実表示のプレビューを操作できる。画像はアイキャッチのスライドへの任意追加。掲載先でYouTubeを照合できない場合は制作室の情報で下書きの並びを表示し、その状態を明記する。保存は掲載設定の版を照合して一括適用し、複数の運営操作による上書きを防ぐ。差し替えは新動画の可否確認後に切り替える。削除するものは当該箇所の掲載で、複数箇所から外すときは影響先を表示する。
- 制作に使ったテーマ版と掲載先の公開版を別々に保持する。改版で掲載先や根拠が変わる場合、既存の掲載をプレビューの候補に引き継ぎ、新しい公開版で配置と動画の内容を確認して適用する。旧版で既に掲載している箇所は運営画面から追跡・解除可能。テーマ、画像、対象ノードの公開解除やYouTubeプレイヤーの制限を、古い閲覧URLでも尊重する。
- テーマキュレーション、公開版の読取・可否判定、言語別表示、レコード画像の既存機能を使う。固定版を編集し直す操作や知識投稿のAI審査は挟まない。[公開・作業版の契約](../design/KNOWLEDGE_CHATGPT_THEME_REGISTRATION.md) ／ [言語別表示](THEME_LOCALE_PUBLICATION_20261117.md)

## ④d 通し確認と運用開始

| 段階 | 開発側の確認と完了条件 |
| --- | --- |
| ④a 制作室の土台 | 実データの複製で、複数試行と日英の採用版、保存案、ショートの関係を保ち、一覧・検索・評価・ゴミ箱・復元・完全削除の影響を確認。PCでの表示件数とスマホでの一覧操作も確認。 |
| ④b 投稿 | 模擬APIで日英ルーティング、各種エラー、二重クリック、通信断と再起動、再認証、処理・サムネイルの再試行、公開範囲の反映を確認。日英・横長と縦の投稿候補をミュート・CCオフで試写し、字幕の抜け、読み切れる時間、絵・プレイヤー操作との重なりを確認する。本人がGoogle接続した後、運営者が試験用に認めた短い映像を日英各一回、初回は明示的に非公開で投稿。チャンネルIDと処理済み動画IDを確認する。 |
| ④c 掲載 | β新規生成を待たず、隔離環境の公開テーマへ、試験専用の既存短い映像を日英に割り当てた公開設定のfixtureで先に検証する。実YouTube再生には使用許可のあるテスト動画を使う。④bの試験動画の限定公開への変更確認後、正式とは別のβの公開テーマに紐付ける。正式とβのテーマID・版・公開状態はそれぞれ取得し、正式の案件をそのままβに流用しない。 |
| ④d 配置・受入 | 3200／HTTPS βで、初見の訪問者として日英、片言語、動画と画像の混在、差し替え／解除、ショートの見え方、ノード詳細、狭幅とキーボード、画像の出典、無掲載テーマを確認。画像・映像の読み込みで年表やグラフの操作が悪化しないことも確認。正式配備は共通公開手順に従い、最初の正式掲載と対象動画・チャンネルを確認して運営者の操作で行う。 |

隔離環境では非公開・埋め込み不可・削除・処理未完了・異なるチャンネル・期限切れ・公開版が変わった状態も再現する。試験映像に本公開予定の未使用作品が紛れないようにする。βのテスト掲載は受入後に解除し、試験動画そのものはYouTubeで個別に管理する。サイトの公開は[共通本番公開手順](../runbooks/PRODUCTION_RELEASE.md)に従う。
