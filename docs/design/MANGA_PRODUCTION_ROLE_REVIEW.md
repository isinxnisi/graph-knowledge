## 新Role候補：当該漫画の「原作」担当

仮IDは `ORIGINAL_STORY`、日本語表示案は「原作（漫画制作）」、英語表示案は `Original story credit (manga production)`。**ID・翻訳も未採用**。英語Original authorや原著者への同義置換を避ける。名称を採る前に定義と反例を決める。

定義案：**対象漫画を制作する際の「原作」担当として資料に明示された、人物の制作関与。原作と作画／漫画等の分担を資料で確認し、既存作品の翻案元であるだけの作者クレジットを除く。** 具体的にネーム・文章・構成のどこまでを担当したか、単独の物語作者か、著作権者かは、このRoleだけで認定しない。単に「ストーリー担当」とある資料も自動で原作へ翻訳しない。

端点は制作関与者person→対象漫画work、正規方向subject-to-object。肯定は上記の限定付き制作関与を述べるため、CONTRIBUTED_TOを維持するtyped値の候補とする。否定は当該Role・scope・period込みの命題に掛け、著者・作画・制作関与全体の否定へ波及させない。期間不明はnull、刊行日から補完しない。一Claim一Roleという現行方式を再利用する案であり、兼務は別Claimとして資料ごとに確認する。

### 既存7 Roleとの差

| 既存Role | 原作候補との違い |
| --- | --- |
| AUTHORSHIP | 資料の著／著者というクレジット。原作表記だけから著者を追加せず、同じ人物の別資料に著がある場合も別の支持命題として判断する |
| CREATION | 資料の作というクレジット。「原作」は「作」の文字を含むが、既存CREATIONの同義ではない |
| DRAWING | 絵を描く担当。原作→作画も、作画→原作も含意しない。絵によるネームを作ることから完成漫画の作画を推定しない |
| SCRIPT_WRITING | 脚本の明示。原作やネーム原作を脚本へ置換しない |
| STORY_CO_CREATION | ストーリー共同制作の明示。原作／作画の2名クレジットだけからこのRoleを追加しない |
| SUPERVISION | 監修の明示。原作担当であることから監修・内容承認を認定しない |
| PRODUCING | プロデュースの明示。企画や製作統括を原作担当から推定しない |

全Roleとの比較はdistinctを基本案とするが、これは人間が定義を採用した後にcatalog変更票へ記録する内容。現行IDの意味・baselineを広げて吸収しない。

### Graph・取得・保存への影響

採用後は、既存の「制作」表示束の中で原作と作画／著者を別Claimとして確認できる。池上→トリリオンゲーム→稲垣→Dr.STONE／アイシールド21という経路を増やす候補になるが、役割を採用しただけで未受入関係を表示しない。同じ漫画への関与から人物同士の直接関係を生成しない。

新Role条件はLIMIT前の取得、実効条件キー・cursor・URL保存と探索復帰、比較キー、関連Claim詳細、日英labelまで接続する必要がある。新enumを「全Role」の既存保存条件へ黙って足さない。Roleなし・条件省略・全列挙の違いを維持し、広い旧Claimを原作Roleへ書き換えない。原語はCitation、同じISBNの根拠でも独立資料数の増加とは扱わない。

採用後の作業は、有限catalogの定義・既存7 Role比較・包含／除外／境界例・before/after hash付き変更票、日英label／enum、schema／条件／表示の小さい縦経路、語彙チェック・既存回帰、adapterの明示対応、版と入力hashの再レビュー。旧Web／operatorへ新Role付きKGを先に投入しない。今回この実装には進めていない。

## 「漫画」3件：DRAWINGへの条件と別の著者命題

現行DRAWINGは漫画の画／作画の明示、または本人が当該漫画を描いたと明示する関与。「漫画」というクレジットは、絵・構成等を含む可能性があるため、それ自体をDRAWINGと同義にしない。一方、追加資料が同じ人物・漫画の作画を明示するなら、その狭い作画命題に既存Roleを使える。

## 「監修」2件：既存SUPERVISIONを適用する条件

SUPERVISIONの現行定義は、資料に監修として明示された制作関与。監督・作者・作画・推薦文・権利許諾のみとは区別する。対象が漫画作品かアニメ版か、作品全体か刊行物かを確認し、scope・periodを外挿しない。

**手塚眞→PLUTO**はNDL第1巻に監修表記があり、現行baseに同ISBN・ja・期間不明のSUPERVISION Claimが既にある。新Roleも新Entityも不要。既存Claim `cc2bc0c3-d8e7-47fe-8aaf-1b219bff0137` を再利用する。NDL Sourceも浦沢の著者Claimで既存なので、同Source・同Claimへの新Citationを提案する際は既存Citationと追加の支持範囲を審査する。単なる再取込では増やさない。

**梅澤由香里→ヒカルの碁**は、NDL第1巻の監修表記と[日本棋院の監修者紹介](https://www.nihonkiin.or.jp/event/area/ichigaya/post_1328.html)・[受賞記録](https://archive.nihonkiin.or.jp/kishihp/umezawa/journal.htm)が整合する。日本棋院は吉原由香里について旧姓梅沢と明示する。NDLの梅澤表記も含め、同一人物の正式なアンカー／UUID・表記対応を確認する必要がある。本人はr0002の12名にも企画の53名にも含めていないため、既存catalog外人物を自動追加する例外を作らず、収集範囲の追加判断と次版へ回す。新Roleは不要。

## 「浦沢直樹 [ほか]著」1件

名前が書かれた人物と、[ほか]で省略された人物は分ける。本人名に掛かる著だけを狭く確認できればAUTHORSHIPの人間レビュー対象にできるが、それを作画・脚本・原作・全担当の認定に使わない。誰の担当か曖昧な集約文字列は保留し、著者の完全な列挙・典拠・出版社の明示等で補う。

今回のPLUTOでは、2026-10-14に人間受入済みの同ISBNの浦沢AUTHORSHIP Claim `839b0bb8-1781-4a3e-8446-9a22d08d1658` があり、同じNDL URLと責任表示を根拠にしている。その受入注記は「本人名に掛かる著だけ」「他の人・組織の役割は生成しない」と限定している。新たな受入票・Claim・同じCitationを作る必要はない。

r0002 adapterの集約表記一律保留は取得処理の保守的な制限であり、既存の人間受入を無効にする意味ではない。今後この処理を広げる場合も、集約著者を分解して他人を推定せず、名前に掛かる責任表示と既存受入の照合を明示条件にする。

## 人間レビューで決める順序

1. 現行Roleによる4 Claimと関連レコードの受入可否を先に判断する。
2. 当該漫画の原作担当という定義・反例・日英表示・仮IDを採るか決める。翻案元の原著由来は別の関係モデルへ残す。
3. 漫画3件は資料別のDRAWING／AUTHORSHIP候補として扱う方針、監修は既存再利用と範囲追加の区別、集約著者は明示本人だけを確認する条件を判断する。
4. 採用された意味だけを次の実装・テーマrevisionに固定する。今回のレビュー資料を人間承認票として流用しない。

語彙catalog・baseline・既存Role定義・収集コード・r0002定義／承認・元台帳・公開KGは今回変更していない。
