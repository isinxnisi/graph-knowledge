# 共通ヘッダー・本人ナビ・ページ見出し（2026-10-24）

基準 main 0ed5caf。スマホのカテゴリ＋横レール方式を、サイト移動と本人メニューの二つの責務へ整理する。PCの本文・会話・一覧の再設計はしない。

## 役割

- ヘッダーの固定した並び：ブランド、サイト移動、本人名／アカウント、表示設定。PC／スマホで役割を変えない。探索復帰の有無で右側の操作位置を押さない。
- サイト移動：探索、コミュニティ発見、支援。保存されている元のGraph URLがある場合のみ「元の探索へ戻る」と表示。ホームしかない場合は「探索を始める」。一段のメニューで復帰できる。
- 本人メニュー：表示名全文、参加先、個人Capsule、招待、設定、活動・履歴、ログアウト。ヘッダー上は頭文字＋省略した名前を維持し、対応待ち招待は閉じた状態でも示す。
- PCのサイドメニューは同じ定義・名称・URL・現在地判定を使う。縦長本文でもstickyで追随し、低い画面ではメニュー自体をスクロールできる。
- スマホの本文上のカテゴリ選択・横レールを撤去。本人メニューへ集約して、操作を探すための二重のナビゲーションをなくす。個別コミュニティのタブはその場所の操作として保持する。
- 認証確認中・失敗・ゲストを区別。アカウント入口の寸法を保ち、初回確認中にログイン済み／ゲストのどちらかを断定しない。サーバー認可は従来のまま。

## 見出し

小さな共通部品 PageIdentity で `PLUNODE / COMMUNITY`・`ACCOUNT`・`ACTIVITY` を示す。本文の主タイトルが現在のページ／対象、属性ラベルは機能領域、個別画面の上位リンクは所属先、タブやh2は対象内の切替を示す。すべてのセクションに属性ラベルを繰り返さない。

個別コミュニティは場所の名前、会話はスレッド名を主役にする。Capsuleや会話本文の構成は維持する。

「アカウントと一覧を再確認」は「最新の状態に更新 / Refresh current data」に変更する。実処理はアカウントと保存データの再取得であり、ページ固有の一覧だけの操作ではない。履歴ではなく更新アイコン、透明背景・薄い枠・適切な内側余白のセカンダリ操作とする。入力保持と再試行機能は削除しない。

## 境界

API、schema、権限、保存形式は変更しない。0ed5cafのハッシュ除去通知、認証ストア、入力保全、招待更新、通報、Graph復帰を維持。本番と3275の架空試作は変更しない。
## 戻りと補助操作の仕上げ（2026-10-24）

個別コミュニティでは属性ラベルの COMMUNITY を発見画面へのリンクにする。会話の所属コミュニティ名はその場所へのリンク。別行の「コミュニティ一覧」「スレッド一覧」は重複するため置かない。投稿履歴への文脈付き復帰と、元のGraphへの復帰は別の役割として維持する。

3点操作は20pxの図形と44pxの操作領域を分ける。通常は透明、hover・focus・展開中は反応を示す。参加状態のラベル付きメニューと区別し、ポップアップ内の項目は共通の余白と密度にする。

補助メニューは通常のdetails展開アニメーションから除外し、見えているviewport内へ配置する。開閉だけでなくスクロール・resize・visualViewport変化でも位置を更新する。通報等のnative dialogはbody portalを維持し、可視領域に合わせて中央配置・内部スクロールとする。背景スクロールを抑え、閉鎖時に元の状態とフォーカスへ戻す。入力・認可・冪等処理は変更しない。
