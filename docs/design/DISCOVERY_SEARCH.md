# Discovery Search — テーマと切り口を試す初期版

後続の[Discovery Modelと検索体験の再設計](DISCOVERY_MODEL_REDESIGN.md)では、11世界と現有データの提案を共通文脈で扱う方針、操作別能力・収録状況・次のUI比較を整理した。設計案であり、以下の現行API・3テーマ・画面を置き換えたものではない。

2026-10-16。[Issue #4](https://github.com/isinxnisi/graph-knowledge/issues/4)の実装単位。[M3構想](M3_DISCOVERY_EXPERIENCE_CONTEXT.md)と[探索プリセットのレビュー](EXPLORATION_PRESETS_REVIEW.md)を参照する。今回の体験を評価するための実装であり、分類体系・多段プリセットの最終仕様ではない。

## 体験と読み順

「入力して送信するフォーム」から、**気になる世界→つながりの切り口→実在する対象→Graph**へ重心を移す。

1. Home／検索ペインの既存入口から、入力なしの一回で開く。最初のフォーカスは見出しへ移し、名前欄を自動的な主役にしない。
2. 漫画とつくり手、科学と研究、出来事と参加者の3入口。選び直し・同じテーマの再タップで解除できる。公開KGで起点を確認できないテーマは表示しない。
3. そのテーマの公開データに存在する関係から、作品づくり・影響・組織・出来事への参加などを提示する。複数選択はOR。選択中の切り口はゼロ件になっても残し、解除できる。テーマを変えても切り口・名前・種別は維持し、周辺起点だけを解除する。
4. 現在の選択を小さな解除可能なチップで示す。全体の選び直しも一回でできる。種別・直接の周辺起点は補助的な開閉領域に置く。
5. **選択領域の後、結果一覧のすぐ上**に任意の名前・別名欄。入力するたびに結果を更新し、送信ボタンへの依存を減らす。この位置は今回の実験案。
6. 結果は20件単位のコンパクトな行。PCは2列、スマホは1列。名前・種別・短い説明・別名を優先する。実件数を示し、名前の完全一致→名前・UUIDの安定順で表示する。人気や信頼度の順位とはしない。原文を推測で翻訳しない。
7. 選んだ対象からGraphへ。明示的に選んだ関係の切り口を既存Graph条件へ引き継ぐ。役割・立場・参加役割は指定なし。切り口を一度も選ばなければ、従来どおり既存Graph条件を維持する。テーマ・種別・周辺起点は候補集合の条件であり、Graphの新たな関係条件にはしない。

## デザインと動き

ライト・エディトリアルの明朝見出しと淡い背景を継承。テーマは軽いネットワーク図と小見出し、切り口は小さな丸い選択肢、結果は罫線付きの行として視覚的な強さを分ける。巨大な結果カードやダミー画像を追加しない。切り口の数値は前面に出さず、補助説明で「関係の記録数」として扱う。資料の数や独立根拠の数と混同しない。

- テーマ選択：背景・輪郭を180msで変え、小さな図の輪を300msで反応させる。押下中だけ軽く縮む。
- 関係の切り口：選択／解除の背景変化と＋から×への180ms回転。テーマで選択肢が変わる箇所だけ200msのフェードと4pxの浮上。
- 選択チップ：170msの小さな出現。結果：200msのフェードと5pxの浮上。画面全体を毎回動かさない。
- 通信中：前の結果を薄く残し、短い進捗線と更新文を表示。古い行は`inert`・`aria-hidden`で操作対象から外す。遅い応答はキャンセルし、演出完了を操作の条件にしない。
- ダイアログの外寸はviewportに合わせて一定。固定ヘッダと一つの本文スクロールで、ロードごとの高さ変化を防ぐ。スマホのテーマ／切り口は横一列、結果の縦幅を確保する。キーボード・タッチ・Escape・背景・Backの既存操作を維持。
- `prefers-reduced-motion`では上記の演出と進捗線の動きを停止し、状態と更新文は残す。

## 実データの範囲

[収集テーマ管理](COLLECTION_THEMES.md)は別の運営経路。以下の三入口は現在の公開起点の周辺検索であり、収集テーマや知識世界の正式分類ではない。収集計画や承認状態を検索タグ・収録済み・収集予定として自動表示しない。将来の接続は、探索意図と必要なデータ、公開revisionで観測した収録状況、実装済み検索能力を確認して判断する。

テーマは分類属性ではなく、実在の編集的な起点から**published Claimを最大2段階**辿ったEntity集合。

| テーマ | 起点 |
| --- | --- |
| 漫画とつくり手 | PLUTO・浦沢直樹・長崎尚志 |
| 科学と研究 | ニールス・ボーア研究所・Dirac・Heisenberg |
| 出来事と参加者 | 1927年ソルヴェイ会議・Lorentz |

種別・名前・直接の周辺起点・選んだ関係のORをこの集合とANDで組み合わせる。切り口は対象に接続する公開Claimの述語で判定し、Roleを作者・原作などへ読み替えない。集合に入ることは漫画家／科学者への分類や、起点との直接の関係成立を意味しない。否定を含む記録も検索対象。新しいClaimや架空の関係を生成しない。

関係の選択肢はテーマ／周辺起点の範囲から取得する。名前・種別・現在の切り口で選択肢まで消さず、別の興味へ移れる状態を保つ。公開Capsuleや会員PGは検索しない。

## APIと状態

既存キーワード必須 `/api/entities` とインライン候補（250ms、最大5件、IME中抑制）は維持する。read-only `/api/discovery/entities` は任意の`q`、`kind`、`around`、`theme`、`predicates`、`after`のみ受理。未知・重複・過大な条件を拒否し、Cypherはパラメータ化する。テーマと直接の周辺の対象集合は、それぞれ起点から一度取得し、両方があれば集合を交差させて検索・件数・選択肢へ使い回す。各Entityから2段の経路を再探索する方式は実データでタイムアウトしたため採用しない。

結果は公開Claimに接続するEntityのみ、21件取得で次ページを判定する。cursor v2は検索語・種別・周辺起点・テーマ・正規化した関係・dataset・revision・最後の順位／名前／UUIDに束縛する。条件不一致は400、KG更新は409として再試行へ。v1は追加条件なしの従来検索に限り継続使用できる。cursorをGraph URLへ流用しない。

250ms debounce・AbortController・直近24条件／30秒のメモリキャッシュを使う。通信失敗は成功やゼロ件と扱わず再試行を提供する。検索語・cursor・テーマの内容をGA4へ追加送信しない。

開閉にはnative Historyの一時stateを一件使用。閉じる／Escape／Backは直前のGraphを維持し、Forwardで選択条件ごと再表示する。選択後は検索の履歴一件を消費してからGraphへ進む。開く前に探索URLを確定し、確定不能なら既存警告を維持。既存URL codec・保存形式・認証・所有権・広告境界は変更しない。

## 今回確定しないこと

- 実Entityの分類属性・複数タグ・分類体系。今回の3入口をその代わりにしない。
- 方向・複数段・役割を組み合わせた探索プリセット。今回の述語フィルタ引継ぎとは別。
- アニメ化・掲載媒体を扱う関係モデルとデータ追加。
- 公開Capsuleの発見・Graph個別関係の閉鎖。

原資料・英語別名の不足は維持し、翻訳や情報を捏造しない。M3全体の完成と本人の最終評価は、今回の実装・自動検証と別に残す。検証と反映結果は[公開β進捗](../PUBLIC_BETA_PROGRESS.md)を参照。
