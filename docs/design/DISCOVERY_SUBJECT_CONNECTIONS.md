# Discovery：対象位置・名前照合・接点からの対象変更

2026-10-19。運営者が[対象位置レビュー](DISCOVERY_SUBJECT_POSITION_REVIEW.md)の基本案と以下の具体的操作を採用。実装・検証結果は末尾へ記録する。①プリセット→②対象検索（省略可）→選択対象→Graph、③共通関係条件という構造を維持する。

## 採用契約

- `other-works` rev1の作品起点と旧GET／POSTは維持。rev2で、作品位置と中央の制作担当者位置を追加する。同じ形W-P-W、相異なる3 Entity、人物→作品の両Claim、全段affirmed、各ClaimへのRole限定は共通。期間・scopeを跨ぐ意味を推論しない。
- 対象POST v2はqと`nameTarget: subject | contributor`を受ける。入力欄は一つ、バッジで照合先を選ぶ。contributorはrev2の作品検索時だけに対応。kindと経路の位置は別概念で、現在はwork／personをそれぞれ端点／中央に対応させる。未知の組合せは解除せずエラーにする。自動語分割・役割推定はしない。
- qと照合先は②の検索条件。Graphでは③を維持し、ほかの成立経路も辿れる。初回はqに一致した完全証拠を必ず引き継ぎ、別人物の証拠へ代用しない。
- 証拠v2は`subjectId`／`subjectPosition`と`matchContext`を持つ。Claim順とW-P-Wの線形順は維持し、中央人物を先頭へ回転しない。作品検索はその作品を先頭とし、人物検索は作品ID順で代表2作品を選ぶ。左右対称な全証拠を一律に並べ直す案は採らず、旧証拠と取得元の安定性を優先する。
- EXISTSと証拠の選択は同じ条件を使い、Entity LIMIT前に完全判定する。関係先名は同じ証拠の中央人物へ適用する。Graph遷移時の名前照合はサーバーで再検証する。公開revision、条件、照合先はcursor／cacheのキーに含める。
- Graph paths POST v2は中央人物rootに対応。人物の追加取得は作品対の全組合せを返さず、ID最小の適合作品と各別作品を結ぶ完全証拠で接点を覆う。候補は有界の証拠であり全経路数ではない。旧v1のページ・cursorとrev1の意味は変更しない。
- Graphは通常のEntity単位の展開・閉鎖・再開・配置・Undoを維持。sourceの証拠内位置を検証し、人物rootを別作品へ置換しない。自由探索への切替は同じroot・制作Role・affirmedを維持する。
- rev2のWorkspace item／URLはv3。旧item v1／v2・URL v1／v2は元の意味で読む。版付き共通条件の形が同じ保存Viewとコレクションは、pattern参照revisionで区別する。未知の版は拒否し、読込みだけでは保存を上書きしない。

## 選択対象：B方式

既存GET pathsで、選択対象から2／3段の公開Claim記録を有界に辿る。**到達経路の形は③と独立**。到達先Entityを最大24件の読み取り専用POST `subject-matches`で一括判定し、候補自身に③が成立する完全証拠を別に確保する。候補数・経路数・Claim数は混同しない。

正式公開前レビューで、候補だけの表示フィルター方式（旧A）を廃止。**「選んだ関係条件／すべての関係」は、この対象からの探索とGraphの実際の③を一緒に切り替える（新B）**。「すべて」はpatternだけでなくRole・肯否を含む追加条件を明示的に解除し、既存の全関係・all-recordsの自由探索へ渡す。patternからの通常の自由探索ボタン（Role・affirmedを維持するGraph内操作）とは目的・操作を区別する。

②の検索snapshot（名前・照合先・kind・関係条件・cache・位置）は戻るために保全する。「選択した対象」で明示変更した③は選択状態に保持し、候補の適合検索とGraph handoffは常にこの同じ値を使う。②へ戻れば検索時の条件へ復帰し、Graphでの編集も②を書き換えない。元の条件へ戻す操作は現在対象の完全証拠を再取得してから原子的に適用する。不適合・timeout・版変更なら切替前の探索を保持し理由を表示する。対象を自動変更しない。

表示候補は現在の③で確認済みの対象だけ。候補からGraphへ直接進めるほか、「この対象から探す」で次の接点探索へ継続できる。到達経路の証拠を候補自身の適合証拠へ代用しない。対象変更は直近10選択を戻れるよう保持する。

到達経路と候補の適合証拠は別表示。到達記録には従来の否定Claimも含み、肯定された事実の連鎖と誤表示しない。取得範囲に候補がなければ「この範囲に表示できる候補なし」。全KGの不在とは断定しない。timeout、Abort、revision変更時は正常0件を返さない。

経路・根拠は必要時に開き、候補取得結果をスクロールごとに親state／履歴へ保存しない。既存scroll ref／停止checkpoint／履歴の頻度制限を維持する。
