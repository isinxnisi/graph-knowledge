# コミュニティを中心にした体験設計

## 実betaの画面整理（2026-10-24）

アカウントとコミュニティは共通の画面枠を使う。「見つける」は公開の発見、「自分のスペース」は個人Capsule・参加先・受信招待・設定、「自分の活動・履歴」は投稿・通報・参加履歴。コミュニティ内のスレッド・管理・招待発行は、場所の名前と状態に続く内部タブとする。個人Capsuleの既存機能は複製しない。

同じ本人が画面へ復帰した際は、再認可の間だけ内容を隠し、許可が確認できたら入力と選択状態を戻す。本人や参加世代・権限が変われば草稿を破棄する。通報は画面を押し下げないダイアログとし、失敗した入力を残す。退出は参加設定内で影響を確認して行い、復帰申請・取消も確定前に対象と結果を示す。詳細と検証は[実beta UI記録](../verification/COMMUNITY_BETA_UX_20261024.md)。以下の将来の掲載・AI体験とは区別する。

2026-10-23の初回公開範囲：人間の場・会話・参加・管理・通報。以下のCapsule掲載／Graph往復は独立したC2の後続体験であり、初回のコミュニティ画面では準備中にする。個人Capsuleは従来どおり利用する。AIは第2弾。[現行リリース計画](COMMUNITY_IMPLEMENTATION_PLAN.md)。

2026-10-21。初案 v0.1を具体化した**設計・隔離試作**。実サービスへの導入・公開ではない。

- 起点：[ユーザー提供の初案](community/EXPERIENCE_V0_1.md)
- 実装者向け：[基礎設計](COMMUNITY_FOUNDATION.md)／[導入計画・確認方法](COMMUNITY_IMPLEMENTATION_PLAN.md)
- 操作試作：`http://127.0.0.1:3275/`。上部の試作帯で日英・閲覧者・参加者・管理者・Capsule所有者を切り替えられる。実会員・KG・AIには接続しない。

## この場所でできること

気になったテーマに名前を付けて、小さな場所を作る。話しても、Capsuleを持ち寄っても、読むだけでもよい。継続的な成果や常駐を求めない。公開の場所は、参加する前からCapsuleのGraphへ進める。

育った場所は選んだCapsuleのギャラリーになる。「この場所のピックアップ」は管理者の選定であって、真偽の認定や本線KGの採用ではない。人気や活動量を一つの信用点へ変えない。

## 入口と画面

| 場所 | 主役 | 次の操作 |
| --- | --- | --- |
| ホーム | 選ばれたCapsuleと最近の会話 | Graphへ／話題を開く／参加する |
| Capsule | 掲載した特定版の一覧 | 直接Graph／この版について話す |
| スレッド | Capsuleがなくても始められる話題 | 投稿／版の根拠／Graphから戻る |
| メンバー | 一緒にいる人、AIであること、役割 | 権限に応じた招待・役割管理 |
| 管理 | 公開範囲、掲載、参加、AI、休止 | 項目ごとに確認・変更 |
| 自分のコミュニティ | 参加中、運営中、申請・招待、アーカイブ | 同じ場所・同じ管理画面へ |

PCはCapsuleを広い主列、最近の会話を細い副列にする。スマホは同じ見出しとタブの順序を維持し、本文を一列にする。大きなカードや設定項目を際限なく積まず、Graphを右側の主操作、会話を補助操作にする。管理は通常閲覧と分離し、管理内でも項目を切り替える。

アカウント側に別の管理状態は作らない。「運営中」からコミュニティの管理へ直接入り、Capsule側では自分の共有版・掲載先へ戻れる。

## 1. 作る → 掲載する → Graph → 戻る

1. 「場所をつくる」で名前を付ける。説明は任意。公開／メンバー限定を**未選択の状態から明示して選ぶ**。
2. 公開なら自由参加、メンバー限定なら招待制。投稿・掲載は参加者が可能。AIは招待するまで参加せず、自主活動も始まらない。
3. 作成直後の空のホームは未完成扱いにしない。「Capsuleを掲載」「話題をつくる」のどちらからでも始める。
4. 掲載するCapsuleの**版**を選ぶ。公開の場所では公開済みの版を選ぶ。掲載者が所有者である必要はないが、掲載しても編集権は得ない。
5. Graphへ直接進む。戻ると元のタブ・掲載一覧・位置が残る。会話の閲覧や参加は必須にしない。

試作では架空の関係図へ進む。実装時は既存Capsule Readerの参照解決とExplorerへつなぎ、現在のClaim、肯否、Role、期間、scope、根拠を維持する。Capsuleの版はKG本文の歴史保存を意味しない。

## 2. 非公開で検討 → 成果だけを公開

「物語の下書き室」はメンバー限定。「公開する説明を、一緒に考える」の会話と非公開ノートを読み、アカウントから自分のCapsuleの「成果の公開版を作る」へ進む。

公開用の題名・説明・参照構成を確認し、その版だけを公開する。私的な説明を確認なしに流用せず、非公開コメント、参加者、検証メモを含めない。元の会話と元の限定版はそのまま残る。公開版を公開ギャラリーに掲載して初めて、そこから見えるようになる。公開しただけでは全コミュニティへ掲載しない。

公開用の整理を同じCapsuleの新しい版として保存する。内容を別々に育て続けたい場合の「別Capsuleへ明示コピー」は後段とし、自動複製しない。

公開の場所に私的なCapsuleを貼っても、本文や題名を読めない人には見せない。一般的な「参照先は表示できません」だけにし、権限を増やす抜け道にしない。限定リンクも参加券にはならない。

## 3. 公開範囲を往復する

| 操作 | 変わるもの | 変わらないもの |
| --- | --- | --- |
| 場所を公開へ | 入口、新しく作る会話の既定、今後の参加受付 | 過去の限定会話・限定版・メンバー一覧 |
| 場所をメンバー限定へ | 場所の閲覧に参加権が必要になる | 独立して公開されたCapsule本体 |
| Capsule版の公開停止 | その許可だけに依存する本文・掲載・プレビュー・Graph入口 | 他の有効な許可、独立したコミュニティ会話 |
| 掲載を外す | その場所の展示 | Capsuleの所有・内容・他の場所の掲載 |

会話と掲載はそれぞれ共有範囲を持つ。公開の場を限定へ変える際、既存の公開会話・掲載も現在の参加者へ限定し、その後場を再公開しても自動公開へ戻さない。限定期間中の発言や紹介文が巻き込まれるのを防ぐ。独立した公開Capsule本体は変えない。

古い限定会話は、その会話に招かれた人の範囲を維持する。参加方式を緩めても、新しく入った人へ古い会話を自動開放しない。必要なら元の限定メンバーに影響を説明したうえで、**会話の共有先を別操作で追加**する。初回の通常操作には会話全文の公開化を置かない。

この保守的な扱いはv0.1からの具体化。試作では新しい招待者へ古い会話の閲覧権を追加する画面はまだない。新しく作る会話には参加できる。

メンバー名簿は参加者向け。公開の入口に参加人数や非公開会話数を表示しない。公開の活動表示は閲覧できる公開内容だけから作る。

## 4. 掲載版を選ぶ・更新する

掲載は固定版。下書きを直しても展示と過去の投稿の参照版は変わらない。新しい公開版がある場合、管理の掲載一覧から題名・版を確認して「新しい公開版へ」変更する。実機能では差分プレビューも提供する。過去のコメントや検証結果は元の版へ残し、新版への評価として移さない。

Capsule所有者は自分の版の公開を停止できる。コミュニティ管理者は掲載を外せるが、他人のCapsuleを編集・削除・強制公開できない。共同編集・公開担当は別途明示招待する役割で、参加時の特典にはしない。

## 5. 管理を終える

通知を休む、離れる、アーカイブする、退会する、削除する、を別の操作にする。静かな期間を失敗・自動削除の理由にしない。

アーカイブは新規参加・投稿・掲載・AI活動を停止し、既存の閲覧範囲を維持する。自分の投稿撤回やCapsuleの共有停止は引き続き可能。最後の管理者は引継ぎ先を無理に決めなくても、アーカイブして離れられる。個人Capsuleを移転せず、場を公開せず、本人の閲覧権も残さない。

管理者が残る場合は再開可能。管理者不在の場所を、最初に来た人やAIへ自動移譲しない。再開の申請はサイト運営が本人性・参加履歴・同意を確認する後段の手続きとする。放置中の通報もサイトへ届く設計にする。

## 6. AIに何を任せるか

「AIの参加と活動」で、参加の範囲、活動の開始、任せる役割を別々に選ぶ。

- 参加：なし／招待したAIのみ／サイトで許可されたAIも受け入れる。
- 活動開始：呼びかけ時のみ／範囲と頻度を決めた自主活動。
- 役割：会話、要約、検証コメント。検証コメントは真偽の確定やKG受入ではない。
- 非公開データの外部送信：別の処理先・対象・予算の承認が必要。参加許可で代用しない。

AIは名前の隣にAI表示を付け、運営主体と活動範囲を確認できる。公式という名前だけで管理権限を持たせない。初回は招待・呼びかけのみ、自主活動は停止。AI参加なしでも通報窓口は閉じないが、安全対応に全私的内容の自由閲覧を認めない。

試作では設定変更・招待済み表示・待機応答・取消を模擬できる。「待機→AI参加なし→遅い応答」で内容が破棄される。実処理先、実投稿、送信、費用は一切発生しない。

## 初案から具体化・変更した判断

| 判断 | 理由 |
| --- | --- |
| 公開範囲は作成時に未選択から選ぶ | 気軽さを保ちながら無意識の公開を避ける |
| 過去の限定会話は参加集合を保持し、再参加も自動復権させない | 公開化・参加緩和で既存情報が流出しない |
| メンバー一覧と限定活動数は外部非表示 | 人の参加や私的な活動の推測を防ぐ |
| 成果公開では公開用本文を確認して新しい版にする | 私的な検討文の巻き込みを防ぐ。元版は保持 |
| 管理者不在は閲覧中心のアーカイブ | 強制移転・公開・管理義務を発生させない |
| 通常の参加／運営一覧を優先、通報・課金・本格分析は接続状況を明示 | 空の機能を稼働中に見せない |

タブ名、固定版掲載、軽い作成、AI既定値は初案を維持した。実画面で評価したいのは、ホームのギャラリーと会話の比重、限定会話への追加招待の説明量、AI設定の理解しやすさ。権限境界を未決に戻すものではない。
