# 原文と別に訳文を保存・訂正する

2026-11-05。原語保存に続く第二段階。手動の訳文投稿と訳文訂正を、既存の本人認証・草稿・受付・確認・結果通知へ接続する。AIによる訳文生成、全量翻訳、訳名検索、UI言語によるGraphラベルの自動切替は後続。

## 保存と訂正の単位

原文は変更しない。`kind / id / 原文内容版 / field / evidenceIdまたはaliasIndex / 訳先言語`で訳文を識別し、独立した追記版を持つ。任意のJSONパスは許可せず、Entityの名前・説明・別名、Recordの本文・矢印・範囲・引用・記載箇所、Sourceの原題・書誌、Themeの名前・説明だけを対象とする。4000文字以内の短い表示文が対象。原文hash・原文そのもの・理由・処理actorを記録する。人の帰属は既存の非公開会員決定と公開投稿者表を通し、公開本文に会員IDを埋めない。

追加migrationはknowledge側 `005-text-translations.sql`。既存001/002/004やmemberの適用済みmigrationは変更しない。原文のRecordや意味対応・時期・Themeの版を増やさず、同じ訳文の再送では訳文版も活動も増やさない。原文が更新された場合、古い訳文を新原文へ付け替えない。新たな投稿は最新の公開原文に対して行う。過去の公開原文の訳文履歴は、その原文と依存資料が現在も公開されている場合だけ読める。

## 投稿と確認

公開詳細の折り畳み「翻訳」で項目・訳先言語を選び、原文をサーバーで固定した私有草稿を作る。訳文専用のフォームと操作 `translate-text` を使う。一回一件で、事実訂正と混在させない。日本語／EnglishをUIの初期選択肢とするが、schemaはBCP 47を保持する。原文の指定と同じ言語への投稿は拒否する。

既存の確認キュー・同意先表示・利用枠・予約・実使用量・再試行を使う。翻訳確認は `translation-equivalence-v1`。Geminiへの型付き入力で原文と訳文を比較し、否定・数字・日時・方向・役割・限定・不確実さの意味一致を確認する。原文が事実として正しいかの再認証とは分ける。元資料を翻訳の新しい根拠として複製せず、HTTP資料取得を不要にする。原文の現在の公開範囲・版・hashと訳文の更新競合はDB側で再確認する。訳文自体の生成は行わない。

投稿結果から訳文の公開先へ開ける。プロフィール公開／匿名は通常投稿と同じ。匿名でも内部の投稿者はログイン会員に結び付く。公開活動には非匿名の訳文投稿・訂正を出し、その投稿時の訳文版へリンクする。停止・復帰は運営相談の既存経路と独立したstatus CASを使う。原文または訳文の公開停止中は、過去版・活動・Capsuleを含む通常の読取ガードを通過しない。

## Capsule

閲覧者が「この訳文をCapsule用に保持」を押した訳文の版と本文だけを、作成時のsnapshotへ固定する。元の知識・根拠やGraphのラベルは翻訳で置換しない。保存後は折り畳み「保存した訳文」で原文と対応して読める。サーバーは訳文版の内容がcanonicalであることと、原文がsnapshotに存在することを検証する。偽の訳者・本文を持ち込まない。

明示的な取得元更新で原文の内容版が変わる場合、旧版にしか対応しない訳文を新内容へ移さない。共有への反映も通常どおり所有者の明示操作。今回のCapsule固定対象はsnapshot内のEntity・Record・Source。Theme名・説明の訳は公開詳細では使えるが、Theme全体の内容をsnapshotへ保存する仕様の拡張は未実装。Graphラベルを訳名で表示する選択や、訳文同士の差分比較、取得元更新時の訳文選択も後続。

## 残る範囲

第三段階は、明示依頼での自動翻訳・原文版/hash/項目/言語をキーにした再利用・翻訳専用のusage管理・実精度評価。原文との意味一致を確認する今回のAI利用を、自動翻訳生成が完成した意味にはしない。U6の同一性・取込の残件と、本番公開U8も別に管理する。

今回の入口は共通原記録のある知識・対象・Themeの公開詳細。旧KG専用の詳細画面への翻訳UI全面展開は未対応であり、共通原記録への接続と合わせた後続範囲とする。
