# 明示依頼による翻訳草稿の生成

2026-11-05。独立した訳文版を基礎に、自動生成→編集可能な草稿→既存の意味一致確認・公開をつなぐ。自動生成だけでは公開せず、原文・公開訳文・保存済みCapsuleを上書きしない。

原文の公開版・hash・項目・訳先言語・文脈hash・生成policyを再利用キーにする。同一キーの依頼は永続キューを共用し、成功済みなら再推論しない。本人の依頼・取消は別に保持し、他人の依頼情報は返さない。原文が更新／非公開になった場合、生成結果を新原文へ転用しない。

既存Gemini無料projectの回数・token予約へ翻訳用途を追加する。投稿確認用の枠を残すため翻訳生成は日／月の1/6以下。収集・投稿・評価と合算したproject上限も維持する。送信不明・使用量欠測は予約を保持し、再試行は二分以上あけ最大三回。永続応答から再開できる場合は再推論せず確定処理だけを再実行する。別key・有料fallbackは行わない。

画面は既存「翻訳」欄内の任意操作にする。初回の外部送信先・条件を短く確認し、依頼後は待ち理由・手動再取得・取消を表示する。常時ポーリングは行わない。生成済み訳文から本人の草稿へ移し、編集・既存の訳文確認・公開・投稿者表示を利用する。生成失敗時は手入力へ進める。

今回の単位は自動生成と再利用・用途別利用量。訳名検索、Graphラベルの自動切替、全量翻訳、本番VPSは別工程。


## R1g：公開文脈と再利用（2026-11-06）

短い名前・関係名の意味が曖昧にならないよう、選択した原文だけでなく、対象の名前・分類・別名・説明、関係の主語／相手・具体語・肯否・限定、資料名を添える。引用／箇所の翻訳には、選んだ根拠の資料と元の関係も添える。訳すのは選択した一項目だけで、文脈を追記したり原文を事実訂正したりしない。

- RecordのEntity／Sourceは固定版readerと共用し、当時の公開版を使う。Entityの現在の名称訂正だけでは、旧Recordの文脈とcacheを差し替えない。aboutRecordも固定参照をたどる。
- aboutThemeは既存仕様がID参照なので、その時点で公開中のTheme版と見出しを文脈へ固定する。そのThemeが更新された場合は同じRecordでも生成依頼を分ける。保存済み訳文／Capsuleは変えない。
- 同じ知識DBのrepeatable-readで原文と文脈を取得する。私有Capsule、会員情報、未公開版、無関係な項目、資料URL先の本文は送らない。
- 補助説明はEntity800字、Theme1200字、資料書誌800字、別名8件、資料4件まで。省略を明示し、選択原文・関係の肯否／限定は切らない。全体24,000字を超える場合は生成を断り、手入力を案内する。
- 文脈は未信頼データとしてpromptから分離する。文脈の命令に従わず、名前・否定・役割・時期・不確実さを保持する。外部送信の案内と確認IDも更新する。
- member031で文脈JSON／hashを追加保存。policyはtranslation-context-v2。旧v1の原文／生成結果／利用量は消さず、新方式へ転用しない。旧待機依頼は送信せず終了する。
- 受付・送信直前・結果確定・草稿読取時に公開条件と文脈を再確認する。非公開化した原文／根拠のcacheは返さない。通信障害は取消に置換しない。
- 同一文脈の生成成功はアカウントをまたいで再利用し、本人の依頼・取消は従来どおり別管理する。生成結果は未公開の草稿であり、公開訳文の確認・投稿者表示・版は従来経路を通す。
