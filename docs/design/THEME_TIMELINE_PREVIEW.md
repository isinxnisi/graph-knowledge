# Issue #75：関係図と同じ作業面で読む年表の試作

2026-11-01。ユーザーの未完成のスケッチ、Gitグラフからの着想、「期間と同じ対象の流れを区別して試作」の回答を起点にする。視覚・操作を評価する段階であり、年表全体の仕様確定ではない。独立worktree／3276に限定し、main・β・本番へ統合しない。

## 今回の形

- 同じページに「関係図」「年表」「並べて読む」「記録と根拠」を置く。別画面への遷移を必須にしない。
- 年表は日付、細い線の帯、具体的な記録の行。行を開くと範囲・根拠・訂正・関係図への操作が現れる。詳細欄で画面を常時占有しない。
- 読んでいる記録とCapsuleに入れるチェックは別。表示を切り替えても選択を保持する。
- 並列表示では、年表で読んでいる記録を関係図でも選択する。図で選んだ関係・エピソードからも年表の対象が分かる。Entityクリックから曖昧な記録を推定しない。
- 関係図は切替時にアンマウントせず、移動・倍率を保つ。狭い画面では縦配置と小さい図を使う。
- 年表の子軸は、明示した親記録の行の中で開く。別の日付・時刻体系へ暗黙変換しない。

年だけの値は年だけで表示する。暦日順の一覧で年単位と日単位の範囲が重なる場合、厳密な前後を意味しない。周期は周期長・単位・折返しを明示し、定性軸は指定された順序だけを使う。順序がなければ入力順として示す。

## 時間範囲と意味上の関係を分ける

2026-11-01追補。ユーザーの「青の時代の期間内で起きたことがすべて青の時代に属するわけではない」「起きた時期が曖昧なことも範囲で表したい」という指摘を、保存構造と入力・表示に反映する。

- 暦日の `meaning` は `point`（時点）、`duration`（続いた期間）、`occurrence-window`（この範囲のどこかで起きた）を区別する。
- `duration` の `from` は開始の最早、`to` は終了の最遅。任意の `startLatest` は開始の最遅、`endEarliest` は終了の最早。未指定の境界は元の年・月・日精度の値をそのまま使う。
- 開始の候補幅と終了の候補幅は重なってよい。その場合、すべての候補に共通する継続区間があるとは表示しない。実際の終了が開始より前になる組合せを主張するものではない。
- `occurrence-window` は `from` と `to` の間のどこかという範囲。期間用の境界属性は受け付けない。`point` には `to` を指定しない。年・年月の精度と、この意味の違いは別に保持する。
- 既存の `meaning` がない from/to は値を変えず「時期の範囲・未区別」として表示する。fromだけの旧時点も保存値へ新属性を勝手に加えない。
- `polarity: uncertain` は主張自体の不確かさ。時期の候補幅とは別で、時期が曖昧でも出来事の存在を肯定できる。
- 画面の「範囲・時期を補足」で意味を選び、必要な日付と、期間の場合だけ境界の幅を入力する。意味を切り替えても入力中の日付を保持する。原資料の「後半」「年初」などはラベルへ残し、勝手に月日へ換算しない。
- 同じ暦軸の期間・発生幅・出来事を、主年表の共通座標上に描く。時間の重なり・同じ対象・表示上の入れ子から、所属・因果・関係を生成しない。前段の横向き比較欄は主年表の描画へ置き換えた。
- 青の時代と作品の関係は、所蔵館が明示した分類を通常の関係記録として別に登録する。同時期の別作者の作品は同じ年表へ置けるが、それだけで分類を作らない。

時期の意味・境界・原表現は検索、Graphの補足、訂正差分、Capsuleの保存した断面、明示的な共有版にも保持する。日付の訂正と同じ内容訂正として扱い、共有URLの版が自動的に置き換わることはない。

実資料のサンプルは[青の時代の出典・入力判断](../research/issue75-themes/PICASSO_TIMELINE_EVIDENCE.md)を参照。期間境界の不確かさを資料にない数値で捏造せず、別テーマの架空操作例で交差する境界幅まで試せるようにする。

## 保存構造

原記録の `time` を継続して使い、座標を年表設定へ複製しない。Package／Theme／Capsule snapshotに任意の `timeline` を追加する。

```ts
type ThemeTimelineConfig = {
  version: 1;
  axes: { id: string; kind: 'calendar' | 'cycle' | 'qualitative';
          label: string; order?: string[]; originLabel?: string }[];
  placements: { recordId: string; axisId: string }[];
  insets: { parentRecordId: string; axisId: string; label: string }[];
};
```

軸IDと表示名を分ける。日時の精度、元表現、根拠、内容版、意味版は元記録の責務。行の開閉・色・表示対象の絞り込み・図の倍率は閲覧状態であり、意味の承認ではない。

構成指定のない既存テーマも投影できる。暦日と、それぞれの周期／定性軸と、時期を定めない情報へ分ける。異なる座標定義を同じ名前だけで一つにしない。

参照・一意性・型一致・周期単位と長さ・定性座標と順序・循環する入れ子を検証する。入れ子は試作上3段まで。配置済みの記録を軸と合わない時間型へ通常訂正した場合は保存を拒否し入力を残す。訂正時に「年表の配置を外す」を明示した場合は、その記録の配置だけを外して保存できる。時期未確定への訂正を妨げず、親記録としての子年表との対応や他記録の配置は保持する。使われなくなった空の軸は除く。軸の追加・移動・順序変更は現在パッケージ入力で行い、構成全体の編集器は未実装。

## Capsuleと訂正

保存時には選択した記録、参照する対象、必要な軸だけを固定する。親だけを選んでも子記録を自動追加しない。子だけを選んだ場合はその軸を独立表示し、日付・timezoneなどの `originLabel` を残す。共有／再訪から現在テーマの未保存の子記録を取りに行かない。

元記録の訂正は差分確認・明示取込を経てsnapshotへ反映する。配置を外した記録を選んで訂正を取り込むと、その保存済み配置の解除も取り込む。別記録だけを取り込んだ場合は、未選択の記録とその配置を保存時のまま保つ。現在テーマの軸構成全体を無条件に取り込まない。通常保存・元記録の訂正・訂正の取込だけで共有版を更新せず、共有への明示反映で同じURLを更新する。Capsule上の独自Graph編集は保存した原記録の年表を暗黙に書き換えないことを画面に示す。

## 主年表の期間描画

`calendarGraph` が元の日付と精度から表示専用の座標を作る。開始・終了・曖昧な境界の候補端・出来事を共通の日付順へ置き、同じ候補範囲で重なる線には別レーンを割り当てる。時期が重複する線を一本へ統合せず、親子関係も生成しない。

描画はCSS Gridの共通行を使う。期間線と確かな中央部分・候補端の各区間が同じ行をまたぐため、途中の記録や根拠・子軸を開くと線も伸びる。元の時間値は変わらない。期間は両端を持つ線、発生時期の幅は丸い端を持つ破線として区別する。表示単位内に収まる時点・発生候補幅は点にまとめ、実期間は短い両端付きの線として残す。開始候補と終了候補が重なれば、確かな中央部分を描かない。

期間線または終端のラベルを選ぶと、その元記録を開き、画面内へ案内する。Capsuleへ入れるチェックは独立したまま。「たどる対象」はその対象の線を強調し、他の線を薄くする。多数の同時期の線は隠さず横スクロールで読む。スマホではレーン間隔を詰め、通常件数ではページ全体が横にはみ出さない。

年・月だけの値は内部の可能範囲で配置するが、補った月日を表示・保存しない。同じ時期の複数記録の行順は前後関係ではない。終端側にも元表現を付ける。閉じた行では時期の短い説明、開いた行では候補端と根拠を確認できる。

Theme／Capsule／ローカル共有版は同じ描画を使用し、渡された断面の記録だけを読む。[期間グラフの実画面検証](../verification/THEME_PERIOD_GRAPH_20261101.md)を参照。

- 今回は1記録1時期・1軸。複数の時期注釈を持つ記録は、将来 `occurrenceId` を持つ時間注釈へ分離し、同じrecord IDを参照する方向で検討する。記録の複製で同一性を偽装しない。

## 表示単位と、線から記録への接続（2026-11-01追補）

ユーザーの「年表示なら1991年の出来事も、1991年のどこかという出来事も点が自然」という明確化を採用する。他の出来事の有無で点化を決める設計にはしない。「点の情報を上に置くべき」という仮説は撤回済みであり、上下の並びを正解として固定しない。

- 暦の表示単位を `auto / year / month / day` として閲覧状態に置く。autoは渡された断面で最も細かい日付精度を使う。保存構造・訂正履歴・Capsule断面へ変更を書かない。
- 時点は元の精度にかかわらず一つの点で表示する。年月までの時点を、混在する日精度の記録に合わせて月初〜月末へ広げない。発生候補幅は元の可能範囲の両端を表示単位へ投影し、同じ単位、または同じ原表現なら丸い点にする。候補幅の点は中抜きとし、記録の意味・範囲は短い説明と詳細に残す。年をまたぐ候補幅は年表示でも幅として残る。
- 続いた期間は同じ単位内に収まっても出来事の点へ変えず、短い両端付きの期間記号で示す。拡大して元の期間を読める。旧入力の未区別という意味も維持する。
- 日表示で年・月だけの時点を配置しても一つの点と元の年月ラベルを使い、未知の月日や候補の後端を作らない。実期間と、異なる端を持つ発生候補幅は引き続き範囲として配置し、未知の月日を表示や原本へ補わない。表示単位は記録精度の上限ではなく、年を選んでも元の月日を失わない。
- 同じ日付・表示単位の記録は、日付の括りを共有しながら、それぞれの見出しに独立した接続線を持つ。期間終端にもその記録の接続先・名前を示す。同一の元日付では入力順を保ち、点を上、期間を下という意味付けはしない。
- 共通CSS Gridを記録単位の行へ展開する。線の始点・終点・境界区間も同じ行を参照し、根拠や子軸を開いたときも接続を維持する。ピクセル座標の計測や遅れて移動する再配置を必要としない。
- 期間の不確かな部分は一本の中央点線、確かな部分は同じ位置の実線にする。全体を囲う破線枠は重ねない。開始候補と終了候補が重なる場合は点線を二重に重ねず、確かな中央部分を作らない。

[表示単位と接続の検証](../verification/THEME_TEMPORAL_PROJECTION_20261101.md)。時刻・timezone・定義のない前期後期・複数の離れた候補などは、この表示改善の完成範囲へ含めない。

## テーマ・年表・関係図の責務（表示分離後の現行契約）

テーマは対象・根拠付き記録を束ねる単位。年表はそれらを時期に沿って読む表示であり、関係図は対象間の明示関係を読む表示である。テーマと年表を同じデータ型・同じ存在にしたものではない。現行画面はテーマ単位の既定年表を開くが、一つのテーマ内にも複数の暦・周期・定性軸を持て、Capsuleでは選択した断面を読む。任意の名前を付けた複数年表を独立管理するUIまでは未実装。

以前はテーマの全記録を既存Capsuleの文書へ変換する都合で、episode/noteまで自由テキストと対象の説明欄へ自動コピーしていた。年表説明を関係図へ出す具体的なUX上の理由はなく、この既定動作を修正した。

| 記録 | 関係図への自動出力 | 年表・記録 |
| --- | --- | --- |
| `relation` | subject→objectの辺、必要な両端、関係に対応する根拠 | 対象名・具体的な関係名・方向・相手名を併記 |
| `episode` | 出力しない。テキスト・対象説明・専用ノードも自動生成しない | エピソードとして保持。時期・根拠・検索・訂正・Capsule断面も保持 |
| `note` | 出力しない。テキスト・対象説明・専用ノードも自動生成しない | 説明として保持。時期・根拠・検索・訂正・Capsule断面も保持 |

関係のないテーマ・新Capsuleは年表から開く。関係図を選んだ場合は内容がない理由と年表への入口を示す。私有Capsuleではそこから空の関係図を編集でき、作者が図のために追加した注記・対象・関係は通常保存する。年表の説明を自動で流し込む動作とは分ける。

期間は `record.time` の性質。`duration` だからEntityを新設する、期間内にあるから所属の辺を作る、といった判断をしない。「青の時代」を期間名に使うだけならピカソをsubjectにした説明記録のtime/labelで足りる。作品を分類する参照先として明示的に結ぶ場合には独立Entityとして扱う意味がある。実資料サンプルの青の時代はその分類先として登録したもので、期間の描画だけのために作った対象ではない。

原記録と関係図の対応は同じ記録IDを使う。関係図に対応要素がない行へは移動アイコンを出さず、年表の説明行の選択から存在しない図要素へfocusを送らない。マークは原記録を表し、作者が独自変更した名前・形・端点と外見を自動同期するものではない。

### 既存の保存・共有内容

現行テーマと新しいCapsuleには新しい出力を使う。既に保存したCapsule・共有版は自動変換しない。所有者の「旧形式の自動注記を整理」操作で、保存時の生成文書と一致する注記、対象の自動説明、その説明用根拠コピーだけを図から外す。元の記録・時期・根拠はsnapshotに保持する。

文面・書式・位置を変更した注記は残す。独自のノード・関係・配置・対象説明の編集も保持する。旧図の対象ノードを勝手に削除・再配置しない。内容訂正の明示取込だけでは旧表示の契約を切り替えず、整理時まで生成基準を保持する。

整理は私有図の内容版を進め、図を編集保存する前なら整理前の図へ戻せる。通常保存・訂正取込後には、その後の作業を上書きしないため整理の取り消しを出さない。取り消し用の文書は私有データであり、共有コピーに含めない。整理・取り消しだけで共有版は変わらず、既存の同URLへの明示反映で更新する。

[表示分離・保存・共有の検証](../verification/THEME_VIEW_SEPARATION_20261101.md)。対象を持たない全体注記、複数の任意年表の管理、原記録と作者独自Graphの外見同期などは引き続き後続。
