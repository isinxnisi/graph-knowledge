# 対象の原文訂正と固定版の読取（R1e）

2026-11-06。R1の一部分。初版全体やR1全体の完了ではない。

## 同じ対象の原文を直す

利用者は通常探索の対象詳細から「名前・説明の訂正を提案」、または知識の投稿の操作選択から入る。共通知識の対象の公開版を取得し、名前・別名・説明・それぞれの原語と訂正理由、根拠を保存する。草稿は未入力でも保存でき、公開確認では厳格に検証する。

- correct-entity は同じEntity IDを維持する原文の変更。分類変更・他の対象への付替え・同一性の統合・訳文だけの変更とは分ける。分類の変更は受け付けない。
- 元の内容版と現在版が違う場合は上書きしない。利用者が改めて取得して差分を確認する。
- 変更部分すべてと理由・根拠をAIへ渡す専用の確認方針 entity-original-correction-v1 を使う。短い訂正概要だけの支持で承認しない。削除も根拠の確認対象。
- 通常の原資料取得・共通証明・公開状態・予算・再試行・最終排他を共用する。外部取込は資格のoperationsに明示された場合だけ同じ処理を使える。既存の専用資格へ権限を自動追加しない。
- 同じ知識の再利用だけで原文訂正を別Recordへ付け替えない。変更なし・古い観測版・ACK喪失の再実行を区別する。

原本の1トランザクションでEntityの次版と、対象・根拠に結び付く訂正記録を保存する。記録の文は変更した欄から組み立てた概要で、任意の事実を紛れ込ませない。会員DBには同じ受理decisionに対する投稿者の帰属を保存し、匿名と公開活動の既存契約を継承する。旧Entity版、旧Record、既存Capsuleの固定断面を更新しない。

現在の選択UIは共通原本の公開Entityが対象。旧KGだけにある対象は直接書き換えず、共通原本への対応・配置別認可の残件としてR1/R4で接続を確認する。新Entity作成時の別名・説明を無根拠で受理する許可にも広げない。

## 公開した当時の内容を読む

/records?id=RECORD_ID&revision=N と mode=record-version は、指定した公開Record版を読む。投稿結果とプロフィールの公開活動は固定版へ結び、別途「現在の知識を探索で開く」を提供する。過去のGraph全体を再現する画面ではなく、その知識の内容・対象・根拠・帰属を読む画面である。

参照するEntity版は次の優先順で確定する。

1. 実際に有効化された公開世代の最初の断面。未公開のstaged/failed世代は使わない。
2. 記録作成時の操作journalが持つ明示的なEntity参照。Entity訂正の記録は訂正後の版。
3. 古い操作に参照版がない場合は、保存時点で公開されていた対象版。画面でもその基準を明示し、明示pinが存在したとは扱わない。

根拠はRecordに保存されたSource pinを使う。指定版が公開済みであることに加え、現在のRecord・対象・資料・関連Record/Themeが閲覧可能であることを再確認する。未共有の旧版や停止中の内容へ履歴から到達させない。取得はno-storeで、画面は再表示時と60秒ごとに閲覧可否を再確認する。通信失敗だけでは表示を消さず、403/404/410の停止は反映する。

## 検証と残件

実DBで、元IDと旧版の保持、同時訂正の競合、再実行、未公開旧版・停止した資料の拒否、公開済み世代とstagedの区別、会員への帰属を検証する。実AIでのこの専用方針の判定と、実ブラウザの結果は[検証記録](../verification/KNOWLEDGE_R1E_ENTITY_HISTORY_20261106.md)で区別する。

追加migrationはない。R1の翻訳文脈・cache、対象の識別、新旧の接続と安全境界、R2〜R5の要件は維持する。無料枠を増やしたり、個別の管理者承認を通常手順に加えたりしない。
