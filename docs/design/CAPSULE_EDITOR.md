# Capsuleを編集する体験と保存の契約

更新日: 2026-10-29 / Issue #63 / `capsule-contribution-001 / r02`

状態: Capsule先行公開に向けた実装契約。公開環境への反映と検証結果は別途記録する。2026-10-09の参照・チェックリスト中心の最小Capsuleから、Graph上で編集する方式へ更新する。ユーザーによる知識登録・KGへの申請は今回有効にしない。

## 判断の基準

Capsuleは、利用者が意図して作る一つの関係図である。探索で見つけた構成を起点に、自分の対象、関係、根拠、注釈、配置を編集できる。保存・共有しても本線KGへ書き込まない。公開されたCapsuleの内容も、KGによる受入や事実の確認を意味しない。

利用者は試しに編集してから元へ戻せる。初回は自動保存を採用せず、閲覧、編集中、保存済みを明確にする。後日の自動保存や申請の追加を理由に、現在の操作を曖昧にしない。

既存Capsuleを削除してよいことは2026-10-29にユーザーが承認した。旧形式の完全移行は公開条件にしない。小さい互換読取は維持できるが、旧体験への適合のために新しい文書や編集操作を複雑にしない。この承認は会員・コミュニティ・本線KGの削除を含まない。

## 入口と画面の役割

- Graph付近の「Capsule作成」で、現在表示している対象・個別Claim・配置を取り込む。対象の選択チェックリストや必須の命名ダイアログを挟まない。
- タイトルは起点Entityの名称などから仮決定し、後で変更できる。
- Capsule名と編集状態をGraph枠に表示する。編集中は青い縁と控えめな光で状態を伝え、文字でも区別する。色だけには依存しない。
- 保存済みのCapsuleへ戻る入口をGraph画面に置く。ブラウザ保存と本人の会員保存を区別し、最近使ったもの・お気に入りを扱う。
- Graphを主な作業場所とし、右側は選択要素の説明・根拠・由来の確認、詳細入力は小さいダイアログで扱う。モバイルでもGraphからの往復を保つ。

## 閲覧・編集・保存

| 操作 | 内容と配置の扱い |
| --- | --- |
| 保存済みCapsuleを開く | 保存した文書と配置を表示する |
| 閲覧中にノードを移動 | その閲覧中の一時配置。保存済みの内容版は変更しない |
| 編集を始める | その時点の閲覧配置を編集の初期状態として引き継ぐ |
| 編集する | 文書の草稿をメモリに保持する。操作単位でUndo/Redoできる |
| 編集を破棄 | 編集開始直前の閲覧内容・配置へ戻る |
| 明示的に保存 | 内容と配置を一つの版として保存する |
| 保存に失敗、競合、結果不明 | 未保存の入力を保持し、成功した表示にしない。再試行は同じ操作を照会・再送する |
| タブ復帰などで本人を再確認 | private内容を一時的に隠し、同じ本人の確認後に再開する。編集中の入力、閲覧中の一時配置とpan・zoomをメモリ内に保持する |
| 未保存のまま別画面へ移動 | 保存前の変更があることを確認できる。暗黙に保存しない |

通常GraphにもCtrl/Metaクリックによる複数選択と、選択したノードのまとめて移動を入れる。複数ノードの一回のドラッグは、CapsuleのUndoでは一操作として扱う。探索条件や起点の変更後に、別の探索の移動履歴を混ぜない。

## 編集できるもの

| 対象 | 初回の操作 |
| --- | --- |
| KG由来Entity | Capsule内のタイトル、任意の説明、分類バッジ、根拠を編集する。KGの同一性と取り込んだ元情報は保持する |
| 独自Entity | タイトル、任意の説明、分類バッジ、根拠を持つCapsule内の対象を作る |
| 関係先から追加 | 本線KGで実際につながるEntityと、取得できた個別Claimを追加する |
| Entity検索から追加 | 本線KGを検索して選び、選択中の対象との間にCapsule内の「関係する」を作る |
| 独自Entityを追加 | 選択中の対象との間にCapsule内の「関係する」を作る |
| 関係 | 任意の表示ラベルと説明・根拠を編集する。元のKG Claimの意味を上書きしない |
| 自由テキスト | テキスト、表示スタイル、位置を保存する。Entityとの関連付けは必須にしない |
| 削除 | Capsuleから取り除く。Entityを取り除いた際はその接続関係と関連する根拠を一緒に扱う |

検索からの追加や独自作成で生まれる関係は、KGで確認された関係に見せない。「同じ図にある」ことだけから新しい関係を生成しない。

内容をいったんすべて取り除いた、名前だけの空の文書も保存できる。あとから独自対象・KG検索・テキストから組み直せる。これは新しい文書形式の契約であり、文書を持たない旧参照形式の検査を緩めるものではない。対象・関係・テキストは内容一覧からも選択でき、追加した対象やテキストが画面外へ置かれた場合は、倍率を変えず必要な分だけ表示位置を動かす。

## 文書・断面・KGの同一性

`lib/domain/capsule-document.ts`を文書契約とする。既存の会員保存の外枠に`content.document`を追加し、文書のある外枠は`schemaVersion: 2`、文書自体は`schemaVersion: 1`として区別する。

文書はnodes、relations、texts、evidence、layoutを持つ。図の要素キーとKG参照のIDを別の意味として扱う。KG由来の対象や個別Claimは元ID・取得時点・取得できたrevision・取得した内容を保持する。Capsule内の編集値はその上に保持し、元の断面を上書きしない。独自要素にKGでの同一性や受入状態を自動付与しない。

Graphの表示線が複数Claimをまとめていても、保存する根拠の単位は個別Claimである。表示用の線IDをClaimのIDとして保存しない。KG専用schemaに独自Entityや自然言語の関係を偽装して押し込まず、描画用の入力を分ける。

### 「有る・無い」を記録する範囲

作成操作の時点で表示・取得済みだった情報を固定する。後から通信が完了したことだけを理由に、保存対象の図や説明を変更しない。

- Entity/Claimの概要と、詳細や根拠まで取得したかを区別する。
- 隣接情報には取得条件と取得済みClaim IDを残し、取得範囲を`unknown`、`partial`、`complete`で表す。
- `complete`は記録した検索条件の範囲で取得が完了した意味であり、KG全体を取得した意味ではない。
- 完了した範囲の空集合は「その条件の範囲では無かった」と扱える。未取得や途中の空集合から不存在を推測しない。
- 元の根拠や詳細の追加取込は、明示的な操作とする。

現在のKGを取得して比較する場合も、保存した断面、Capsule内の編集値、現在のKGを混ぜない。取得失敗と削除を区別し、未取得情報の比較不能を「変更なし」と表示しない。最新情報の取り込みは、利用者が選んで行う操作として後から拡張できる。

## 保存と認可

匿名利用の新しい保存先はIndexedDBとし、明示保存だけで文書を書き込む。旧localStorageの読み取りは互換用であり、新しい編集草稿の自動永続化には使わない。会員は本人のPostgreSQL保存へ進める。

会員の所有者確認、dataset、Origin、期待する利用者、期待revisionを検査する。更新のrequest IDと結果照会によって、通信結果が不明な際の二重更新を防ぐ。会員の一覧は文書本文を含めない概要を返し、開く・編集する・共有内容を確認する時に対象の詳細を取得する。

文書は最大200対象・400関係・100テキスト、保存payloadは2MBまでとする。会員ごとのprivate文書と全datasetの固定共有版の合計は64,000,000 bytesまでとし、保存・共有の同時実行でも上限を超えないよう所有者単位のlock下で確認する。構成参照と文書の一致、関係の端点、根拠の対象、KGのsnapshotとIDの一致を検査する。上限を超えた場合は切り捨てて保存しない。

最近開いた時点とお気に入りは、本人IDを含むキーで分離したブラウザ内metadataとして保持する。この個人用整理情報の端末間同期は初回の対象にしない。文書本文の会員保存と混同しない。

追加migrationは011（Capsule文書と更新receipt）および012（コミュニティ掲載）。既存migrationのchecksumを変更せず、適用はCLIの明示オプションで行う。準備状態をcapability APIで返し、未適用の会員DBへ新しい文書を書き込まない。

## 共有・コミュニティへの最小接続

共有するのは保存済みの指定版である。本人が編集中の草稿を共有へ混ぜない。限定リンクとコミュニティ掲載は独立した許可として扱い、一方のURLを知ることから他方の権限を得ない。

コミュニティ掲載では、本人のCapsuleの詳細を取得して共有する内容を確認し、保存済みの版を固定する。掲載、明示的な版更新、撤去、閲覧、関連する会話との往復を初回に用意する。新しい版の保存だけで掲載内容を更新しない。投稿本文へ任意の添付を増やす経路は今回の対象にしない。

公開範囲、メンバー世代、発行者の資格、撤去、運営による版の共有停止を各読み取り時に確認する。権限のない掲載を一覧から除いてから件数を制限する。退会後の再参加や公開範囲の再変更で、失われた許可が自動的に復活しない。通報が対象とした版を保持し、後に新しい版へ更新されても別の版を誤って停止しない。

## 後続の知識登録への引き継ぎ

「選択範囲を申請」などの入口は準備中として閉じておく。今回、ユーザー投稿を受け付けるAPI、審査queue、AI推論、KGへのmerge、受入結果を実装・稼働したことにはしない。

後続設計で保持するUX上の条件は、申請確認用の内容をCapsuleから分離して編集できること、申請対象と単なる文脈を区別できること、対象ごとの状態・結果・次に必要な操作が分かること、部分受入と実際のKG公開を区別することである。受入時に元Capsuleや独自要素を破壊的に書き換えることを前提にしない。

## 並行機能と公開の境界

本変更はKGの読取APIを利用し、公開KGの書込・固定fixture・語彙・受入pipelineを変更しない。Kev、AI教育Worker、日次予定、AIラボのartifact、管理Connectorの接続設定も変更しない。

公開時は既存の会員・コミュニティ・運営・Graph・AIラボとの往復を確認する。ソースの検証、mainへの受入、開発PCの3200/beta、本番VPSの反映を別々に記録し、クラウドの一時確認サーバーを既存betaや本番として報告しない。
