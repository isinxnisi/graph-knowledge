# Capsuleを編集する体験と保存の契約

更新日: 2026-10-30 / Issue #63 / `capsule-contribution-001 / r03`

状態: 初期実装を基礎に、作成・閲覧・再編集を共通の広い作業面へ統一する現行契約。以下のUI・保存形式・コメント既定値は実装対象として反映した内容であり、それだけで実環境での検証やユーザーによる体験の受入を意味しない。今回の配置・実操作・未確認事項は[2026-10-30のUX・beta検証記録](../verification/CAPSULE_EDITOR_UX_BETA_20261030.md)に分けて記録する。過去の[2026-10-29の反映](../verification/CAPSULE_EDITOR_BETA_20261029.md)は今回のUI品質の受入証拠にしない。

今回の終了点は既存のlocalhost:3200とHTTPS beta。本番VPSへの転送・切替は行わない。ユーザーによる知識登録・KGへの申請は準備中を維持する。

## 判断の基準

Capsuleは、利用者が意図して作る一つの関係図である。探索で見つけた構成を起点に、自分の対象、関係、根拠、注釈、配置を編集できる。保存・共有しても本線KGへ書き込まない。公開されたCapsuleの内容も、KGによる受入や事実の確認を意味しない。

質素かつ上質な道具として、Graphを主役にする。アイコン、短いラベル、余白、フォーカス、必要なときに現れる操作に役割を持たせる。説明文や青い装飾の追加だけを品質の根拠にせず、対象を見たまま操作でき、結果を認識し、自然に戻せることを基準にする。

利用者は試しに編集してから元へ戻せる。初回は自動保存を採用せず、閲覧、編集中、保存済みを明確にする。後日の自動保存や申請の追加を理由に、現在の操作を曖昧にしない。

既存Capsuleを削除してよいことは2026-10-29にユーザーが承認した。旧形式の完全移行は公開条件にしない。小さい互換読取は維持できるが、旧体験への適合のために新しい文書や編集操作を複雑にしない。この承認は会員・コミュニティ・本線KGの削除を含まない。

## 入口と画面の役割

- Graph付近の「Capsule作成」で、現在表示している対象・個別Claim・配置を取り込む。対象の選択チェックリストや必須の命名ダイアログを挟まない。
- Graphからの作成、My Capsulesからの再訪、会員一覧からの再編集は、共通の広いレスポンシブな作業面を使う。今回のhostは画面に広く取るモーダルとし、My Capsules一覧の寸法で編集面を制約しない。
- タイトルは起点Entityの名称などから仮決定する。編集時はタイトルを直接クリックして入力し、その場で適用・取消できる。タイトルやフォームの適用は草稿への反映であり、Capsule全体の保存とは別である。
- Capsule名と編集状態をGraph枠に表示する。編集中は青い縁と控えめな光で状態を伝え、文字でも区別する。色だけには依存しない。
- 保存済みのCapsuleへ戻る入口をGraph画面に置く。ブラウザ保存と本人の会員保存を区別し、最近使ったもの・お気に入り・共有とコミュニティ掲載の状態を一覧から確認できる。共有状態の概要は本文や共有tokenを一覧へ含めない。
- Graphを主な作業場所とし、内容一覧と詳細ペインは必要時に開く。右側は選択要素の説明・根拠・由来・現在KGとの比較を確認する場所とし、編集ダイアログへ入るための必須の中継地点にしない。狭い画面ではペインがGraphを常時押しつぶさない。
- 選択対象・背景の右クリック、対象の直接編集、選択ツールの操作メニュー、追加ツールから主要操作へ到達できる。常設の長いテキストボタン群へ全操作を重複配置しない。

## 閲覧・編集・保存

| 操作 | 内容と配置の扱い |
| --- | --- |
| 保存済みCapsuleを開く | 保存した文書と配置を表示する |
| 閲覧中にノードを移動 | その閲覧中の一時配置。保存済みの内容版は変更しない |
| 編集を始める | その時点の閲覧配置・表示中心・倍率・選択を編集の初期状態として引き継ぐ |
| 編集する | 文書の草稿をメモリに保持する。操作単位でUndo/Redoできる |
| 既存Capsuleの編集を破棄 | 編集開始直前の閲覧内容・配置・表示中心・倍率・選択へ戻る |
| 新規作成を破棄 | 元の探索Graphへ戻る。作成前の探索配置を変更しない |
| 明示的に保存 | 内容と配置を一つの版として保存する |
| 保存に失敗、競合、結果不明 | 未保存の入力を保持し、成功した表示にしない。再試行は同じ操作を照会・再送する |
| 通常の定期再確認・タブ復帰 | 本人再確認だけを理由に作業面を差し替えない。入力、ドラッグ、選択、メニュー、フォーカス、閲覧位置を維持する。通信失敗は認証失効と区別する |
| 実際のログアウト・本人変更・権限失効 | private表示・変更操作を止める。元の本人の草稿を別人へ渡さず、遅れて返る旧セッションの応答を採用しない。再認証可能な草稿は元の本人に分離してメモリ内に保持する |
| 未保存のまま別画面へ移動 | 保存前の変更があることを確認できる。暗黙に保存しない |

通常GraphにもCtrl/Metaクリックによる複数選択と、選択したノードのまとめて移動を入れる。複数ノードの一回のドラッグは、CapsuleのUndoでは一操作として扱う。探索条件や起点の変更後に、別の探索の移動履歴を混ぜない。

保存する視点はGraph座標系の`layout.center`と`zoom`を基準にし、`viewport`に保存時の幅・高さ、互換用に`pan`も保持する。表示領域が変わった再訪では、新しい幅・高さからpanを復元する。画面寸法だけの変化を編集内容の変更と扱わず、毎回fitして利用者の視点を上書きしない。centerもviewportも無い旧文書は正確な視点を復元できないため、ノード位置と倍率を保持して要素の範囲を中央に置く。次の明示保存から実際のcenterを記録する。

Undo／Redoは追加、編集、除外、複数要素の一回の移動を操作単位で戻す。フォームの入力中はフォームの取消を先に扱い、タイトル入力のEscはタイトルだけを取り消す。IME変換中のEnter・Escをフォーム確定や画面終了へ流さない。未保存内容の破棄・画面終了はフォーカスを持つ確認ダイアログで扱い、戻る操作から編集を続けられる。

開閉、メニュー、保存結果、選択・追加の反応は短い変化で因果関係を伝え、操作をアニメーション待ちにしない。`prefers-reduced-motion`では動きを減らしても状態・フォーカスが分かることを検証する。

## 編集できるもの

| 対象 | 初回の操作 |
| --- | --- |
| KG由来Entity | Capsule内のタイトル、任意の説明、分類バッジ、根拠を編集する。KGの同一性と取り込んだ元情報は保持する |
| 独自Entity | タイトル、任意の説明、分類バッジ、根拠を持つCapsule内の対象を作る |
| 関係先から追加 | 本線KGで実際につながるEntityと、取得できた個別Claimを追加する |
| Entity検索から追加 | 本線KGを検索して選び、選択中の対象との間にCapsule内の「関係する」を作る |
| 独自Entityを追加 | 選択中の対象との間にCapsule内の「関係する」を作る |
| 関係 | 任意の表示ラベルと説明・根拠を編集する。元のKG Claimの意味を上書きしない |
| 自由テキスト | 改行を含む本文、幅・折り返し、文字サイズ、太字、左右／中央揃え、表示スタイル、位置を保存する。Entityとの関連付けは必須にしない |
| 削除 | Capsuleから取り除く。Entityを取り除いた際はその接続関係と関連する根拠を一緒に扱う |

検索からの追加や独自作成で生まれる関係は、KGで確認された関係に見せない。「同じ図にある」ことだけから新しい関係を生成しない。

右クリックメニューはEntity、関係、テキスト、背景、複数選択に応じて操作を出し分ける。選択済みの対象の右クリックで複数選択を崩さない。画面端で収め、Esc・外側クリックで閉じ、キーボードのメニュー移動とフォーカス復帰を扱う。日常的な除外を毎回確認で遮らずUndoで戻せるようにする。一本の表示線に複数Claimがある場合は個別の関係を選んで編集し、線全体の除外では対象件数を示す。

KGの関係先追加は実在する個別Claimと対象を取得し、追加済みを区別する。追加した要素を選び、必要な分だけ視点を動かす。Entityの分類は名称と独立した小さいチップとしてGraph上へ描画する。自由テキストは共通の折り返し計算で表示範囲と当たり判定・選択範囲を合わせ、編集フォームでは本文と書式を一緒に確認できる。

独自Entityも図の中心になり得るため、補助要素に見える点線では描かない。白に近い塗りと実線でKG由来との微差を残し、出自は詳細でも示す。Entityの形は標準・角丸四角・丸・四角・ひし形から選べる。これはCapsule内の表示上の指定であり、人物・組織などのKG分類や元snapshotを書き換えない。省略時は元の分類に対応する形を使う。

独自関係の編集フォームには両端の名前と矢印を表示し、向きの反転と逆向きの追加を行える。相互関係は独立した2本の関係として保存し、それぞれのラベル・説明・根拠を編集できる。片方向の根拠を逆方向へ自動コピーしない。同じ端点・同じラベルの逆関係がある場合は重複追加しない。反転／相互化は1回のUndoで戻せる。自己関係には無意味な反転／相互化操作を出さず、KG由来Claimの方向は元記録に従う。

安全に閉じられる一覧・閲覧・検索・フォームは外側クリックでも閉じる。適用前入力のあるフォームは外側クリックで失わず、Capsule全体の未保存編集を閉じる場合は明示確認を出す。共有画面のコメント草稿は同じWorkspace内で開き直しても保持し、Workspaceを離れる時点で破棄確認する。処理中、IME変換中、内側から外側へドラッグした場合を単なる外側クリックと扱わない。×は共通の中央配置とし、保存通知は背景色・下線・チェックで区別し、通知の閉じる操作は控えめにする。

内容をいったんすべて取り除いた、名前だけの空の文書も保存できる。あとから独自対象・KG検索・テキストから組み直せる。これは新しい文書形式の契約であり、文書を持たない旧参照形式の検査を緩めるものではない。対象・関係・テキストは内容一覧からも選択でき、追加した対象やテキストが画面外へ置かれた場合は、倍率を変えず必要な分だけ表示位置を動かす。

## 文書・断面・KGの同一性

`lib/domain/capsule-document.ts`を文書契約とする。既存の会員保存の外枠に`content.document`を追加し、文書のある外枠は`schemaVersion: 2`、文書自体は`schemaVersion: 1`として区別する。

文書はnodes、relations、texts、evidence、layoutを持つ。今回の`layout.center`／`viewport`、nodeの`shape`（round-rectangle／circle／rectangle／diamond）、textの`width`（96〜800）・`fontSize`（12〜48）・`fontWeight`（normal／bold）・`align`（left／center／right）は省略可能な追加項目とし、文書schemaVersionは1のままとする。省略時は旧スタイルに対応する既定値で描画する。保存・再訪・固定版共有で同じ書式を読む。図の要素キーとKG参照のIDを別の意味として扱う。KG由来の対象や個別Claimは元ID・取得時点・取得できたrevision・取得した内容を保持する。Capsule内の編集値はその上に保持し、元の断面を上書きしない。独自要素にKGでの同一性や受入状態を自動付与しない。

Graphの表示線が複数Claimをまとめていても、保存する根拠の単位は個別Claimである。表示用の線IDをClaimのIDとして保存しない。KG専用schemaに独自Entityや自然言語の関係を偽装して押し込まず、描画用の入力を分ける。

### 「有る・無い」を記録する範囲

作成操作の時点で表示・取得済みだった情報を固定する。後から通信が完了したことだけを理由に、保存対象の図や説明を変更しない。

- Entity/Claimの概要と、詳細や根拠まで取得したかを区別する。
- 隣接情報には取得条件と取得済みClaim IDを残し、取得範囲を`unknown`、`partial`、`complete`で表す。
- `complete`は記録した検索条件の範囲で取得が完了した意味であり、KG全体を取得した意味ではない。
- 完了した範囲の空集合は「その条件の範囲では無かった」と扱える。未取得や途中の空集合から不存在を推測しない。
- 元の根拠や詳細の追加取込は、明示的な操作とする。

現在のKGを取得して比較する場合も、保存した断面、Capsule内の編集値、現在のKGを混ぜない。取得失敗と削除を区別し、未取得情報の比較不能を「変更なし」と表示しない。最新情報の取り込みは、利用者が選んで行う操作として後から拡張できる。

## 保存と認可

匿名利用の新しい保存先はIndexedDBとし、明示保存だけで文書を書き込む。旧localStorageの読み取りは互換用であり、新しい編集草稿の自動永続化には使わない。会員は本人のPostgreSQL保存へ進める。

会員の所有者確認、dataset、Origin、期待する利用者、期待revisionを検査する。更新のrequest IDと結果照会によって、通信結果が不明な際の二重更新を防ぐ。会員の一覧は文書本文を含めない概要を返し、開く・編集する・共有内容を確認する時に対象の詳細を取得する。

文書は最大200対象・400関係・100テキスト、保存payloadは2MBまでとする。会員ごとのprivate文書と全datasetの固定共有版の合計は64,000,000 bytesまでとし、保存・共有の同時実行でも上限を超えないよう所有者単位のlock下で確認する。構成参照と文書の一致、関係の端点、根拠の対象、KGのsnapshotとIDの一致を検査する。上限を超えた場合は切り捨てて保存しない。

最近開いた時点とお気に入りは、本人IDを含むキーで分離したブラウザ内metadataとして保持する。この個人用整理情報の端末間同期は初回の対象にしない。文書本文の会員保存と混同しない。

追加migrationは011（Capsule文書と更新receipt）、012（コミュニティ掲載）、013（コメント受付ONのDB既定値）、014（限定リンクの所有者再取得）。適用済みchecksumを書き換えず、013は`--capsule-comments`、014は`--capsule-share-recovery`と正しい`--confirm-origin`で明示適用する。全系列適用後のledgerは000〜014の15件となる。013は既存の受付停止やコメント内容を更新せず、014は既存リンクを再発行・失効しない。011／012の準備状態はcapability APIで返し、未適用の会員DBへ新しい文書を書き込まない。013／014はledgerと実際のschema・APIで確認する。

## 共有・コミュニティへの最小接続

共有するのは保存済みの指定版である。本人が編集中の草稿を共有へ混ぜない。限定リンクとコミュニティ掲載は独立した許可として扱い、一方のURLを知ることから他方の権限を得ない。

共有ダイアログは保存済みのタイトル・版を短く示し、コメント受付のswitch、リンク作成、コピー・プレビュー、明示的な更新・停止をまとめる。新しいprivate版を保存しても、既存リンクやコミュニティ掲載が示す内容は自動更新しない。会話は実際の共有版へ接続し、private最新版と取り違えない。Graph・根拠も文書に保存された断面を読み、現在KGとの差分確認は別の操作にする。

有効な限定リンクは、所有者が共有画面を開き直すと同じURLを何度でもコピーできる。再取得でURL・対象版・コメント・掲載内容を変更しない。従来の「発行時に一度しか表示しない」制約は廃止する。DBにtoken平文は保存せず、014以降のリンクはサーバー秘密と用途・dataset・Capsule・ランダムなlink ID・版を分離したHMACから再生成し、保存済みhashとの一致と本人認可を確認して所有者だけへ返す。共有先や一覧summaryには返さない。

既存hashのみのリンクは復元できないため、共有画面で一度新しく発行した後から再取得に対応する。既存リンクを移行時に勝手に失効しない。認証secretの更新で再生成できなくなったリンクも、hashによる閲覧と明示停止は維持し、所有者には作り直す経路を示す。別の保存版への共有更新は引き続き新URLへの明示的な置換であり、旧URLを同じ内容のまま保証する契約と混同しない。

新しく共有するCapsuleはコメント受付ONを既定にする。共有発行時にスレッドを同じtransactionで準備し、まだスレッドが無い版もONとして扱う。DB既定値・サーバーの作成値・共有UIを一致させ、既に明示してOFFにした状態は再発行だけで変えない。受付ONは既存の投稿資格を広げない。本人・共有先・公開状態などの認可を読み取り・投稿ごとに確認する。

共有先と所有者の共有画面ではコメントを自動表示し、別の「コメントを見る」操作を要求しない。空、読み込み、投稿中、失敗、未ログイン、権限なし、受付停止を区別し、必要な次の操作を近くに示す。定期読込や単なる通信失敗で会話・入力を置き換えず、権限失効時はprivate表示を止める。投稿草稿・再送情報は本人と対象版に分離する。

コミュニティ掲載では、本人のCapsuleの詳細を取得して共有する内容を確認し、保存済みの版を固定する。掲載、明示的な版更新、撤去、閲覧、関連する会話との往復を初回に用意する。新しい版の保存だけで掲載内容を更新しない。投稿本文へ任意の添付を増やす経路は今回の対象にしない。

公開範囲、メンバー世代、発行者の資格、撤去、運営による版の共有停止を各読み取り時に確認する。権限のない掲載を一覧から除いてから件数を制限する。退会後の再参加や公開範囲の再変更で、失われた許可が自動的に復活しない。通報が対象とした版を保持し、後に新しい版へ更新されても別の版を誤って停止しない。

## 表示場所と編集状態の分離

今回の実装は次の責務を分ける。

- `CapsuleSurface`は広いdialogの表示hostであり、保存や編集履歴を持たない。
- `CapsuleStudio`は閲覧／編集、草稿、Undo／Redo、編集前の閲覧状態、選択・フォームを扱い、保存を`onSave`へ委譲する。
- `CapsuleWorkspace`は保存先、本人、capability、request ID・結果照会、IndexedDB／会員API、共有UIの接続を扱う。

通常Graph上のシームレスな編集は今回実装・検証した体験ではない。将来はWorkspaceの表示hostを差し替え、Studioを途中でunmountせず保持するか状態を上位へ持ち上げ、元のGraphとの視点・選択・フォーカスの引渡し、URL／戻る／離脱確認、共有ダイアログの重なりを設計・検証する必要がある。今回の分離はその変更箇所を限定するためであり、hostを交換するだけで同じ体験が成立すると保証するものではない。

## 後続の知識登録への引き継ぎ

「選択範囲を申請」などの入口は準備中として閉じておく。今回、ユーザー投稿を受け付けるAPI、審査queue、AI推論、KGへのmerge、受入結果を実装・稼働したことにはしない。

後続設計で保持するUX上の条件は、申請確認用の内容をCapsuleから分離して編集できること、申請対象と単なる文脈を区別できること、対象ごとの状態・結果・次に必要な操作が分かること、部分受入と実際のKG公開を区別することである。受入時に元Capsuleや独自要素を破壊的に書き換えることを前提にしない。

## 並行機能と公開の境界

本変更はKGの読取APIを利用し、公開KGの書込・固定fixture・語彙・受入pipelineを変更しない。Kev、AI教育Worker、日次予定、AIラボのartifact、管理Connectorの接続設定も変更しない。

今回の3200／HTTPS beta反映では、既存の会員・コミュニティ・運営・Graph・AIラボとの往復を確認する。ソースの検証、実ブラウザでの機能・操作確認、配置したSHAとbuild、ユーザーによる体験の評価を別々に記録する。AIによる評価を人間のユーザーテスト済みとは扱わない。本番VPSは次の作業であり、今回実行しない。クラウドや一時確認サーバーを既存betaや本番として報告しない。


## スマートフォンでの操作とヘッダー（2026-10-30追記）

狭幅ではCapsuleのモード・保存状態をタイトル側へまとめ、破棄・保存・閉じるを同じ行に置く。主要操作の44pxの押下領域は維持し、長いタイトルは省略する。タイトル入力時だけ入力面を広げる。サイトのアイコンだけの操作にはラベル用の余白を残さず中央に配置する。管理者で操作数が増える480px以下ではアカウント名をアイコンに集約し、本人名はメニュー・アクセシブルな説明に残す。

Capsule編集中のノード・関係・テキストは、ダブルクリック／ダブルタップから直接編集へ進む。閲覧中は内容確認へ進む。タッチは400ms、マウスは300msの同種入力を対象とし、単タップ選択と区別する。8px以上の移動、長押し、複数指、touchcancel、タブ離脱をまたいだ入力を二連続のタップと扱わない。通常Graphの単選択・遅延展開の契約を維持する。実端末での操作感の評価とイベントの機能テストは区別する。
