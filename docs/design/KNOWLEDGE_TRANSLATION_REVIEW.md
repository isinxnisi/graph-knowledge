# 訳文の意味一致確認と公開文脈

2026-11-06 R1i。[生成と再利用](KNOWLEDGE_TRANSLATION_GENERATION.md)に加え、手入力／生成後に編集した訳文の確認にも、同じ公開原文・周囲の固定文脈を添える。自動生成だけで公開しない契約は維持する。

## 受付と送信

- 対象・項目・原文・原語に加え、対象名・分類・関係の主語／相手・肯否・限定・資料名を、知識DBのrepeatable-readで取得する。ブラウザから文脈や取得版を受け取らず、既存の認証付きcapture／saveでサーバーが解決する。
- 生成と同じ24,000字以内の公開文脈を、会員投稿の不変なreference_contextへ保存する。reviewContext・hashと、使用したEntity／Record／Source／Themeの固定参照を持つ。既存JSON列を使い、追加migrationはない。未共有Capsule、会員情報、無関係な記録を送らない。
- translation-equivalence-v2-contextでは、原文と訳文に加えこの文脈を未信頼データとして送る。文脈は曖昧さを解く材料であり、原文への追記・新事実の根拠・公開指示にはしない。
- 関係語はsubjectIdからobjectIdへの述語として解釈する。例えばA possibly influenced Bを「影響を受けた可能性がある」とする訳は向きが逆であり、支持しない。自然な言換えは許し、具体的な役割・否定・不確実さを残す。
- 共通projectの回数／token予約、本人の同意・取消、提出版、有限再試行は既存のまま。別AIや有料fallbackを増やさない。0.8Bの任意ヒントを必須ゲートへ変えない。

## 受理と再開

1. 送信直前に原文・公開文脈・hash・依存する版を再取得して一致を確認する。資料や対象が非公開なら送信せず、決定的な変更は補足依頼へ戻す。DB接続障害は再試行とし、内容の不受理へ変えない。
2. 通常の自動受理では、保持した送信wireとdigest、policy、選択原文／訳文／文脈hashの一致を確認する。旧policyの結果を新方式の判定として受け入れない。既存の任意運営救済でも公開文脈の検査は省略しない。
3. 公開transactionでは使用した対象・資料等に共有lockを取り、公開状態と同じ固定文脈を再検査する。判断に使った文脈とhashをpublication proofへ保存する。事実の原文・端点・既存Record版を訳文で書き換えない。
4. 確定準備後に停止して再開しても同じproofを照合する。すでに知識transactionが確定したもののACK回収は従来のidempotence契約を維持する。

旧草稿・旧判定・過去の訳文・利用量は削除しない。文脈がない未完了の依頼は推論を繰り返さず、草稿保存と再依頼を案内する。保存時に新しい公開文脈をサーバーで取得する。公開済みの訳文や保存済みCapsuleを一括更新しない。

## 検証と残る範囲

意味一致の実AI評価には正しい役割訳、逆向きの不確かな影響、文脈中の命令を使う。少数例の成功を翻訳全般の精度保証にはしない。初回の逆向き見逃しと補修後の結果を区別して残す。
