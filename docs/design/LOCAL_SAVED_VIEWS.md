# ブラウザ内の保存ビュー

2026-10-09採用・ローカルprototype。[Capsule構想](CAPSULE_AND_USER_CONTRIBUTION_VISION.md)と[保存ビューの提案](EXPLORATION_PRESETS_REVIEW.md#会員の保存ビューと再現性)に沿って、起点と確定条件を保存・再訪する最初の体験を実装する。会員保存・同期・公開共有・Capsule・探索途中のワークスペースは未実装。

## 目的と範囲

直前一件の復帰は画面再読込で失われる。関心のある対象と条件へ後日戻るには、明示保存と名前付きの入口が必要になる。まず既存KGを変更しない同ブラウザ内の保存で試せるようにする。認証・PostgreSQLの完成を前提にしない。この試作の利用可能性は会員／有料機能の境界を決定しない。

検索ペインとGraph起点欄の「保存・再訪」から同じ一覧を開く。起点ありなら、適用中の条件を名前付きで追加できる。未適用draft・選択中のEntityは保存条件／起点にしない。一覧から開く・削除ができる。保存成功・保存不可・起点確認失敗を明示する。表示文言はlocale境界を持つ。

## 保存契約

- 同一originのlocalStorage、dataset別のキー `graph-knowledge:saved-views:<dataset>`。画面再読込後も残るが、別origin・別ブラウザ・別端末へ同期しない。ブラウザのデータ削除で失われる。
- collectionはversion=1、dataset、views。各viewはUUID、利用者のtitle（trim後1〜80 UTF-16 code units）、rootId、具体的な4条件、createdAt。datasetごと20件まで。
- 条件はPredicate集合・制作Role・組織立場・Event参加立場。nullと空集合を区別し、現行の条件正規化を使う。facet名や表示labelから条件を再解決しない。
- Entity名は名前欄の初期値に使うだけ。知識データの複製としてEntity・Claim・Source・受理ページ・cursorを保存しない。枝の開閉・選択・座標・pan/zoomも保存しない。
- 入出力をschema検証。未知version／語彙／dataset不一致／破損は自動削除・上書きせずエラーにする。v1は現在の語彙・条件意味を前提とするため、将来の語彙／意味変更時は版互換・migrationを再検討する。結果の過去再現は保証しない。
- 書込み成功後だけ画面へ反映。容量不足や保存禁止は失敗として表示し、既存データを保持する。追加・削除前に最新一覧を再読込し、storage eventで別タブの変更も反映する。同時書込みのトランザクション保証はなく、完全に同時の更新は後勝ちとなり得る。共同編集向けの保存基盤ではない。

## 開くときの遷移

1. 現行のEntity APIで起点を取得・IDを確認。確認中は現在の探索を維持し、ダイアログを閉じると通信を中止する。404や通信失敗で保存ビューは消さず、再試行できる。
2. 成功した時だけ起点＋全確定条件を一世代で適用する。現在の探索を既存の一件snapshotへ保持し、旧近傍通信を中止する。
3. 保存した起点の近傍を、cursorなしで一段階だけ再取得。同一起点・同条件でも現在データを読み直す。近傍失敗は既存のGraph内再試行を使う。
4. 開く前に探索していた場合、「直前の探索へ戻る」で受理済みGraph・条件・表示位置へ戻れる。再読込直後など元の探索がなければ復帰ボタンは出さない。

DB・API・Claim同一性・datasetの受入境界は変えない。起点削除／統合時の自動付け替えは行わない。認証や更新可能KGの導入時には、現在の認可と参照失効を別途設計する。

## 検証と次の境界

保存schema・dataset分離・空条件・未知語彙拒否・件数上限・保存拒否・404／503／遅延応答・三限定の原子的遷移・直前復帰をunit/componentで検証する。ブラウザテストは既存API応答fixtureを使い、390px／1440pxで保存・再読込・条件付き再訪・失敗・復帰・削除・Escape/focusを検証する。新規実データの受入や人間の使い勝手評価を代用しない。

枝・配置の再開は別の保存ワークスペースとして次に比較できる。会員同期／公開共有への移行では保存先・所有者・閲覧認可・importを設計する。本実装はそれらの採用を約束しない。

2026-10-09の実検証：通常テスト285件、型検査、lint、build、差分検査が成功。保存用15件は最終schema変更後にも再実行して成功。Playwrightの保存ビュー2件（390px／1440px）と画面確認に加え、本番buildで保存・条件復帰・Graph表示操作の6件が成功した。開発serverで初回近傍通信の中断が一度発生したが、保存テストの再実行と本番buildでは再現しなかった。再発時は初回取得のライフサイクルを追跡する。実DBとの結合・実データでの使い勝手・人間受入は今回の検証範囲外。
