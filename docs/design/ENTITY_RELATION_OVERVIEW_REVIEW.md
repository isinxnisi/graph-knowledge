# Entityの関係俯瞰と起点切替のUXレビュー

2026-10-04。**設計提案、未採用・未実装**。[複数分野のレビュー](CROSS_DOMAIN_EXPLORATION_REVIEW.md)への補足。今回はコード・操作契約・API・docsを照合し、文書だけを更新する。

## 結論

**関係概要を任意に確認し、必要なら新しい起点へ進む体験には採用価値がある。** 未知の対象へ到達した時、現在の探索条件や取得済みページでは見えない関係の種類を知り、探索の向きを判断できるため。

推奨は「関係概要を見る」という明示ボタンから開く小さいモーダルと、同じ操作へのダブルクリックのショートカット。概要を見ることを起点切替の必須手順にせず、対象を知っている人は直接切り替えられるようにする。右ペインの選択詳細・Graph・起点・条件は概要の開閉で置き換えない。

概要は現在のGraphの集計ではなく、**現在のdatasetで閲覧可能な登録Claimを、追加の探索条件なしで集計したもの**を推奨する。関係先・Claim・Sourceを全件取得せず、predicateと視点、肯否別の主張件数、制作関与だけの小さいRole概要に限定する。新しいtaxonomyは不要。

次フェーズ案は「任意の関係俯瞰 → 明示的な起点切替 → 直前探索への復帰」を一つの小さい経路として扱う。概要だけを先に薄く実装・検証し、その後に切替と復帰を接続する。今回のレビューでは実装範囲を確定・承認したものとはしない。

## 2. 俯瞰・詳細・起点切替の責務

| 操作 | 答える問い | 変えるもの |
| --- | --- | --- |
| 通常の選択・展開 | 今の探索の中で、誰・何へ繋がるか | 現在選択と、同じ条件の受理ページ・表示Graph |
| 関係俯瞰 | この対象について、どんな主張が登録されているか | 俯瞰対象ID・概要取得状態だけ |
| Claim詳細 | この主張の肯否・期間・限定・根拠は何か | 詳細対象。Graphの起点は変えない |
| 起点切替 | この対象を、どの条件で新しい主題にするか | 起点＋確定条件＋探索世代。元の探索を復帰用に保持 |

「この人は何をしている人か」には既存の登録説明を補助表示できる。関係概要が答えられるのは登録された主張の種類であり、完全な人物紹介ではない。制作Roleから職業を生成せず、影響の件数で人物の重要性を評価しない。

未知の対象では俯瞰が役に立つが、既知の作品を主題にしたい人には追加確認が負担となる。概要は任意の中間ステップとし、全員にモーダルを経由させない。概要を閉じると現在の探索へ戻るだけで、枝を閉じたり、探索条件を適用したりしない。

## 3. ダブルクリックに関する重要な制約

現在の未選択Nodeへダブルクリックすると、最初のクリックで選択と通常の展開が始まり、二度目で俯瞰を開く。背面のGraphがリセットされることはないが、最初の展開の応答でNodeが追加され得る。概要表示中に進行中の展開が完了することもある。

したがって、**ダブルクリックならGraphが完全に不変、とは約束できない**。これを実現するために最初の選択を300ms待たせたり展開を巻き戻したりするのは、現在の応答性・操作契約を壊す。推奨は契約を維持し、二度目のクリックによる閉じるだけを抑止する。

「関係概要を見る」ボタンは、概要だけを開き、selectEntity／expandを呼ばない。現在のGraphへ対象を追加せずに確認できる導線として使う。将来の検索結果・共有リンクから開く時にもこの意味を使う。

ダブルクリックは補助導線。Entity詳細の明示ボタンからキーボードでも到達できるようにし、操作発見性をダブルクリックだけに頼らない。設定モーダル・閾値変更・doubleClickEnabledをこの機能のために先行実装しない。

モーダルを開く時は待機中のGraphジェスチャーを取消し、背面入力を止める。既に受理した枝は保持し、通常の進行中取得は取消し・巻き戻ししない。モーダルを閉じることによる追加取得は行わない。

## 4. UIの比較と推奨

| 案 | 利点 | 負担・判断 |
| --- | --- | --- |
| 右ペインへ常時概要を追加 | 操作が少なくGraphと同時に読める | 選択ごとの集計通信と縦の情報量が増える。Phase 07の詳細整理を圧迫する |
| 右ペイン内の任意切替 | 既存領域だけで成立する | 元の詳細表示やスクロールの復元が必要。将来頻繁に使われるなら再評価できる |
| 明示操作から小さいモーダル | Graph・右詳細を維持し、短時間の判断に集中できる。検索等からも同じ形で使える | 背面操作を一時停止する。フォーカス／Escape／復帰の契約が必要。今回の推奨 |
| 独立ページ／大きな新ペイン | 多い情報や直リンクへ拡張できる | 今回の概要量には重い。URL・履歴・画面構成を同時に増やすため後回し |

初回モーダルの内容案：名称、kind、短い登録説明、登録範囲の注記、predicate別概要、任意の制作Role概要、閉じる、起点切替の二つの操作。人物の全プロフィール、関係先一覧、出典一覧、比較表は載せない。

読み込み・取得失敗・再試行・登録主張なしを明示する。概要取得失敗を「関係なし」にしない。概要が失敗しても閉じてGraphを続けられ、対象が確認できている限り起点切替は可能とする。集計の成功を次の操作の必須条件にしない。対象が削除・閲覧不能で404となった場合は起点切替を行わず、閉じる操作と状態説明を提供する。UUID不正は400、接続不能・予算超過は503、予期しない失敗は500という既存方針を使う案。

Escapeと明示閉じるボタンで取消し、開いたボタンへフォーカスを戻す。Graphから開いた場合はGraph領域等の実在する操作先へ戻す。詳細paneを置き換えず、選択・pan/zoom・座標を概要のために再配置しない。モーダルは同時に一つとし、条件編集との重なりを許さない。

## 5. 何を集計するか

見出しは例えば「このデータセットに登録された関係概要」。近くに「公開されている登録主張の集計です。現在の探索条件では絞っていません。未登録の関係は含みません」と表示する。実世界の全関係や、確認された肯定事実の一覧として見せない。

### predicateと視点

最初は正確なpredicateごとに、対象がsubjectかobjectかを分ける。例として人物のINFLUENCED_BYは「影響を受けた関係についての主張」と「影響を与えた関係についての主張」。後者は同じ保存Claimを対象側から見た表示であり、逆向きのClaimを生成しない。

人物・作品・組織で表示が違っても同じ集計契約を使う。作品のCONTRIBUTED_TOは対象側の制作関与、組織のAFFILIATED_WITHは対象側の関わり。eventはkindとしてあるが現在接続predicateがないため、将来の出来事探索が実装済みとはしない。許容端点外の行は推測して生成しない。

「アシスタント等の人物関係」「家族」といった未定義カテゴリへまとめず、初回は既存4 predicateの順方向／逆方向表現だけを使う。必要になってから分類を検討できる。

### 件数と肯否

- 数えるのはDISTINCT Claim ID。Source数、相手Entity数、DisplayRelation数とは別。
- 表示例は「登録主張3件：肯定2／否定1」。これは架空の構成例。3人、3本のGraph線、独立した3資料を意味しない。
- 肯定・否定を別に示す。否定だけでも概要行は存在するが、「その関係が成立する」とは表示しない。
- 同じ三つ組の複数Claimや旧広いClaim／Role付きClaimは別件として数える。主張件数を根拠の強さや実績数へ変換しない。
- 同じClaimがsubject／objectの両視点に現れる自己関係を扱う場合、各視点では1件、全体総数は1件。初回は総数表示を必須にしない。
- 期間・scopeが違う主張を集計できるが、同時に成立したと断定しない。「異説あり」「矛盾」とは集計から判定しない。

### 制作Role

CONTRIBUTED_TOの行に限り、既存Role ID別の肯否件数と「役割を限定していない主張」を区別して概要にできる。Roleなしを「全Role担当」や「担当不明という事実」に変換しない。

「監修の主張：肯定0／否定1」は、監修した人物が存在する一覧ではない。複数Roleや異scopeを比較する詳細は従来のClaimへ戻す。概要には「巻・版などの限定は個々の主張で確認」という短い注記を置き、集計を全巻・全期間の担当認定にしない。対象が作品でもRoleは人物の関与を限定する値のまま。

初回Role表示は小さい概要の補助。Roleによる起点切替・新Role・科学Role・独自カテゴリは追加しない。情報量が多ければ制作行の開閉内へ置けるが、正確な種別と肯否を保つ。

## 6. 必要な取得データと層

Graphの取得済みページから作った概要は「取得済み範囲」に限られ、現在条件の外の関係を知る今回の目的を満たせない。neighborsを無条件で全ページ取得する案は、相手Entity・Claimを大量転送し、概要と探索の上限／cursorを混同する。そのため小さい専用の読取集計を推奨する。

**API案（未実装・未確定）**：`GET /api/entities/{id}/overview`。既存Entity詳細・neighborsの返却型を変えず、明示的に概要を開いた時だけ取得する。

必要な論理データ：対象のEntitySummary、dataset識別、集計範囲が公開・追加条件なしであること、predicate＋subject/object視点別の肯定／否定Claim件数、制作行だけのRole別件数と無限定件数。relation先ID・全Claim ID・Citation・Source・cursor・Graphの座標は返さない。具体JSON名は実装前に確定する。

- サーバーquery層：対象IDをパラメータ化し、両方向の閲覧可能なClaimを重複排除して集計。Citation／SourceへJOINして件数を水増ししない。条件付き探索のpredicate／Roleを受け取らない。
- サービス／domain境界：正確なpredicate・Role IDs、視点、非負整数を検証しDB表現を返却型へ変換。表示labelを取得条件に使わない。
- presentation／locale：順方向／逆方向、肯否、登録範囲、無限定の説明を解決。名前や件数から新しい分類を生成しない。
- UI：GraphStateとは別に概要対象ID、loading／error／取得結果、要求識別を管理する。モーダル閉鎖・対象変更で概要要求を取消し、遅い応答を旧対象や新探索へ混ぜない。Graphのpendingとは分ける。

将来検索結果やテーマ入口からも、Entity IDだけで同じ概要を開ける。この価値はあるが、検索API・共有URL・テーマ機能を今実装する必要はない。現在選択や起点を概要対象IDで代用しない。

### 軽量という言葉の限界

返却量は種別数に依存し、現在は小さくできる。ただし集計自体は対象のClaimを走査するため、高次数の対象では無条件に安いとは限らない。DBの既存読取予算・タイムアウトを守り、性能は実測する。

neighborsのLIMITやGraphの100 Entity／200 Claim上限を集計前に適用すると、後ろのページの種別を見落とす。初回は正確な集計が予算内に完了しなければ503等で取得不能を示す。サンプルを完全な概要として返さず、失敗をゼロ件にしない。事前集計・別索引・汎用統計基盤は先行導入しない。

今は公開範囲を集計し、将来の認可は詳細取得と同じ範囲へ揃える。非公開Claimや隠れたRoleの件数を漏らさない。datasetを跨いだ混合集計はしない。現在はno-storeを基本とし、永続キャッシュやDB版のスナップショット再現を約束しない。

## 7. 概要から起点切替へ

「広く見る」は対象IDと追加条件なしを一度に確定し、概要を閉じ、新しい探索へ進む。「同じ条件で見る」は現在の確定条件を使う。概要表示中のdraftを適用しない。どちらもCROSS_DOMAINの原子的な起点＋条件切替、旧通信破棄、直前探索の復帰契約へ接続する。

条件が無指定なら二つは同じ実効条件になるので、重複するボタンを減らせる。現在条件が空predicate／空Roleでも「同じ条件」はその意味を維持する。概要に種類があるからといって条件を勝手に補うことはしない。

起点切替時の復帰記録は**実際に切り替える直前の探索**を保持する。概要を開いた時点で凍結しない。ダブルクリックの最初の展開が完了していれば、その受理済み範囲も含む。モーダルを閉じただけでは復帰記録を作らず、元の探索へ戻る操作でも概要を自動再表示しない。

「この関係で見る」「別の軸で見る」は、概要で見たpredicateを条件に解決する将来導線として自然。ただし今回の最小案には含めない。Role行を押しただけでRole条件を適用する機能も追加しない。件数表示を条件編集の代わりにしない。

## 8. 次フェーズに含めるか

| 案 | 適する目的 | 判断 |
| --- | --- | --- |
| 起点切替＋復帰を先行、概要を後で追加 | 遷移・状態復帰だけを最短で確認したい | 技術リスクを分けられる代替案。ただし未知対象での判断材料が不足したまま |
| 概要だけを先行し、起点切替を後へ | 概要の理解・集計性能だけを検証したい | 小さいが、俯瞰から行動を選ぶ目的を最後まで試せない |
| 最小概要＋起点切替＋直前復帰 | 俯瞰して主題を変え、元の枝へ戻れる体験を検証したい | **今回の推奨**。実装を三段階に分け、途中で範囲を膨らませない |

最小範囲は明示ボタン、任意ダブルクリック、小さいモーダル、専用集計、正確なpredicate／既存Role概要、二つの起点切替意図、直前1件の復帰。全プロフィール・関係先一覧・分類・preset・一般検索・新predicate・新Role・保存／共有・詳細の全面刷新は含めない。

実装前に固定する事項：具体API型、件数単位と肯否表示、modalのフォーカス復帰、ダブルクリック初回展開の扱い、直接切替導線、概要取得失敗時の操作、直前復帰の予算／失効。同一起点・同条件の場合の不要なリセットも避ける。

検証順：まず登録種別集計（現在条件外、未取得ページ、複数Citationでも件数不変、複数Claim、否定だけ、Roleなし／あり、人物／作品／組織、ゼロ件、非公開除外）。次にボタン経由でGraph不変、未選択／選択済みダブルクリックの初回展開と開閉抑止、Escape・失敗・再試行。最後に切替・戻るの座標／選択／pan/zoom／共有枝／通信途中の回帰を確認する。
