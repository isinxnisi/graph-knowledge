# ブラウザ内の探索途中保存

2026-10-09採用・ローカルprototype。[保存ビュー](LOCAL_SAVED_VIEWS.md)は起点と条件へ戻れるが、展開した枝と配置は失われる。探索途中の保存は、同じ調査の続きを進めるための参照・表示状態を保持する。[Capsule構想](CAPSULE_AND_USER_CONTRIBUTION_VISION.md)の保存ワークスペースに相当し、独立した知識・仮説を作るCapsuleではない。

初回はdatasetごと1件の保存・再開と専用JSONの持ち運びを実装した。1件では別の調査を保存するたびに以前の続きを置き換える必要があったため、同日、最大10件の追加・選択・再開・置換・削除へ拡張した。保存・再訪と途中保存の入口の統合は今回含めない。

## 今回触れる体験

検索欄とGraph起点欄の「探索途中を保存・再開」でダイアログを開く。現在の探索へ名前を付けて新しい1件として追加する。保存・置換は現在のGraphと名前欄の内容を使い、未適用の条件draftは含めない。自動保存・履歴・会員同期・公開共有は行わない。

保存済みの途中は、名前・保存日時付きの選択欄から1件を選ぶ。選択中の名前・時刻・条件・枝数・取得ページ数を表示し、再開・置換・削除・書出しの対象とする。初回表示は先頭、追加・置換・取込成功後はその保存を選ぶ。同名や同条件でも別件として保持する。置換ボタンに対象名を明示し、削除は対象名の確認と取消を挟む。削除後は他の保存を自動選択せず、選択欄（空なら名前欄または閉じるボタン）へfocusを戻す。

再開中は進捗と中止操作を表示し、全取得が成功するまで現在の探索を維持する。選択変更・保存操作は無効。閉鎖・Escapeも中止。成功後はGraphへ移り、以前の探索があれば「直前の探索へ戻る」で元の受理Graphと表示位置へ戻れる。Graph上の選択対象は保存せず、再開時は起点を選択する。

## 永続化の境界

- 同originの `graph-knowledge:workspace:<dataset>` を使う。保存領域はcollection v2 `{ version: 2, dataset, workspaces }`、各要素は従来どおり途中保存v1。datasetごと最大10件とし、追加・置換成功分を先頭に置く。他の保存の順番と内容は維持する。
- 各要素はdataset、毎保存で新しいUUID、名前、保存日時、起点UUID、確定した四条件、枝の意図、表示位置を持つ。UUIDはローカル保存の版であり、知識のidentityではない。名前の初期値は起点名だが、現在のEntity名の正本として使わない。
- 枝はEntity UUID・open意図・受理済みページ数のみ。明示的に閉じた枝と、祖先の閉鎖で休止中だがopenの子孫を区別する。既存一時キャッシュから既に破棄された枝は含めない。
- 取得中は保存不可。失敗・blockedな取得の未受理ページは数えない。保存されたopen意図に受理ページがなければ、再開後に明示再試行を案内し、自動取得しない。
- Entity／Claim／Source本文、Claim ID一覧、受理ページ本文、古いcursor、通信・エラー・選択・操作履歴は永続化しない。知識の完全な過去再現を保証しない。
- 座標は一時キャッシュ内のEntity UUIDだけに限定。pan／zoom／初期配置済み状態を保存し、現在も取得できるEntityの配置を再利用する。新しく取得した対象は既存の配置補完を使う。
- 保存・読込をstrict schemaで検証する。未知版・語彙・キー・dataset不一致・重複保存UUID／枝・不正な座標／倍率・破損は上書きや自動削除をしない。一部だけを受理しない。名前はtrim後1〜80 UTF-16 code units。
- 各保存は合計40ページ・最大400枝／座標、compact JSONで100,000 bytes以内。collection読込は1,004,096文字以内に加え、全要素のファイル予算も検証する。再開時は表示100 Entity／200 Claim、一時取得400 Entity／800 Claimを維持する。10件はローカルprototypeの予算であり、会員／課金プランを決めない。
- 追加・置換・削除前に最新一覧を読み直す。置換・削除では確認したUUIDが残っていなければ競合として止める。対象以外の保存や別タブでの追加を維持し、追加後の10件上限を検査する。満杯でも選択した1件の置換・削除は可能。
- 書込みは一回のsetItem（最後の1件の削除はremoveItem）で行い、成功後だけ画面へ反映する。容量不足・保存禁止では元の保存を保持する。storage eventで一覧を反映するが、選択中のUUIDが消えたら別件へ勝手に切り替えない。再選択または明示再読込を案内する。
- localStorageに原子的な比較更新はなく、完全同時の書込みは後勝ちとなり得る。共同編集向けの同期基盤ではない。

## 現在の知識からの再構成

1. 起点を現在のEntity APIで取得・ID確認する。
2. 画面外に空のGraphを作り、保存された四条件を一括適用する。既存の表示用snapshotをそのまま永続化しない。
3. 起点から取得済み応答の参照を辿り、保存された枝だけを逐次取得する。各枝はcursorなしから始め、今回返ったnextCursorだけを使い、保存ページ数まで読む。APIの現行既定ページサイズ20がv1の前提であり、変更時は互換性を再検討する。
4. 現在の結果が短ければそこで止め、続きが増えても保存数を超えて自動取得しない。最新のhasMore／cursorを残し、再開後の通常の「続きを取得」へ繋ぐ。
5. 閉じた祖先のページも参照取得に使って休止子孫を構成する。現在の関係から辿れなくなった枝は取得せず、件数をGraphの通知で明示する。失われた枝を独立起点へ昇格しない。保存自体は書き換えない。
6. 応答のschema・中心ID・端点・条件一致・cursor進行を検証し、一時取得の上限を確認する。全取得後に保存open意図から既存projectGraphで表示を導出し、表示上限を検査する。
7. 成功時だけ一世代で画面へ適用し、旧探索の通信を無効化する。途中の404／通信失敗／不正応答／上限超過では部分適用しない。起点統合・削除を自動付け替えしない。

各要求の既存15秒制限に加え、復元全体を60秒で中断する。中止後の遅延応答は適用しない。新しい知識が復元中にも変更される場合の一貫した版スナップショットや認可モデルは、更新可能KG・認証の導入時に別途設計する。現在の読取APIは変更しない。

## 旧1件からの移行と戻し方

同じ保存キーの旧途中保存v1は、1件の一覧として検証・表示する。読む・再開する・書き出すだけでは保存領域を書き換えない。初めて追加・置換したときに、検証済みの全一覧を一回のsetItemでcollection v2へ移す。旧保存を選択して置換・削除した場合以外は、そのUUID・名前・日時・条件・枝・配置を維持する。最後の1件を明示削除した場合はキーを除去する。移行中の保存拒否で元のv1を先に消さない。

旧アプリはcollection v2を未知形式として拒否し、上書きしない。旧版へ戻す必要がある場合は、新版で必要な各保存を途中保存v1 JSONへ書き出してから、旧版を空の別ブラウザ保存領域で開き、明示ファイル読込で1件を選んで戻せる。同じ保存領域のv2へ旧版から上書き取込することはできない。複数件を旧1件へ暗黙に縮約しない。DB migrationは不要で、凍結dataset・Claim identity・Predicate・qualification・provenance・Global／Capsuleの境界は不変。

既存の保存ビューcollection v1とそのJSON控えは変更しない。途中保存は別キー・別ファイル形式であることを画面でも明示する。会員保存・共有・Capsule・実データでの操作評価・人間受入は今回の完成条件に含めない。

## 途中保存のファイル持ち運び（2026-10-09追加）

ダイアログ末尾から、選択した1件を専用JSONへ控え、同じdatasetの別ブラウザで再開できる。ファイル操作はブラウザ内だけで行い、自動同期・公開・KGへの取込は行わない。

- 書き出し時に最新のlocalStorageを再読込・検証し、選択したUUIDの途中保存v1をcompact JSONでダウンロードする。ファイル名は`graph-knowledge-workspace-<dataset>.json`。未保存の現在Graphや一覧全体は書き出さない。選択した版が消えていたら別件を代わりに書き出さず拒否する。
- 読込前に100,000 bytes以下を確認し、読込後にもUTF-8 bytesを検査する。strict schema・40ページ／400枝・座標／倍率・未知語彙・datasetを再検証する。従来の途中保存v1 JSONをそのまま受け入れる。collection v2そのものや保存ビューJSONはファイルとして受け入れない。
- 既定では新しい1件として追加する。置換したい場合は、一覧から対象を選び、対象名付きのチェックを入れてからファイルを選ぶ。確認画面はファイル名・dataset・名前・保存日時・四条件・起点UUID・枝数・ページ数を示す。置換の場合は対象名も再掲し、書出しによる控えを案内する。
- 名前はファイルのタイトルとして扱い、Entity名や存在の認定に使わない。起点なしでも読込できる。確認前の選択・取消・再選択・閉鎖はGraphや保存を変更せず、遅延した読込結果を排除する。
- 確認ボタンを押した時だけ元ファイルと最新保存一覧を再検証する。追加は最新一覧を維持して10件上限を再検査、置換はファイル選択時の対象UUIDへ固定する。確認中に他の保存を選んだり、対象が別タブで更新・削除されたりした場合は再確認を求める。storage event未到着でも書込前のUUID比較で拒否する。対象以外の更新・追加は置換を妨げず保持する。
- 取込成功ごとに新しいUUIDを付ける。同じファイルの再取込も新しい版となり、追加なら別件として残す。名前・保存日時・起点・条件・枝・配置は検証後の値を保持する。UUIDは知識のidentityやprovenanceではない。成功後は追加モードへ戻す。
- 読み込みだけではEntity APIを呼ばず、現在Graphを変えない。既存の「保存した途中を再開」を押した時だけ現在データから再構成する。ファイルは現在の関係や根拠の正しさを保証せず、再開時の失敗・中止・直前復帰の契約も維持する。

## 検証

単体／componentで保存schema・旧形式の無書込読込／移行失敗・一覧とdataset分離・10件上限・選択版の競合・保存拒否を確認する。閉鎖／休止子孫・ページ上限・最新cursor・四条件・未知応答・中止・全体timeout・原子的切替・直前復帰も維持する。

ファイルでは最大サイズの往復、未知形式・別dataset・容量不足、取込ごとの版更新、追加と選択した1件の置換、確認後の競合、取消・再選択・閉鎖後の遅延読込を確認する。ブラウザではAPI応答fixtureを使い、390px／1440pxで複数保存・選択・再読込・再開・置換・確認削除、実ダウンロードから独立した保存領域への読込・競合、枝と配置・pan／zoomの再開、Escapeとfocusを確認する。実施結果はAUTOPILOT_HANDOFFに記録する。
