# ブラウザ内の探索途中保存

2026-10-09採用・ローカルprototype。[保存ビュー](LOCAL_SAVED_VIEWS.md)は起点と条件へ戻れるが、展開した枝と配置は失われる。今回は同じ調査の続きを進められるよう、datasetごとに探索途中を1件保存する。[Capsule構想](CAPSULE_AND_USER_CONTRIBUTION_VISION.md)の保存ワークスペースに相当し、独立した知識・仮説を作るCapsuleではない。

## 今回触れる体験

検索欄とGraph起点欄の「探索途中を保存・再開」でダイアログを開く。名前を付けて保存し、再読込後にも同じ入口から再開する。既存保存があれば現在の探索で置き換えることを明示したボタンに変わる。保存時点の名前・時刻・条件・枝数・取得ページ数を確認でき、削除できる。自動保存・履歴・会員同期・公開共有は行わない。

再開中は進捗と中止操作を表示し、全取得が成功するまで現在の探索を維持する。閉鎖・Escapeも中止。成功後はGraphへ移り、以前の探索があれば「直前の探索へ戻る」で元の受理Graphと表示位置へ戻れる。選択対象は保存せず、再開時は起点を選択する。

## 永続化の境界

- 同originの `graph-knowledge:workspace:<dataset>` にversion=1、dataset、毎保存で新しいUUID、名前、保存日時、起点UUID、確定した四条件、枝の意図、表示位置を保存する。名前の初期値は起点名だが、現在のEntity名の正本として使わない。
- 枝はEntity UUID・open意図・受理済みページ数のみ。明示的に閉じた枝と、祖先の閉鎖で休止中だがopenの子孫を区別する。既存一時キャッシュから既に破棄された枝は含めない。
- 取得中は保存不可。失敗・blockedな取得の未受理ページは数えない。保存されたopen意図に受理ページがなければ、再開後に明示再試行を案内し、自動取得しない。
- Entity／Claim／Source本文、Claim ID一覧、受理ページ本文、古いcursor、通信・エラー・選択・操作履歴は永続化しない。知識の完全な過去再現を保証しない。
- 座標は一時キャッシュ内のEntity UUIDだけに限定。pan／zoom／初期配置済み状態を保存し、現在も取得できるEntityの配置を再利用する。新しく取得した対象は既存の配置補完を使う。
- 保存・読込をstrict schemaで検証する。未知版・語彙・キー・dataset不一致・重複枝・不正な座標／倍率・破損は上書きや自動削除をしない。名前は1〜80 UTF-16 code units、読込文字列は100,000文字以内。
- 1件・合計40ページ・最大400枝／座標に制限する。再開時も表示100 Entity／200 Claim、一時取得400 Entity／800 Claimを維持する。これは限定prototypeの予算であり、将来の会員／課金プランを決めない。
- 保存・削除前に最新データを読み、画面で確認していたUUIDと異なれば競合として止める。書込み成功後だけ画面へ反映する。storage eventも反映するが、localStorageに原子的な比較更新はなく、完全同時の書込みは後勝ちとなり得る。

## 現在の知識からの再構成

1. 起点を現在のEntity APIで取得・ID確認する。
2. 画面外に空のGraphを作り、保存された四条件を一括適用する。既存の表示用snapshotをそのまま永続化しない。
3. 起点から取得済み応答の参照を辿り、保存された枝だけを逐次取得する。各枝はcursorなしから始め、今回返ったnextCursorだけを使い、保存ページ数まで読む。APIの現行既定ページサイズ20がv1の前提であり、変更時は互換性を再検討する。
4. 現在の結果が短ければそこで止め、続きが増えても保存数を超えて自動取得しない。最新のhasMore／cursorを残し、再開後の通常の「続きを取得」へ繋ぐ。
5. 閉じた祖先のページも参照取得に使って休止子孫を構成する。現在の関係から辿れなくなった枝は取得せず、件数をGraphの通知で明示する。失われた枝を独立起点へ昇格しない。保存自体は書き換えない。
6. 応答のschema・中心ID・端点・条件一致・cursor進行を検証し、一時取得の上限を確認する。全取得後に保存open意図から既存projectGraphで表示を導出し、表示上限を検査する。
7. 成功時だけ一世代で画面へ適用し、旧探索の通信を無効化する。途中の404／通信失敗／不正応答／上限超過では部分適用しない。起点統合・削除を自動付け替えしない。

各要求の既存15秒制限に加え、復元全体を60秒で中断する。中止後の遅延応答は適用しない。新しい知識が復元中にも変更される場合の一貫した版スナップショットや認可モデルは、更新可能KG・認証の導入時に別途設計する。現在の読取APIは変更しない。

## 互換性・戻し方・残る範囲

既存の保存ビューcollection v1とそのJSON控えは変更しない。途中保存は別キーに隔離し、JSON控えに含まれないことを画面でも明示する。本機能を外しても既存保存ビューとKGは影響を受けず、DB migrationは不要。凍結dataset・Claim identity・Predicate・qualification・provenance・Global／Capsuleの境界は不変。

次の候補は複数件の途中保存とファイル持ち運びの統合。まずこの1件prototypeの再開体験を評価できる。会員保存・共有・Capsule・実データでの操作評価・人間受入は今回の完成条件に含めない。
