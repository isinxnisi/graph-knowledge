# テーマ閲覧UI・SEOの刷新

2026-11-10。依頼元は利用者添付 `plunode-codex-spec.md` 改訂2026-11-10と `plunode-ui-reference.png`。本文の「検討用／実装未承認」は作成時の状態であり、今回の利用者メッセージで実装を依頼された。本番公開は別途承認。生成画像内の文章・商品・科学的主張を無検証で公開する指示とは扱わない。

## 工程と今回の終点

1. 仕様・現行実装・公開境界を照合し、情報移動と往復の契約を決める。
2. 閲覧UI、版と言語を固定した編集用表示情報・画像／解説、文脈別商品カード、公開テーマURL／SSR／metadata／OG／sitemapを実装する。
3. 実テーマでPC・狭いPC・スマホ幅、日英、往復・固定版・公開停止・SEO・既存Capsuleを検証し、必要な修正後commit／push、3200／HTTPS βで利用者が比較できる状態にする。

今回は3まで。本番VPSの切替、Search Consoleでの正式URL再クロール、外部アカウント登録・契約・課金は行わない。①→②→③で報告し、途中なら完了と残りを明記する。無関係な自動開発候補、会員・KG・共有データのresetを含めない。

## 実装する読書契約

- 中央は戻る／タイトル／文字付き「このテーマについて」→画像と問い・導入→年表／図→日時なし情報。編集・Capsule・分割操作を維持する。
- 年表閲覧モードは短い主文・時期・対応する名前と関係・出典への入口。種類のバッジは追加指摘を受け撤去し、否定／不確実の状態は保持する。選択で右詳細を更新し、全文・scope・引用・版を複製しない。子年表は別操作で開閉を維持する。編集用の既存展開は分けて保持する。
- 詳細は具体的な見出しと種別→本文→ある場合の根拠付き解説→出典→対象／商品→記録情報。短いscopeは小さな通常注記、長いscopeは下部の補足群に一度だけ置く。scope専用カード・警告・開閉を作らない。
- 記録の選択とテーマ詳細の一時表示を分離する。戻ると同じ記録・時期注釈・出典の開閉・スクロール・フォーカスに復帰する。Graphは再mount／再layoutさせず座標・倍率を保持する。
- 複数出典の指定をevidence IDで扱い、押した出典の引用・該当箇所を開く。既存の版・翻訳・訂正・投稿者・意味対応の到達先を記録情報へ保つ。

## 未決事項は比較試作

テーマ情報は「下部の全件が読める開いた一覧」を基本試作とし、「上部の閉じた小さな入口」と切り替えて比べる。どちらも未確定。件数を黙って打ち切らない。

商品が地域未対応の場合はA「その販売先を出さない」、B「確認済みの別地域・別版だと明示して案内」を比較する。表示言語と購入地域を別に扱い、同じ本の別版／別言語・画像取得エラー・未確認・商品なしを区別する。AmazonアソシエイトStore ID `plunode-22` と本人が発行した商品短縮リンクを受領。2027年版RED EMBER Webbカレンダー（英語、ASIN B0GMV4CK32）への実遷移を確認。Creators API資格・秘密設定は未提供で、書影は転載しない。OneLinkの国別連携設定は未確認。資格や画像利用条件を未確認で有効化しない。実在書籍の検証とUIは独立して進める。

## データ・SEOの実装方針

表示用の問い・導入・短い見出し・解説参照・画像は、対象ID／内容版／言語を固定し、原記録の本文とは分ける。閲覧時AIは使わず、古い解説を改訂後の内容へ黙って適用しない。代表テーマは根拠と実画像を用意し、未収録の観測・知見を補う収集／編集対応を記録する。テーマ専用の画面コードへ文面を埋め込まない。

公開URLは既存管理用`/themes`と分け、`/t/{themeId}`／実在する英訳の`/en/t/{themeId}`を使う。既存Explorer／KnowledgeReadingをSSR初期データで使い、別記事を二重運営しない。可読本文・画像・出典が最初のHTMLにあり、同じ内容が利用者にも見えることを検証する。

旧`?ktheme`は指定版・表示を保持する互換入口。過去版を最新へ送らない。正規URLのmetadata・canonical・index／hreflang・sitemapは現在の公開認可から作り、停止・非公開・限定共有・無限の探索状態を混ぜない。β全体のnoindexは維持し、正式Hostを模した隔離検証と実βの応答を分けて記録する。

## 情報移動の検証表

元の本文／関係方向・肯否、scope、全ての時間と精度、出典の立場、引用・箇所・書誌、原文言語・翻訳、内容／資料／構成版、意味対応、投稿者・訂正、別名・関連テーマ、保存／Undo／戻る、既存広告を対象に、移設先・操作・検証結果を完了記録へ残す。画像だけ似せた状態、仮データだけの状態は完了としない。

## 編集情報の継続方法

`data/theme-reading-presentation.json` は原本と別の表示manifestで、theme ID／構成版／言語と、各record ID／内容版を明示してGitで改訂する。任意のため未整備の記録は既存本文または翻訳済み時期ラベルで読める。現段階で全件手入力や閲覧時生成を必須にしない。元版が変わると対応しない指定は使わず、再確認して新しい版の指定を追加する。根拠付き解説の本文・出典は通常のnote/aboutRecordと原本版／訳文版へ保存し、manifestはその参照と表示役割だけを持つ。将来の運営入力UIは今回新設しない。

代表テーマはβに新IDで追加し、既存テーマ@5・既存KG・会員・自動収集計画は変更しない。導入の問いに対し、NASAの赤外線／初期宇宙の資料、既存の展開記録、ESAの最初の深宇宙画像と重力レンズの解説をつなぐ。独立した発見を水増しせず、初画像により見える遠方銀河・重力レンズという到達点に限って説明する。初期案ではESA/Webbの実画像を使用した。現在の導入は後述の編集挿絵へ置換し、実画像の資材と原資料リンクを保持する。

Creators API設定は任意のowner専用0600ファイル `PRODUCTS_CREATORS_CONFIG`。資格承認後にcredentialVersion/clientId/clientSecret/marketplace別partners/itemsを設定できる。秘密値はブラウザへ渡さず固定APIだけへ送る。画像は許可されたAmazonホスト・取得期限付き、データ15分／画像1時間、通信失敗1分で再確認する。資格未設定・欠品・通信障害・画像未取得は区別し、グラフを待たせない。提供元の実条件は有効化時にも再確認する。

## 追調整：年表の情報密度と見た目の統一

前回の行は、短い見出し・年表用主文・関係対応・種別・同じ日付・出典ボタンを別々に積んだため、代表4件が約197〜231pxになった。2026-11-10の利用者フィードバックを受け、読むための主文を1つ選ぶ（編集済みtimelineSummary、見出し、原文の順）。初期追調整では種別をその主文と同じ流れに置いたが、後続指摘で年表から撤去した。対応するEntityと矢印は次の補助行、出典は枠なしの短い入口へまとめる。複数出典・否定／不確実の状態は保持する。

左軸にある発生日をカード内へ繰り返さず、期間／発生幅の意味・端点は表示し、時期の名前だけは同じカードで重複させない。完全な時期情報とラベルは詳細・既存の図示・アクセシブルな線の名称へ残る。点と期間の描画・順序・命中領域は変更しない。編集用の全文展開は別モードとして継続する。

導入の画像・余白を絞り、テーマ詳細・Record詳細の見出しを同じ書体と階層へそろえる。選択前の右欄はテーマ説明を先に読み、構成版・翻訳は補助情報へ置く。日時なし情報と地域案のA/Bは今回も確定せず保持する。データ・SEO・認可・AI処理・本番配置の変更を含めない。

## 受入の訂正と参考画像との再比較

前2回の実装・テスト成功をもって「完了／残作業なし」と報告したが、参考画像の読む階層に対して、背景の入口、重要性・知見、出典のまとまりが不足していた。利用者が再提示した画面も同じ比較テーマであり、入口の違いを原因としない。受入は未完了へ訂正し、同じテーマ・幅・選択で見た目を比較する。

年表の主文は14px、対象／関係は11px、出典は11pxの一つの操作にまとめる。年表に背景の開閉行や解説のプレビューを作らない。解説は選んだ記録の詳細へ集約する。タイトル・主文の二重積みや全文・引用・scopeの展開へ戻さない。全件へ無意味な背景欄を水増ししない。種別は主文の先頭を押さず、関係対応と同じ補助行に置く。

詳細の解説は背景・重要性・知見を役割で分ける。知見は根拠のある独立したnote参照の一覧として表示し、ない記録には空の箱を出さない。NASA公式RELEASE22-002の遮熱膜の構造・冷却と、展開後にも残る工程を確認し、β比較テーマの新しい構成版2へ4noteを追加する。旧構成版1・元のTheme@5・Recordの本文と時間は維持する。英訳も同じ原文と参照版へ登録し、閲覧時生成を行わない。

導入の画像・問い・説明を一つの淡い面へそろえ、出典のアイコン／題名／立場／引用操作の列を固定する。選択の常時表示はカード全体の淡い面と細い境界、キーボードfocusは別の細線とする。汎用ボタンの強い枠が主文の周囲に残らないことをbuild後の実画面で確認する。

画像は後続の指摘で編集挿絵へ変更した。参考画像の一般的な望遠鏡を実機写真として流用しない。商品画像の資格未確認、日時なし情報と地域案A/Bの未採用はそのまま区別する。今回の追修正だけで当初依頼全体のデザイン採用や本番公開を完了とは扱わない。

詳細を優先する追加指摘を反映し、テーマ概要のタイトル・本文・章見出し・商品カードにもRecord詳細と同じ文字階層を適用する。テーマの構成版は下部の記録情報へ移す。PCの常設詳細欄では同じ図へ戻す冗長なボタンを出さず、ペインが切り替わる狭幅では戻る導線を残す。背景は通常の文章、重要性だけを淡い面、知見は箇条書きとし、同じ温度感の箱を積まない。

### 「読みたくなる表現」の確認

参考画像が出された理由は、情報を並べただけで人間味がなく閲覧意欲をそそらない、という指摘への回答だった。文字サイズ・枠・roleラベルの一致を合格条件にしない。具体的な見出し、問いに応じる段落、読む理由と根拠への自然な順番を確認する。

β比較Theme@3では、5つの自作解説noteを通常のcorrect操作で内容版2へ改訂した。例えば遮熱膜の背景は「テニスコートほどのものをロケットへどう収めたか」、重要性は「かすかな赤外線を捉えるための冷たい環境」、後続の知見は「観測まで残る準備」へ役割を分けた。主張はNASAの公式資料内に留め、未検証の発見・書籍・数値で面白さを補わない。roleだけで決まる汎用章名に加えて、参照版・言語に固定した編集見出しも持てる。

Theme@1/@2・解説note@1を保存し、Theme@3だけがnote@2と対応する英訳を使う。旧版へ新しい解説を混ぜない。`seed-theme-reading-preview.ts`→`extend-theme-reading-preview.ts`→`refine-theme-reading-preview.ts`の順で、専用βDBに限り再現できる。各scriptは既存版を検査し、上位版があれば止まる。稼働中の既存テーマ・収集計画や本番は更新しない。

### 背景の重複表示を取り消す

背景のために一行を占有し、さらにクリックで同じ説明を開かせる案は、情報密度と読書体験を悪化させたため撤回する。年表は出来事・時期・対象の対応・出典への入口に絞る。元からある子年表の展開は、別の情報が増える操作なので保持する。

詳細の背景も汎用見出しを一行足さず、本文につながる補足段落とする。出典は段落末の小さいリンクアイコンから確認できる。繰り返しの事実要約ではなく、なぜ折り畳む必要があったか等の理解が進む補足を扱う。すべての記録に背景・重要性・知見を埋めるルールにしない。

追加指摘：役割ごとに別の枠・見出し・段落規則を割り当てた案も撤回。詳細は本文→「解説」→「出典」→「関係する対象」の共通順序とし、解説は一つの章で同じ本文サイズ・段落間隔を使う。補足roleと編集見出しのデータは保持するが、この表示の章をキャッチコピーへ置き換えない。主題の見出し、本文、章、注記の階層を固定する。

### 内部用語を閲覧の見出しにしない

「対象」の一括置換ではなく、読む場所で何があるかを示す。Recordの関連先は表示用の種類群に応じて「関連する人物・組織」「関連する作品」「関連する機器」等へ出し分け、機器を作品へ誤分類しない。KGの分類・データは変えない。未知の分類を勝手に断定せず「関連する情報」とする。関連テーマは「関連するテーマ」、人物等の詳細からの探索は実際の名前を操作名に含める。左検索は実際の入力に合わせ「名前から探す」、TOPの別入口は「ほかの名前から探す」。日本語／英語を同じ意図で変更する。検索条件等で意味が明確な「検索対象」は機械的に言い換えない。

### 追加一覧と左余白

今回の「段落」は改行の追加ではなく左余白の指定。章見出しのアイコン16px＋間隔7pxに対し、本文・カード・操作・リンクを23px下げる共通sectionを使う。意味のある並列内容の箇条書きを否定する指示ではなく、箇条書きの点は余白に置く。

Entity詳細の二つの重複一覧を一つにまとめ、表示中の固定版を優先し、同じIDの最新公開版を上書き／二重表示しない。テーマ内の記録とほかの公開知識を短い表示で区別し、前者は固定版を開く経路を保持する。関連テーマ→初期3件の関連知識→本・作品→補助情報の順とし、巨大な一覧の後ろへテーマや商品を追いやらない。テーマ・本／作品・下部の解説一覧も初期3件まで、続きは各一覧末尾の独立した操作で段階表示する。

年表の関係／出来事バッジは、本文と対応情報を繰り返し、折返しで行を増やしたため閲覧モードから外す。否定／不確実は残す。詳細の種別は継続する。キーボードfocusは本文の内側を囲わず、行全体へ細い外周を出す。

## 導入の再構成（追加指摘）

小さい写真・クレジット帯・青いリンクの紹介欄は、読書の入口として不採用。透過の編集挿絵、問い、短い導入を一体化する。写真を挿絵へ差し替えるだけでなく、独立した画像枠とクレジット帯を外す。制作情報はテーマ詳細へ移す。TOPでは同じ編集資産の問いを短い紹介として使い、本文descriptionの切取りや同じレイアウトの単純流用を避ける。[資材の制作記録](THEME_READING_VISUAL_ASSETS.md)。
