# U5：受付版への相談と運営例外対応

2026-11-04。利用者の「続けてください」を受け、前回の残件である異議・運営例外と総合確認を進める。通常の投稿を全件の手動承認へ戻さない。本番VPS、既存収集、共通Kev、課金・提供元設定は変更しない。

## 利用者の体験

結果カードの項目から「この結果について運営に相談」を開く。公開後は「公開内容について運営に相談」。普段は短い入口だけを置き、相談文と、この項目・参照資料・確認結果をサイト運営者へ渡すことを明示確認して送る。受付版・項目へ固定し、未選択の内容や個人Capsule全体を運営へ渡さない。匿名の公開表示を選んだ投稿でも、相談者はログインした本人として内部照合する。公開の匿名性は変えない。

一つの受付項目につき相談は一件。受付済みの再送は同じID・同じ内容へ収束し、24時間に5件まで。未対応の相談を取り消せる。取消は相談の閲覧を失効させ、元の知識確認や公開内容を取消しない。回答後に内容を補う場合は新しい草稿・受付版から行う。

回答と処置結果は同じ受付版のカードに表示し、既存の永続未読へ通知する。GETで既読にしない。相談中のカードは約5秒で確認し、一般の通知badgeは既存の最大約60秒の更新を使う。

## 運営の体験と権限

既存 /operations に「知識投稿の相談」を追加する。共通ヘッダーの運営件数へ未対応を加算する。既存のサーバー許可リストと、現在activeな本人・sessionを各読取／書込で再確認する。コミュニティ管理者の権限を広げない。

一覧では状態・受付版・案件番号・時刻のみを示す。「内容を確認（監査に記録）」を明示操作し、その相談で共有された項目だけを読む。根拠の引用は文字として描画する。現在の草稿・未選択項目・メールや会員一覧を探索できる経路にはしない。取消・本人停止／削除・運営権限喪失後に、過去のinspect操作を再送して私有内容を再取得できない。

- 回答して対応終了：元の確認結果・公開内容を変えず、理由と次の操作を本人へ通知する。
- もう一度確認：現在も同じ受付版・未取消・同じ送信先への同意が有効な場合だけ、既存キューへ戻す。過去attempt・結果不明の課金予約・project上限は保持する。
- 運営による内容確認：原資料と事実の支持を人が確認した例外。元のAI結果は書換えず、監査記録を別参照する。原資料の本文照合・現在の公開資格・版・型付き意味・受付本人の再検査を通した後にのみ通常の受理へ進める。書誌のみ／未対応形式／原資料不一致を無条件で通す抜け道ではない。
- 公開停止・解除：受理済み共通知識の現在の公開範囲へ作用する。新しい保存版の作成や私有草稿・独立会話の削除ではない。停止を行った元案件・状態版でだけ解除し、後続の他案件の停止を巻き戻さない。現在停止は既存の公開reader・Capsuleの取得元認可へ適用する。

例外確認・公開停止／解除は、意味を説明した確認欄と投稿者へ返す判断理由を必須とする。内容確認は30分以内の同じ運営者のinspectに限定し、期待案件版・公開状態版を照合する。通信結果不明では同じrequest IDで再確認する。

## データと復旧

追加member migration 026のみ。適用済み000〜025と知識側001/002/004を改変しない。相談は私有の受付・jobへFKで結び、本人削除と連動する。公開内容への確定処置は、所有者情報を含まない別outboxへ保持する。私有の投稿が消えても確定済みの公開操作を失わない。

二つのDBを単一transactionと呼ばない。会員側で期待版を含む公開visibility commandを確定し、既存review workerが同じrequest IDで知識正本へ配達する。適用後の通知は別の完了印を持ち、公開側commit後／通知前の停止も再送で収束する。公開状態競合は勝手に上書きせず、運営へ再確認を示す。回答・原判定・公開した版番号を保持する。

## 今回の境界

一件の相談で追加往復を続けるチャット、一般の知識通報、自動優先度判定、任意の私有投稿を読む運営検索は作らない。公開知識の投稿者表示・活動履歴と、私有の相談・運営監査を混ぜない。現在停止・削除された会員の私有相談は閲覧しない。匿名や退会を理由に共通知識そのものを削除する方式ではない。

既存Entityの名前・別名自体の変更operationは今回も対象外。一般利用者へのAI提供条件と対象者の拡大、U6収集、U7総合移行、U8本番公開は別工程。指定本人の限定βで確認したことを一般公開済みと報告しない。
