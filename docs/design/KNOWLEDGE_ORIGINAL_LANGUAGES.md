# 知識の原語を項目ごとに保存する

2026-11-05。ユーザーの継続指示により、[多言語案](KNOWLEDGE_MULTILINGUAL_PROPOSAL.md)の第一段階を実装する。原語情報の保存・投稿UI・異言語の事実訂正・保存断面の保持が対象。訳文を保存する機能、自動翻訳、訳文だけの訂正は後続であり、現行の事実訂正へ混ぜない。

## 保存契約

既存のJSON内容版へ任意の `textLanguages` を追加する。各値は `{ tag, basis }`。`tag` はBCP 47形式、`basis` は投稿者の指定 `declared` または生成処理の指定 `generated`。言語推定や本文の正しさの証明ではない。過去の内容版・digest・受付・保存済みCapsuleを書き換えない。追加migrationは不要。

| 対象 | 言語を持つ項目 |
| --- | --- |
| Entity | name、description、aliasesの各位置（内容版と一緒に固定） |
| Record | assertion、relation、scope |
| Theme | title、description |
| Source | 原題title、bibliography、原資料本文document |
| Evidence | 原文excerpt、記載箇所locator |

欠落は不明として扱う。歴史的な `language: ja` から本人の指定を作らない。新しく言語未指定で生成するEntity・Sourceは `und`。UI言語や、旧Capsule外側の固定 `language: ja` を原資料の言語へコピーしない。現行の外側のCapsule属性は互換用として残る。

名称・関係・ThemeのIDと、時間・意味分類の構造は言語から独立する。名称や訳名一致によるEntity統合は行わない。新しい名称モデル・訳名検索を実装済みとは扱わない。

## 投稿・表示

本文、矢印、新しい対象名、引用に小さな言語選択を置く。資料本文と原題は任意の折り畳みに置く。最初のUI選択肢は日本語・English・複数言語・未指定。既に保存されている他の言語tagは失わず表示でき、保存schemaでは他言語tagも検査する。日本語UIで英語の本文を入力してもUIは切り替わらない。

言語未指定でも草稿と通常の投稿は保存できる。根拠照合・内容確認・参照版の条件は維持する。言語を指定していないことだけで全件保留にしない。資料本文・原題・引用を別々に持ち、引用を投稿本文の訳文と取り違えない。

公開詳細は指定された本文・関係・引用へHTMLのlangを付け、本文の原語を短く表示する。指定がない古い文を日本語と断定して表示しない。投稿確認へ渡す文脈にも、入力の言語と引用の言語を分けて含める。

## 訂正とCapsule

事実の訂正は同じRecord IDの次版。英語で訂正した場合はその文と原語を次版に残し、旧日本語は旧版のまま保持する。引用と資料pinを勝手に翻訳・差替えしない。訂正者の帰属は既存の公開／匿名規則を使う。

取得文を書き換えたとき、元の作者の言語指定を新しい文の指定と見なさない。投稿画面で元の文から書き換えると、本人が選択した指定がなければ該当欄を未指定へ戻す。Capsuleの投影でも、書き換えた欄だけ言語指定を外す。未編集の関係語・引用、固定した元snapshotの指定は保持する。

訳文だけの訂正は今回の操作に含めない旨を訂正欄へ示す。後続の翻訳版は、対象ID・内容版・項目・訳先言語を参照する別履歴とし、今回の `textLanguages` を訳文や訳者の保存場所にしない。

## 後続

多言語の残りは、短い表示文の翻訳版・訳文訂正・訳者帰属と、Capsuleへの翻訳版固定。その後に、明示依頼による自動翻訳・既存利用枠・cache・実精度評価を接続する。基本は追加2まとまりを目安とする推定で、翻訳の対象や評価結果によって分割する。U6のEntity同一性／Chat取込の残件とは別に進捗を示す。

翻訳比較の機能を原語保存へ先行実装したり、全量のAI翻訳を起動したりしない。現行の事実訂正を、翻訳だけの訂正として案内しない。
