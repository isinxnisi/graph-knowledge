# R4b 時間入力・訳文・固定保存

2026-11-08。R4bはR4の最終区切り。R5の統合受入とR6の正式公開は別工程。直接作図の後続化を、フォーム入力の除外へ広げない。

## 時間の原表現と描画

- 暦は `YYYY`、`YYYY-MM`、`YYYY-MM-DD` に加え、`YYYY-MM-DDTHH[:mm[:ss]][Z|±HH:mm]`。原文字列と精度を保持し、時区を省略した値へUTCや日本時間を付けない。暦の表示単位は年・月・日・時間。分秒を入力した場合も原値は保持し、時間単位の点へ集約して読む。
- 時区指定の日時は指定offsetで照合する。時区未指定の年月日とは独立した軸へ置く。明示配置で混在させる入力も拒否する。投稿からThemeへの自動追加とCapsule独自時期の投影でも同じ境界を守る。
- `expression` は「1991年前期」「5月頃」等の原資料の時期表記。確認できる年・月・境界だけをfrom/toへ入力する。「前期」を1〜6月へ変換しない。境界不明の前期は、年までの位置と原表記を併記する。
- 時点、続いた期間、発生時期の幅、旧来の未区別範囲、開始／終了の不確かな幅は別の意味として維持する。同じ表示単位へ収まる出来事は点として読めても、保存した意味・精度は変えない。
- 共通の時期フォームを会員投稿、Capsule関係編集、運営の共通記録入力／訂正から使う。最大16件の安定ID付き注釈。周期は軸名・一周の長さ・単位・位置・折返し、定性軸は軸名・段階の意味・始終を入力する。未入力の草稿は再開でき、登録時に意味・範囲を検証する。
- 年表構成フォームで、各Recordの各time IDを軸へ置き、定性軸の順序と子軸の親を選べる。子軸は任意の `parentTimeId` を持ち、複数時間の最初の行へ勝手に紐付けない。未指定の旧参照は従来の配置規則を維持。循環・型不一致・3段超過・欠落参照は拒否する。親の時期を外した場合は接続参照も外し、別の時期へ付け替えない。
- Capsuleの独自構成は `knowledge.timeline`。固定取得した `snapshot.timeline` や本線KGを変更しない。作図・直接ドラッグ編集は今回追加しない。

## 原文と訳文

対応fieldはEntityの名前・説明・別名、Recordの本文・関係語・範囲・引用・該当箇所、Sourceの資料名・書誌、Themeの名前・説明。該当箇所への入口を補い、Theme訳も「Capsule用に保持」から保存できる。

旧KGの対象・関係の詳細でも、準備済みの公開原本と訳文は未ログインで読める。未準備の場合だけ、ログイン後に翻訳を開く操作から、公開原本をサーバーで読み同じIDの固定原本として参照する。Origin・会員資格・機能の公開範囲を照合する。利用者から原文payloadを受け取らず、書込直前に公開元を再照合する。既に正本がある場合は上書きしない。本線KGへは書かず、この操作でAI送信・翻訳採用を行わない。

Capsuleは `snapshot.theme` に取得時のTheme原文・版を保存する。Theme参照pinとの一致、訳文の対象原文との一致、サーバー正本とのdigest一致を検証する。追加fieldは任意であり、旧文書を強制変換しない。DB migrationは不要。

「取得元の更新」では、保持したfield／言語に対応する現在の訳文を、現在の公開原文の版に限定して取得する。Themeは日本語／英語の訳も明示的に探せるため、Capsule作成後に公開された訳文も比較して追加できる。同じ原文への新版訳は個別選択して草稿へ取り込む。原文が更新された場合、旧訳を新版原文へ付け替えない。対応原文を外す更新、または訳文が公開停止された場合は、その訳文を外すことも比較に示す。比較後の再照合、独自編集・配置の保持、保存と共有反映の分離を維持する。

翻訳生成の公開周辺文脈、原文／文脈hash、model／prompt／用語方針による再利用条件はR1g／R1iの実装・実評価を継承。今回のUI接続を理由に全量翻訳や外部AI全再評価を追加しない。time labelや自由な軸名への翻訳生成は、対応fieldを黙って増やすのではなく独自表示として保持する。
