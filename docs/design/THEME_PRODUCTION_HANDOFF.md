# ChatGPT Webのテーマ制作・見直しの引継ぎ

## 責務と境界

ChatGPT Webの制作予定／独立した見直し予定が、同じ運営者の非公開案件を取得して継続する。Plunodeは状態・実行権・正確な未完送信・評価対象版を保存する。新しいLLM実行基盤・Worker・cron・公開画面・収集計画の転用は行わない。品質は現行の共通ガイド（確認時revision3／本文1.5、第10節）をChatGPTが判断し、サーバーは点数化しない。

## 保存と操作

追加member migration044の独立schema `theme_production` に、所有運営者／配置環境、依頼・範囲・原稿／資料／素材参照を含む現在progress、Theme参照、phase、status、未完作業・阻害要因、状態版、実行ID／lease、直近の全体評価、保存済み送信を保持する。一運営者／環境で未完案件を一つとし、取得は案件を作らない。過去の冪等操作記録は監査用で、通常の再開レスポンスへ過去のAI理由を積み上げない。

MCP操作は案件作成、現在／指定案件の読取、phaseを指定した排他取得、保存／延長／解放／制作→見直し引継ぎ／全体評価／完了、送信の事前保存、保存済み送信の実行。既存scopeと運営者認証を再利用する。

制作と見直しを独立phaseとして保持し、`waiting-publication`等のstatusからphaseを推測しない。制作から見直しへの引継ぎでleaseを解放する。executionIdはChatGPT一回の起動全体に同じUUIDを使い、API呼出しごとに別ターンと数えない。専用ターンの起動はChatGPT側の指示の責務。

## 競合と送信境界

状態版＋owner＋有効lease＋executionId＋操作requestIdを検査する。期限後は新しい実行が引き継ぐ。期間は既定15分、明示延長可能。古い実行は更新できない。

登録・更新・翻訳等は、既存command全体をJSON wireとdigestで先にcommitしてから別操作で送信する。保存前に配送しない。案件単位のadvisory lockで取得・保存・送信意図の記録を直列化し、取込先の実際の書込transactionでも同じlockとleaseを確認する。調査・検証待ちで長いsession lockを保持せず、期限後の引継ぎを妨げない。knowledge DBへの同期訳文公開だけは、短い公開commit区間をmember側の同じfenceで囲む。保存済みrequestIdの通常APIへの迂回送信は拒否する。通常の手動登録は従来どおりで、案件へ登録したrequestIdだけを制御する。

送信前のdurable marker、送信後の実結果、工程の品質判定を分ける。応答喪失時はgetで既存receiptを確認し、有効leaseで同一wire／requestIdを再送する。受理済みの通常処理はlease終了だけで取り消さない。旧受付の反映待ちがある間、競合する新Theme更新を重ねず、訂正・再試行は既存の項目版制御を使う。処理未完を公開済み／評価済みと扱わない。

## 全体評価

現在の公開Theme版と固定原本、可視性、表示訳文、テーマ画像・編集情報、紹介商品と全要素の関連商品の参照版をdigestへ含める。テーマ版を増やさない訳文／関連商品変更も旧評価を無効にする。評価は全体を対象に行ったこと、対象digest、現行ガイド版、結果、未解消の物理的例外を記録する。完了は見直しphaseのみ、未反映なし、全体評価が現在の対象・ガイドと一致した場合に限る。過去完了を現在の合格と返さない。APIは文章品質の判断そのものを代行しない。

## 検証と反映

隔離member／knowledge DBで同時取得、状態版／期限／所有者、配送直後中断と冪等回復、反映待ちから見直しへの復帰、訳文等の変更による評価失効、一般投稿維持・運営AI送信0を確認する。既存テーマ・ガイド本文・予定・収集計画は変更しない。MCP schema／技術ガイドと既存Appへ反映する。通常ChatGPT Web予定での実運用確認は別であり、API試験で済んだと報告しない。
