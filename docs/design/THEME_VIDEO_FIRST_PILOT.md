# 初回の企画と試作手順　初代ウォークマンの二つの端子

2026年11月24日・制作前の作業票。[チャンネルの編集方針と三本の編成案](THEME_VIDEO_CHANNEL.md)を、最初の一場面で試す。下の語りと画面は比較・改稿用の見本。

## 脚本担当に渡す企画

**仮題「初代ウォークマンには、ふたりで話せるボタンがあった」**。サムネイル案は一台から二組のヘッドホンへ延びるコード。題名で会話できることを明かし、絵で「このつなぎ方で、どうやって？」と思える組み合わせを試す。核は、同じ曲が二人に届いた後で、隣の人の声をどう届けるかという小さな困りごと。二つの端子と一つのボタンを見返したとき、隣に座っていた人まで思い浮かぶ一本にしたい。

カセットを知らない人には、テープに入った曲をその場で二人が聴くのに必要なことだけ渡す。初代機を知る人には、盛田が友人と出かけたときの記憶を届ける。累計販売台数、社内の賛否、歴代機種、開発者の人物紹介は今回の焦点から外す。「マイクがあるなら録音もできたのか」という自然な疑問には、再生専用であったことを本編で短く答える。

**企画段階で外した筋**は「録音機能を削る英断が世界を変えた」。魅力は伝わりやすいが、成功を説明するには販売や利用実態の根拠が要る。今回は、実物に残る機能と一人の回想から具体的にたどれる範囲を深くする。生成画像で外装・端子の位置を補うと、それ自体が歴史資料に見えてしまう。模式図には「しくみの図」と付け、実物の配置まで再現した印象を避ける。

## 最初の紙芝居

下表の各行は、観客が一つのことを受け取るまでのまとまり。横長の左に本体、右に聴き手を置く案で示す。一行の中で語りを何文にするか、カットを何個にするか、何秒置くかは仮読みで決める。

| 場面 | 仮の語り | 見せるもの・聞かせる順序 | 視聴者に残ってほしいこと |
| --- | --- | --- | --- |
| 一台、二人 | 「1979年の初代ウォークマン。ヘッドホンを、もう一組つなげます。」 | 既につながった一組を見せ、本体を画面に残したまま二本目の線を延ばす。先端を目で追う間、次の説明を待つ。 | 左右の耳用の端子が別々なのでなく、二人が一組ずつ使える。 |
| 二人で聴いてみると | 「盛田昭夫は、友人と車で出かけたときのことを書いています。同じ曲は聴ける。ところが、ひと言話すたび、ヘッドホンを外すことになった。」 | 同じテープから音が届く二人を同じ大きさで置く。片方がヘッドホンに手をかけたところで少し待つ。画面の端に「盛田昭夫の回想をもとにした図」。 | 二つ目の端子で解決したことと、そこで初めて生じる不便の両方が分かる。 |
| 声の通る道 | 「初代は、録音のできない再生専用機です。でもマイクはあります。このボタンを押すと、いま隣で話す声が、ヘッドホンに届きます。」 | 二本のコードを残す。ボタンとマイクの関係を順に示し、声が二人に届くところまで見る。ボタンに「ホットライン」と添える。音を使うなら説明用の短い自作音。録音の再現と受け取られる台詞や当時の曲は要らない。 | 「ホットライン」はその場の声を聴くための仕組み。曲を録る機能ではない。 |
| 最初の一台をもう一度 | 「曲を聴くための端子が二つ。隣の人と話すためのボタンが一つ。」 | 冒頭と同じ構図に戻す。目が二つの端子とボタンを拾える間は余計な音を重ねない。リンクは概要欄へ。 | 初代機の小さな操作部に、二人で聴いている姿が重なる。ここで閉じても一話が完結する。 |

この四場面が短くまとまるなら、そのまま一話にできる。数分の尺を試すときは、友人が聴いていた曲が誰の演奏だったかという、同じ場面を豊かにする選択肢がある。盛田は、同行した作家・庄司薫の妻でピアニストの中村紘子による演奏を用意したと記している。固有名詞を増やすなら、人から人へ何を聴かせたかったのかが伝わる場合に使う。仮読みで会話の不便を見失うなら短い案に戻せる。[回想の車中のくだり](https://bunshun.jp/articles/-/5676)

**語り口の比較。** 「時代を変えた驚きの機能です」と言うと、視聴者が感じる前に評価が決まってしまう。「同じ曲は聴ける。けれど、隣の人が何か言ったら？」なら、端子とボタンの間にある不便を自分で想像できる。一方で毎回クイズのように問いかけると疲れる。上表では回想を語る箇所を平叙文にした。仮読みでどちらが自然に耳に入るかを試す。

## 企画から脚本、脚本から映像へ

| 工程 | 次の担当に渡すもの | 何が起きたら戻すか |
| --- | --- | --- |
| 題材を選び、大筋を立てる | 公開テーマの版、採用する記録と該当箇所、補った原資料、観る前後で変わる見方。二案を短く比べ、採る筋と今回捨てる筋を明記する。 | 題名への答えを言うと先に観たいものがなくなるなら、題材内の別の関係へ。 |
| 語りと画面を一緒に下書きする | 意味のまとまりごとに、仮の言葉、実際に見えるもの、見る順序、音・字幕、主要な言明の根拠を対応させる。素材が仮なら明記する。 | 絵が音声の飾りになっている区間は、画面で何に気づけるかまで戻る。図にする価値が薄い場面は声だけにしてよい。 |
| 狙いを伏せて読み、改稿する | 先に作品だけを渡す。受け手が面白いと感じた箇所、取り違え、置いていかれた場面を記録し、その後で企画と照合する。残す長所と変更理由を各一行で添える。 | 「便利な古い機械」で終わるなら要点と大筋へ。「端子一つが片耳用」に見えるなら図へ。単に語尾が気になるなら文だけを直す。 |
| 清書し、映像担当へ渡す | 改稿後の確定稿そのもの、読み方、字幕、素材とクレジット、図の意味、同期の合図、前の画面から残すもの。参照は採用した版に固定する。 | 代替素材で証拠の意味が変わる、新しい断定が要る、同期に無理がある場合は、元の場面を改稿してから渡し直す。 |
| 仮動画を等速で通して観る | 実際に確認した映像・音声・端末条件と、残った問題。意味・根拠を変える修正は確定稿にも反映する。 | 誤読、音量差、見切れ、字幕と図の競合は該当箇所へ。映像にしてなお発見が弱い場合は、尺の調整を続けず企画へ。 |

引き渡しの具体例は「『もう一組』で二本目が現れ、一組目は残る。二本の行き先が見えるまでマイクの話を始めない」。声の実測尺に合わせた秒数や描画方法は映像側で決められる。完成画面で字幕がヘッドホンを隠すなら、位置や間を変える。声を消して字幕だけにした場合も、語りだけを聞いた場合も、どこで誰が何をできるかを追えるか試す。図の違いは色に加えて線種・ラベルでも表す。

添付原案の要点整理から清書までの十工程は、このように戻り先のある仕事にまとめた。複数回の評価にはそれぞれ異なる問いが要る。資料の正確さは原資料で確かめ、初見の理解は狙いを見せずに確かめ、間や抑揚は実際の音と映像で確かめる。AIによる疑似初見の指摘は改稿候補として扱い、実視聴の記録と区別する。

## 小さく試して判断する

1. **まず紙芝居一組と冒頭の別案。** 上の四場面を同じ仮声で読む。Aは端子から入る。Bは「友人に、その奥さんのピアノを聴いてもらう。盛田昭夫が車に持ち込んだのは、そんな一本のカセットでした」と、聴かせる相手から入る。後半と題名はそろえ、同じ人に両案を先に見せて答えを教えてしまうのを避ける。制作時間は資料の照合、素材の用意、改稿に分けて控える。
2. **初見の人に、答えを含まない問いを渡す。** たとえば題材に詳しくない人と知っている人を含む4〜6人に、各人一案を見せる。最初に「友達にこの一本の話をするなら？」とだけ聞く。次に「もう一度見たいところ」「分かりにくかったところ」を聞く。説明を聞き直さずに二人への音の経路を指せるかを見る。少人数は誤解を特定するための目安で、優劣の統計判定には使わない。
3. **作品の評価とチャンネルの評価を分ける。** 視聴後、同じ題材の「初代機と軽いヘッドホン」、異分野のプーさん、Webbの三枚を同じ大きさで示す。「今日はここまで」も選べる。選んだ理由と元々の関心を聞く。異分野を選んだだけでは再訪の証明にならない。次の実作ができた時点で、実際に観たか、その回単体でも満足したかを確かめる。
4. **何を作るかを決める。** 複数人が端子や録音を同じように取り違えたら、その箇所を描き直してから通し試作へ。機能は伝わり、人と一緒に使う情景が誰の感想にも出なければ、盛田の回想を入口に戻す。発見が別々の言葉で語られ、音の行き先も読み取れるなら、冒頭の人気投票を重ねず横長一本の仮動画へ。不評でも具体的に気に入られた場面は残す。

公開後にYouTubeを使う場合、維持率の落ち込みや繰り返し再生が出た区間を、同じ場面への自由回答、字幕・端末条件と照合する。再視聴は見どころの再観察でも、図を読み取れなかった結果でも起こる。異分野の回への実際の移動と、Plunodeに原資料を探しに行く行動には、それぞれ別の意味がある。[YouTubeによる視聴者維持率の読み方](https://support.google.com/youtube/answer/9314415?hl=ja)

公開後にテーマの該当記録が訂正された場合は、固定版と場面の対応から影響を受ける語り・画面・題名を特定する。中心の発見を変える訂正なら動画自体を改訂し、補足で足りる場合は該当箇所と出典が分かる訂正を添える。

**制作着手の境目。** いま渡せるのは、出典付きの企画、場面の見本、比較案、戻り先。次の制作単位はこの紙芝居の仮読みと初見確認である。素材選びに時間を使ったのか、発音や間の調整を反復したのかを一度経験してから、`isinxnisi/auto-summary-news` と `isinxnisi/ns-auto-video` の音声尺計測・素材参照・描画などを必要な処理ごとに照合する。生成方式、定期制作の本数、縦長の画面構成はこの試作で得た材料を使って決める。
