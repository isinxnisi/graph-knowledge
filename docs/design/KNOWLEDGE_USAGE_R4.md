# R4 検索・表示・保存の利用接続

2026-11-07 R4a完了、次はR4b｜R4はbまで｜全体はR6まで。R3までの共通原本・公開世代・自動整理・定期収集を利用者の通常経路へ接続する。R4全体の範囲は再計画を維持する。

## 区切り

- **a：検索・関係探索・焦点と再訪**。通常の検索・一覧から旧KGと新しい公開対象をすべて探せるようにし、分類・関係条件を取得前に適用する。続きを明示し、先頭ページだけの絞込を全件検索と見せない。同一対象の近傍・経路を現在有効な版付き判断から読む。対象→Themeに焦点を渡し、元探索の位置・条件を保持する。Record直リンクの再読込と固定版活動を確認する。
- **b：時間入力・多言語・Capsule**。時刻・部分期間・周期／定性軸・複数時間・子軸参照の入力から表示・保存までを揃える。Theme訳と各fieldへの入口、固定保存と差分取込、文脈・cache条件を閉じる。aの完了をR4全体の完了としない。

## aの判断

旧KGを無条件で新原本へ大量に再登録せず、既存の全件検索を維持し、新公開対象の一覧を同じ既存の行表現で補う。名前の一部・分類・関係・周辺／収録範囲をサーバーで照合し、続きを読める。片方の接続失敗で他方の既存表示を消さない。

同一性はIDの置換ではない。現在公開中で内容版も一致する判断のグループを読み、近傍・経路・Theme候補を広げる。元のRecord端点・固定版・Capsule断面を書き換えない。近傍cursorには照合グループを含め、解除後に古い続きへ誤接続しない。

Themeへの焦点は明示的な対象IDとして渡し、固定snapshot内の対象だけを選択する。同一性で見つかった別IDはTheme側の実IDへ解決する。対応しないIDを勝手な行や架空Entityへ変えない。TOP／テーマ検索からの表示は従来の初期表示を維持する。

検証は変更した境界の自動テスト、既存の実データに対する読取、PC／390pxの代表操作まで。R1〜R3のAI全再評価や全件目視を追加しない。DB変更が必要になった場合だけ追加migration・復元検証を行う。通常の管理者承認・共有Kev変更・VPS切替は追加しない。
