# 受入済み知識更新とテーマ制作の分離

対象は受入検査済みの `accept-record`。収集予定・AI審査・制作案件・共通知識の公開契約は変更しない。

## 原因と経路

`deliver_collection` → `knowledge-missions` の配送／import受付 → 資料照合と既存受入検査 → `knowledge-foundation.accept-record` → 共通知識の保存とテーマpin追加。最後の処理が常にテーマの現在headへ追加し、編集と同じ `put(theme)` でdraft時刻だけを進めていた。承認公開版は進まないため、知識追加だけでも `workingChanges` になった。

## 方針の比較

- 最新headを自動承認：未公開原稿・訳文を巻き込むので不採用。
- 未公開原稿がある間は公開への知識追加も延期：安全だが、受入済み情報を読者へ届けられず、制作と収集が干渉するため不採用。
- **承認済み版を親とする知識更新版と、未公開原稿を分離する**。受入済みpin差分だけを適用し、公開と履歴保存を同じ短い既存writer transactionで行う。

## 公開・版・履歴

- 公開版だけがある場合：公開版＋受入Recordから新版を作り公開headを進める。
- 本当の作業版がある場合：公開版＋受入Recordを公開し、元の作業版を親とした別の作業版を残す。番号は全体で単調増加する。作業版の見出し・本文・Story・画像・商品・年表編集を公開版へコピーしない。
- 作業版へは三者比較で知識差分を反映する。同じpinを明示的に削除／置換していたらその選択を保持する。
- 新規未公開テーマ：受入が許された運営内部経路でも非公開のまま。一般の収集は既存の公開参照検査を維持する。
- 公開版に同じRecord版があれば、別受付でも無変更。元requestIdの再送は既存operationsの結果を返す。未公開原稿から削除したpinを再送で復活させない。
- 公開元の固定済み訳文・画像だけを継承する。グローバル訳文headは新たに承認しない。訳文だけの未反映編集もpendingを保つ。
- knowledge migration **011-theme-knowledge-updates.sql** の追記専用履歴に親版・公開／作業区分・Record版・元actor/requestを保存する。元operationへのFKは同一transactionの最後の保存まで遅延検査する。既存SQLのchecksumは変更しない。
- Theme訳文の継承はこの親版をたどる。公開／作業の分岐を番号順の編集／撤回と取り違えない。通常編集のedit/revert保護は維持する。
- 旧公開版・承認履歴・Capsuleの固定参照は変更しない。

## 制作案件

新規制作と原稿編集は従来の独立した全体見直し／公開切替を必要とする。資料収集で見直しを起動しない。

完了済み案件は、現在の公開版から追記専用の公開知識更新履歴だけをたどって評価済み版へ到達し、評価済み旧版の**現在の参照情報を含むdigest**・ガイド・登録状態が変わっていない場合、完了を維持する。ただし `lastWholeThemeAssessment.current` を新版の合格に偽装しない。原稿・訳文・商品等の実変更は従来どおり見直しが必要。進行中の制作／見直し案件の実行権や工程は操作しない。

## Webb 28→29の限定復旧

本番受入履歴・operations・配送主体・ID／版・固定content digestと、差分が既存pin末尾の受入Record一件のみであることを照合する。最新head29／公開28に別編集があれば停止する。29のcontentや元受付は書き換えず、元operationに結びつく知識更新履歴と公開履歴を追記して29を公開する。旧28の履歴は残す。未承認のTheme訳文は継承せず、実在すればpendingを維持する。

`scripts/repair-webb-collection-publication.ts --check/--apply` は本番DB／正式origin／固定Webbだけに限定した保守CLI。新MCPツールは追加しない。適用は配置手順のwriter停止・最終backup後に行い、再実行は検証済み結果を返す。βには本番Webbデータをコピーしない。

## 配置

同一固定sourceからWebとknowledge-opsを構築する。両DBbackupの隔離復元、011適用・再適用・既存行保全・限定復旧の検証を先行する。本番のWeb／既存3 Workerを停止して最終backup→011→限定復旧→同sourceのWeb／Workerへ切り替える。予定設定・ガイド本文・会員DB migrationは変更しない。失敗時にDBや旧Webへ機械的に巻き戻さず、公開状態を再照合して前進復旧する。
