# 実betaコミュニティの入力保持とナビゲーション

2026-10-24。`78021a4` 以後のmain（開始時 `60fba73`）を基準とした実機能の修正。3275の架空データ試作と本番は対象外。

## 原因と修正契約

旧CommunityPageはfocus／visibility／pageshow／定期取得で最初にdataとuserをnullへ戻していた。ページ全体の再読込ではなく、フォームのunmountと入力stateの初期化が原因。隔離DB・実OIDCの画面でfocusだけで通報入力欄が消えることを修正前に再現した。

`useCommunitySession` は通常の再取得と再認可を分離する。同一User・同一対象・同じ参加世代／権限ではsubtreeを維持する。非表示・認証通知・BFCache復帰時は内容をinertかつ非表示にし、開いたdialogも閉じ、再認可後に同じフォームへ戻す。別User・401／403／404・参加世代／role／状態変更では入力を破棄する。古い応答は世代番号で拒否する。入力はメモリのみで、URL・History・storageへ保存しない。

書込は読取用AbortControllerと分離し、focusによる再取得で中断しない。処理中の再取得はまとめて後から行う。既知の失敗と送信結果不明をtyped resultで返す。冪等操作の結果が不明なら同じ入力とrequestIdを保持し、表示のrevisionが変わっても元の送信を再確認する。サーバーの期待版検査は迂回しない。

通報はnative modal dialogへ移動。タイトル・タブを押し下げない。背景クリックでは閉じず、Escape／キャンセルも入力があれば破棄確認を出す。既知の失敗では編集を維持し、版変更なら明示した再試行だけ新しい版を使う。結果不明では入力を固定して同じ送信を再確認する。成功時だけ閉じ、受付案内を表示する。再認可中はdialogも非表示にし、復帰時のフォーカスを保持する。

## 画面の範囲

- 共通ヘッダー：サイト探索と公開コミュニティの発見。アカウントメニューの「参加・運営」は自分の参加先。
- 共通PersonalNavigation：「見つける」「自分のスペース」「自分の活動・履歴」。既存MemberCapsules本体を再利用し、会員データや処理を複製しない。
- 個別コミュニティ：名前・公開状態・参加状態の下にスレッド／管理／メンバーを招待／管理履歴。受信した招待と管理者の招待発行を区別する。
- 上位メニューはaria-current、内部タブはaria-pressedをURLの状態から決定。内部切替もブラウザBack/Forwardに残し、ページングと画面内のスクロール復元を継続する。上位メニューは通常スクロール、スマホは横方向のメニュー領域とし、固定領域を積み重ねない。
- ログイン案内は操作と説明をまとめ、同一originのコミュニティURLにだけ戻す。個人Capsuleは従来通り、コミュニティCapsuleは準備中のまま。

## 重要操作

退出は参加設定内へ移す。本人が最後の管理者かを認可済みdetail DTOに追加して説明を分ける。参加世代も本人のdetailだけで再認可の判定に利用する。DB schema・権限規則は変更しない。最後の管理者の退出ではアーカイブ、旧限定会話の非復活、運営判断→本人承諾→再開の別操作を明示する。

復帰申請と取消は確認dialogを経由する。非公開の現在名を取得せず、対象IDと操作結果を表示。キャンセルでは送信しない。申請による自動権限付与は行わない。
