# 実beta：認証表示・共通枠・対応待ち招待

2026-10-24。開始main `5f902e1`。3200／graph-betaの実機能を対象とし、3275の架空試作・本番・公開KG・Worker・Kev・DB schemaは変更しない。

## 原因と変更

- `useMemberIdentity` がfocusごとにnull化し、ヘッダー・会員・コミュニティが別々にプロフィールを取得していた。nullを未ログインと表示し、CommunityPageの初期busy=falseも未ログイン案内の瞬間表示を生んだ。
- `/member`↔`/communities`の通常anchorはdocument全体を読み直していた。ページごとに同じ見た目のヘッダー／メニューを作ってもDOM・表示状態は共有されていなかった。
- hashをEffectで読むまで既定の一覧・現在地を描き、取得済みcommunity.roleも現在地の判断に混ぜていた。

表示用本人情報をrootの単一メモリstoreへ集約。初回checking／authenticated／guest／errorと既知状態のrecheckingを分離する。要求を重複排除し、通常移動では30秒以内の表示用確認を再利用。APIの認可を省略するものではない。認証通知では世代を更新して旧応答・旧招待情報を拒否する。ストレージには本人情報・私的本文・草稿を保存しない。

`app/(personal)/layout.tsx`で既存ヘッダー・PersonalNavigation・フッターを一度描き、会員／コミュニティの本文をchildrenとして切り替える。URLは従来どおり。cross-pageの内部移動はNext Link、同ページhashは履歴とhashchangeを維持する。既存MemberCapsules本体・編集・Graph保存は再利用。個人Capsuleのqueryは同じアカウント内のタブ移動で保持する。

### 表示契約

| 状態 | 共通枠 | 本文 |
|---|---|---|
| 初回確認中 | 認証確認中。未ログイン確定表示を出さずメニュー領域を確保 | hash未確定なら目的地以外を描かない。公開ディレクトリはcredentialsを省いた匿名読取で独立表示可能 |
| ログイン済み／通常再確認 | 本人表示・メニューを維持 | ページAPIごとの取得状態を表示 |
| 401で未ログイン確定 | ログイン入口とゲスト用項目 | 公開情報、またはログイン案内 |
| 認証確認失敗 | 認証失敗と再試行。既知の本人表示と認可を分ける | hard再認可が失敗したprivate本文は表示しない |
| 対象403／404 | アカウント全体をguestにしない | 対象の内容・草稿を破棄し、対象の取得失敗を表示 |
| 別User／ログアウト | 旧招待と旧本人情報を引き継がない | 旧応答拒否・期待User照合、本人の入力保持契約を継続 |

前回のCommunity再認可時の非表示／inert、同じ参加世代のdraft保持、通報の同一requestId再送は維持。入力を保持するためにサーバー認可を緩めない。

## 対応待ちの招待

`GET /api/communities/invitations/summary` → `{pendingCount:number}`。session／active本人を確認し、本人宛て・期限内・pending・活動中コミュニティ・現役管理者の発行世代・招待先の参加世代・再受入要件をSQLで評価する。一覧のLIMITや先頭ページの件数を利用しない。名前・本文・他Userの件数は返さない。migrationなし。

アカウント入口（閉じたメニューの外から見える位置）と「届いた招待」に同じstoreのバッジを表示する。未取得は「…」、失敗は「!」と説明、確定0は数字なし。未読とは呼ばず、閲覧だけでは減らさない。最大99+表示。幅を確保し、小さな更新でレイアウトを動かさない。

前面の30秒周期とfocus／visibility／BFCache復帰で更新。複数表示部品は通信を共有し、招待承諾・辞退等の成功後も更新する。バックグラウンドでは新しい周期要求を送らず、復帰時に確認する。期限切れ・他人の取消は次回確認まで最大約30秒（通信遅延は別）残り得る。メール／push／既読管理／AIは実装しない。

## 実betaで見つけた追加修正

同じページ内のhash移動で作った履歴から別ページへ移動すると、BackでURLだけが戻り本文が残った。hash移動をNextのHistory API経由にし、ルーターの履歴情報を保持したうえで既存hashchange処理を通知する。Community内リンク・個人メニュー・ヘッダーで同じ方式を使用する。実際の往復をブラウザ回帰へ追加した。

英語320pxの認証確認表示の重なりも修正。追加試験の初回は開発コンパイル中の15秒APIタイムアウト、英語見出しとメニュー名の試験側の混同を切り分けた。認可やタイムアウトを緩めず、準備後に再検証する。
