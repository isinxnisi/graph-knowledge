# 知識DB投影の比較と検証（2026-11-19）

## 隔離環境での比較

変更前はmainの `95337a6a`、候補は012と共用投影・関係範囲に限った隣接認可。独立したPostgreSQL 16のDBとNeo4j 5.26.31の試験用コンテナを使用した。各DBで同じ合成データのRecord 1,600件を公開し、テーマ-only更新8回、Record訂正8回、80関係に波及するEntity訂正1回、検索・前世代のカーソル・隣接各50回、旧KG巡回5,000件を同じ版で5回実行した。

| 指標 | 変更前 | 変更後 |
|---|---:|---:|
| 試験DB全体の割当サイズ | 155.44 MB | 37.71 MB |
| 巡回行／台帳 | 25,000行／5件 | 5,000行／1件 |
| 巡回テーブルと索引の割当サイズ | 8.39 MB | 1.14 MB |
| 生成世代数 | 18 | 10 |
| テーマ-only更新  p50／p95 | 10.35／13.51秒 | 1.08／1.43秒 |
| Record訂正  p50／p95 | 10.98／13.61秒 | 2.29／2.98秒 |
| 初回投影／80関係の対象訂正 | 15.93／14.40秒 | 10.33／2.28秒 |
| 現役のRecord検索  p50／p95 | 368／1,235 ms | 385／1,111 ms |
| 前世代のカーソル  p50／p95 | 2,918／5,570 ms | 2,463／5,784 ms |
| 隣接取得  p50／p95 | 3,006／4,938 ms | 357／987 ms |
| 変更なしの巡回一覧  最小〜最大 | 11.70〜19.48秒 | 35〜75 ms |

アプリサービスの往復時間を含むWSLでの1系列の値。検証・buildも同じ開発PCを使用したため数％の差はばらつきを含む。前世代カーソルのp95は約4%上昇した。幅広い部分一致語での旧世代検索には秒単位の遅延が残る。検索観測に関する採用判断は、現役検索のp95と隣接の改善、固定APIと同じ権限判定、テーブル容量の減少を合わせて行った。巡回計測は同じreleaseを返す試験用readerを使用。実稼働では旧KGのreleaseを軽い照会で確認する。

新規書込みの比較は、同じ負荷で蓄積する論理行と、試験DBが割り当てた容量を示す。既存β・本番のDBファイルやホストディスクの空き回復量の測定値には使わない。ベースラインを独立したDBへ複製し、旧投影28,800 Record行・28,818 Entity行、巡回25,000行、現役ID・原本・過去ledgerを保った012適用と冪等性を確認した。隔離での適用は219 ms。約130万行の既存本番投影の処理時間とは区別する。
