# U6b：取得済み資料の読解・個別自動登録（2026-11-04）

## 現在地

βの運営画面「資料の収集」に、取得済み資料・公開先Theme/Entity・収集範囲を固定して読解・登録する経路を追加した。資料の通常保存や一覧閲覧からは外部処理を開始しない。通常の支持された項目は全件の人間承認を挟まず、共通原記録→通常publisher→検索・図へ進む。

**U6全体は未完了**。後追い意味整理・まとめて適用、Chat側のパッケージ貼付/取込、その経路まで含む実テーマ一巡は後続。U7統合受入とU8正式公開は別工程。

## 今回の判断

- 利用者投稿の審査案件を収集用に偽装せず、collection主体による限定accept-recordを使う。対象/テーマ・取得原本・引用を固定し、公開直前にも現在の参照・公開範囲を確認する。
- 新しい関係名は具体語を保持。新規対象は引用と一時IDで参照し、名前だけで既存対象へ統合しない。テーマなしのEntity対象にも接続でき、テーマ対象には互換な追記をする。旧Theme版や保存済みCapsuleを差し替えない。
- AIの抽出と、その項目の支持確認を別試行にする。原文一致、対象の接続、両端、肯否、時期の型/精度も機械確認する。AI応答不明・ACK喪失・取消を、新たな無制限推論や公開重複で回避しない。
- 新規ID候補はnew:1〜4の小さいenumとし、存在する対象IDと日付欄を混同しにくくした。原出力は保存し、形式を人が書き換えて受理しない。
- 収集対象の選択条件と、知識の事実上の限定を分けた。共同参加者の一部を図に載せることは、ほかの参加者がいないという主張ではない。選択条件はuserデータへ隔離し、system命令へ連結しない。
- 全体の無料枠は既存80回/日・2400回/月・token/RPM/TPMを維持。先行の固定20回を、収集と評価を合わせて日/月とも全体の1/3（現在26回/日・800回/月）へ統一した。開発評価も同じcollection枠へ計上し、既存の全体台帳を迂回しない。未報告の思考tokenは0とせず出力予約を残す。

## 登録負担と利用量

今回の実経路はNASAの取得済み1資料を再利用。成功依頼は、資料選択1件、公開先の検索/選択、範囲入力（各約100字）、外部処理と公開の確認1件、実行で進む。運営者が資料・対象・範囲を決めた部分は自動化していない。引用選択、Entity候補・関係名、個別支持確認、通常受理と公開は自動。初期の形式/範囲不具合による再依頼2回も、実測記録から除外していない。

成功2依頼の作成から支持確認応答の記録までは実測16,854ms/18,826ms。入力時間、公開投影の完了、ブラウザpollまでを含む総操作時間の実測ではない。人の入力所要時間は計測しておらず、登録に何分かかるという推定値へ読み替えない。

実資料は読解4回/支持確認4回の計8回（失敗も含む）。入力11,563 token、候補2,273 token。思考内訳は全8回未報告のため出力予約16,384を維持した。先行評価15回も含めcollection23/26回、同じproject全体の利用枠へ計上した要求70/80回。保存試行は72件で、送信前取消2件を外部呼出へ数えない。台帳の回数/予約はリセットしていない。

## 残る制約・次の単位

U6bの基本接続まで。1区画最大2候補の有限抽出で、資料全体や指定範囲の網羅を保証しない。今回のTheme依頼もNASA/同社の両役割を一度に全抽出したという結果ではない。対象を選び直したThemeなし経路で別の関係を確認した。

具体語の語義/同名の後追い整理、Chatパッケージ取込、異なる二つ目の実テーマを収集経路で一巡させる確認は後続。登録候補には独立移入された同名Webbが複数あり、名前一致の自動mergeはしない。候補の見分けと同一性整理も次工程で扱う。語の途中から始まる文脈抜粋、英語の限定表現などの読みやすさは改善余地がある。

新共通Entity/Recordと旧KGの通常対象検索の横断、保存/共有/訂正までの統合再確認はU7。prototype専用 `/themes/explore` はβで404のまま。公開検索APIと、新規対象選択・Recordからの通常Graphを確認した事実から、通常検索UI全体の統合済みを主張しない。正式VPSへの配置はU8。

U6の残りは「後追い整理」「パッケージ取込と総合一巡」を基本追加1〜2回の指示で進める推定。U7/U8は別。通常収集に管理者の全件承認を戻さず、整理の確認を公開必須のgateにしない。
