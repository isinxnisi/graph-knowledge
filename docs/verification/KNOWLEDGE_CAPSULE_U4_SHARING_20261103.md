# U4：年表Capsuleの共有・現在停止・OGP接続

2026-11-03。U4の基本実装をmain／3200／HTTPS β／3276へ反映。前段の[保存・時期フォーム](KNOWLEDGE_CAPSULE_U4_BETA_20261103.md)、[原記録／Theme構成の明示取込](KNOWLEDGE_CAPSULE_U4_UPDATES_20261103.md)に、同URL共有・版付き会話・固定掲載・現在の表示停止・年表OGPを接続した。契約は[U4設計](../design/KNOWLEDGE_CAPSULE_U4.md)。本運用全体、一般投稿AI審査、収集切替、本番公開の完了ではない。

## 確認先と操作

日常確認先は https://graph-beta.isinxnisi.com/ 。既存GoogleアカウントのMy Capsulesから **U4確認｜Webbの年表と共有**（保存版4）を開く。共有画面から同じ有効URLを取得できる。限定リンクを公開リポジトリの本文へ追加せず、完了報告と開発PCのprivate検証記録に残す。

1. 共有を開いて現在の公開版を確認する。編集→保存だけでは共有は進まない。「保存した変更を共有へ反映」で同じURLへ反映する。
2. 共有ページで履歴とコメントの「投稿時の図」を開く。版2・3のコメントが残り、現在は版4を読める。閲覧中の内容は自動で新しい版に差し替えない。
3. 既存の「コミュニティと管理のテスト状況」のCapsule欄では **U4確認｜Webbの年表と共有（更新）** が保存版3の参加者限定掲載として残る。リンク版4へ自動追随しない。
4. **U4確認｜年表の共有停止** は別に作成した停止確認用の保存版1。共有を停止済みで、保存文書は残る。自分のデータを削除せず、停止と保存の違いを確認できる。

## 実装の判断

既存の共有・会話・コミュニティを再利用した。新しい共有サービスや別の版管理画面は増やしていない。指定した保存版をfreezeし、公開履歴と投稿対象版を保持する。通常保存と公開反映、URL再発行、停止の区別も継承する。

初回freezeと掲載では、原本baselineのRecord／Entity／Source／Mappingを指定された公開版の内容・作成時刻・理由と照合する。公開IDだけを借りた改竄断面を拒否する。Theme pinを含め、現在のvisibilityと、その版が実際に公開された履歴を確認する。現在がprivateのheadや一度も公開していない版を返さない。作者の独自名・説明・注記・時期・配置は別の編集値として保つ。

共有HTML・JSON・画像は同じ読取処理を使う。履歴・コメントごとの文脈・固定掲載と一覧／会話カード／掲載先・通報時の内容検査にも同じ現在確認を通す。公開世代の再生成を待たず停止を反映する。raw baselineも返す形式なので、作者が図から除外した参照も確認対象に含む。一覧候補はLIMITより前に確認し、同じ参照はまとめて照合する。参照群が多ければ400群ずつ処理する。

知識の読取障害では公開面を閉じる。表示中の新断面も再確認が失敗すると閉じ、コメント草稿は既存の親側cacheに保つ。初回の一時障害後も、同じ指定版を「リンクを再確認」で再取得できるようにした。不正な版指定を最新版に付け替えない。本人だけが持つ保存文書や、自分の投稿の撤回まで禁止しない。

年表／並列の初期表示では、固定した作者編集済み文書から主軸の一部をカードにする。最大4注釈とその終点を描き、点・期間・発生時期の幅を区別する。共通のcalendarGraphで年月日の精度と不確かな境界を解釈し、境界の幅が重なれば確かな内部期間を捏造しない。同じ単位の期間にも短い長さを残す。周期の折返しや別軸を同じ暦へ変換しない。時期なし情報は件数で示す。関係図初期表示のカードは従来表示を維持する。1200×630、版番号付き画像URL、no-store。画像を読まれたときに生成し、保存・共有の完了に画像生成を待たせない。

実画面でスマホの作者名・handleがタイトルを圧迫することを見つけ、Capsule見出しの作者表示をスマホではプロフィールへ進むアイコンに圧縮した。専用行を足していない。また、通信中のコメントに「投稿結果不明」が同時表示される紛らわしさを修正した。
