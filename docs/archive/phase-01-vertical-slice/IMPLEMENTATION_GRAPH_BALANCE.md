## 問題と採用ルール

- 円状の初期配置が上下へ伸び、「全体を表示」で文字が小さくなる。初期は斜め45度から始まる横長の楕円とし、短いCanvasではさらに横へ広げて縦を縮める。Node16px / Edge15pxへ文字を大きくし、ラベル背景に5pxの余白を取る。
- 追加配置が最初に空いた場所を採用し、接続先への距離や既存ラベルを無視していた。新規Nodeだけを、接続先の重心・各接続先の周囲の有限候補から選ぶ。接続距離の目安225〜295、Node間200未満と楕円状の衝突を強く避け、端点とラベルの余白・既存ラベルの近さも評価する。中心からの拡がりには縦を横より強めに抑える評価を加える。
- 後から見つかる関係では、まだ関係のない既存Node同士が近すぎると短いEdgeが発生する。接続の有無に関わらず、全既存Nodeとの距離を候補評価へ含める。
- 双方向の制御点±24は線とラベルを分けるには狭かった。単独Relationは直線を保ち、複数Relationは実際の端点距離×0.32を70〜115に制限した範囲へ分散する。重み0.5。縦向きの組だけラベルに最大±18pxの縦オフセットを付ける。曲率は配置後・Nodeドラッグ終了後に更新する。
- 選択Edgeの細いラベル枠が窮屈に見えた。線を強調し、ラベルは淡い背景へ切り替える。
- 「全体を表示」の50px余白は短いCanvasの面積を圧迫していた。24pxへ縮小する。全体確認では縮小し、通常探索の初期zoomは可読性を優先する。パン・ズームを引き続き使える。

追加展開で既存Nodeの座標・pan・zoomを変更しない。配置は表示上の読みやすさのためで、距離に関係の強さや真偽の意味を持たせない。全体の反復レイアウトや新規ライブラリは追加しない。条件と数値はARCHITECTURE.mdの「Graph全体のバランス調整」を参照する。

## 残る制約

有限候補と中点に基づく近似評価なので、任意のデータ・探索順・手動ドラッグで全ラベルの衝突がなくなる保証はない。既存Nodeを固定するため、後から発見した接続の長さを常に最適化できるわけでもない。全展開を短い画面に収めると文字は小さくなる。全体表示で位置関係を確認し、拡大したGraphやテキスト一覧で関係を読む。
