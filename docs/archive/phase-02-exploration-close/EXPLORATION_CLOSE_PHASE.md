2026-10-03。推奨探索モデルを基準にした実装準備。**復元UXは「休止した子孫も復元」で承認済み。移行順序1〜4を実装済み。** 実施結果は [IMPLEMENTATION_EXPLORATION_CLOSE.md](IMPLEMENTATION_EXPLORATION_CLOSE.md) を参照。

[EXPLORATION_MODEL_REVIEW.md](../../design/EXPLORATION_MODEL_REVIEW.md) を前提とする。今回のフェーズは単一起点の自由探索に「展開を閉じる／再開する」を加える。フィルタ、複数起点UI、時系列、個別非表示、pin、API・DB・fixture変更は含めない。

## 復元UXの選択肢

| 案 | 再開時の動作 | 利点／負担 |
| --- | --- | --- |
| 毎回最初のページから取得 | 以前の続きを捨て、子孫も再クリック | 単純だが、探索の絵が戻らず通信が増える |
| そのEntityだけ復元 | 受理済みページを戻すが、到達不能になった子孫の展開意図を解除 | 戻る範囲が小さいが、以前の探索を辿り直す必要がある |
| 休止した枝も復元（推奨） | 受理済み範囲と、再到達した開いた子孫の受理済み範囲を戻す | 探索の絵を戻せる。子孫が戻る説明と上限検証が必要 |
| 再開するたび選択ダイアログ | 上記を毎回選ぶ | 自由度はあるが操作が重く、初期フェーズには非推奨 |

現在のNodeクリックは選択＋未展開なら一段階取得、右詳細には「続きを表示」、展開済みNodeには二重枠がある。この流れに合わせ、**閉じたNodeのクリックも選択＋再開**とする。閉じる操作は右のEntity詳細と隣接一覧の見出し部分に同じ操作を設け、開閉フェーズ当初はNodeクリックをトグルにしなかった。その後の承認により、選択中Nodeの再クリックだけ300ms判定後に開閉する。詳細は [GRAPH_INTERACTION_AND_SETTINGS.md](../../design/GRAPH_INTERACTION_AND_SETTINGS.md) を参照。

推奨案の契約:

- 明示的に閉じたEntityは閉じたまま。祖先の閉じるによって到達不能になった子孫は「休止」であり、開く意図を残す。
- 再開によって再到達した休止展開を、受理済みページだけ復元する。未取得のページ・中断したページは取得しない。自動多段取得は行わない。
- 例：A→B→C→Dを開いた後Bを閉じ、Bを再開すると、B・Cの受理済み展開が戻る。Cを先に明示的に閉じていたならCの展開は戻らない。別経路で支えられる対象は閉じる時から残る。
- キャッシュがない再開は、一段階目を通常取得する。その後はクリックで進める。中心の検索し直し・ページ再読込では探索キャッシュをリセットする。
- 詳細には「展開を閉じる」「展開を再開」、未取得には「近傍を展開」を使用する。再開可能なキャッシュがある場合だけ「取得済みの枝も復元します」と短く補足する。
- 二重枠は現在有効な開いた展開を示す。取得済みで閉じた状態は二重枠にしない。選択枠・肯否・Node形状は維持する。
- 復元時は「取得済みの枝を復元しました」と状態通知する。キャッシュ消失時は再取得することを伝える。通常の選択だけでは閉じた枝を残す指定にならない。
- 起点も閉じられる。起点Nodeだけは残るが、他に有効な取得元がなければ周辺は消える。「閉じている」を「孤立Entity」と表示しない。

## 状態と責務

現在のgraph-state.ts / use-graph-explorer.ts / GraphCanvas.tsx / Explorer.tsx / EntityDetails.tsx / RelationsList.tsxを確認した。

- 取得キャッシュ：Entity・ClaimのID辞書。詳細APIの取得結果で探索Claimを追加しない。
- 展開記録：Entity ID、固定の無条件取得スコープ、open意図、受理済みページ（入力cursor、Claim IDs、出力cursor）、hasMore、通信・エラー・上限状態。初回未取得と0 Claimの受理済みページを区別する。
- 起点：内部ではroots配列の境界を用意するが、このフェーズでは1件だけ。centerIdが必要な配置処理は唯一の起点から導出する。
- 表示対象：起点から到達済みの開いた展開に属するClaim・両端点の最小集合を純粋関数で導出する。独立した可変の表示辞書を正本にしない。
- 表示Relation、Graph、テキスト一覧、カウントは同じ表示対象を使用する。cache件数を画面件数にしない。
- 世代番号は中心変更に、展開ごとの要求番号は局所的な閉じる・休止・再取得に使用する。AbortControllerだけに依存しない。pendingの解除はその要求自身に限り、新しい要求を古いfinallyで消さない。

合流はページ所属の重複を許し、切断された循環は起点からの最小到達集合で除く。双方向APIから同じClaimを取得していても、他の有効な展開が支えるなら残る。「閉じる」はそのNodeに接する全辺の非表示ではない。この意味は操作説明にも残す。

## 上限・キャッシュ・復元の失敗

- 表示上限100 Entity / 200独立Claimを維持する。新しいページは候補表示を導出して検査し、超過ならページ全体を拒否、cursorを進めない。
- 枝の復元にも同じ検査を行う。休止子孫を含む復元候補が超過する場合は**復元全体を拒否**する。表示・open意図・cursorは変更せず、選択は維持して「他の展開を閉じて再試行」を提示する。順番による部分復元は行わない。
- 閉じるで余裕ができたら、以前のblockedを永久ロックにしない。再試行・再開操作で候補を再検査する。上限エラーの解消だけで自動通信しない。
- 初期の一時キャッシュ上限は400 Entity / 800 Claimとする（表示上限の4倍、性能目標ではなく有限化の初期値）。到達不能・閉じた展開を利用の古い順に破棄し、ページ所属・cursorも一緒に破棄する。複数展開が参照するデータは残す。
- 有効表示と進行中要求の記録は退避破棄しない。受理時に安全な破棄で予算内にできなければ新規ページを拒否しcursorを維持する。詳細コンポーネントは現在どおり選択単位で保持し、無制限な詳細キャッシュを追加しない。
- この予算と復元検査はフロントのセッション内だけの責務。DBに探索状態を保存しない。

## UI・配置・選択の整合

1. GraphCanvasは消失Edge→消失Nodeの順に差分削除する。Relationが残って所属Claimだけ変わる場合は既存Edgeを更新する。
2. 残ったNodeの位置、pan/zoomを維持し、閉じる・再開のたび全体fitや初期レイアウトを実行しない。
3. 消えるNodeの座標を同じ探索世代の一時辞書に保持する。再表示では以前の座標を優先し、現存Nodeと衝突する場合だけ既存の追加配置ルールでそのNodeを配置する。座標辞書もEntityキャッシュの破棄・世代リセットに追従する。
4. 再表示Nodeは新規取得と同じ淡い外枠を使用できる。状態通知で復元と取得を区別し、Graphへ常時説明ラベルを増やさない。
5. 閉じたEntityが残れば選択を維持する。選択Entityが消えたら起点に選択を戻すが、自動展開はしない。選択Claim / Relationが消えたら選択を解除する。
6. Relationの所属が変わっても詳細APIの全公開Claim比較は維持する。Graph上の現在の所属ID集合を詳細へ渡し、画面内／Graphには未表示を区別する。詳細取得は閉じた枝を戻さない。
7. 通信中でも「展開を閉じる」を可能にする。閉じた展開と新たに到達不能になった展開の要求を無効化・abortし、loadingを解除する。旧応答は表示・cursor・エラーを変更しない。
8. 未取得、開いて取得中、開いて受理済み、閉じた取得済み、休止、上限停止、失敗を区別する。隣接一覧が空であるだけで孤立と判定しない。

## 実装順序と完了条件

### 1：契約と受け入れ例

復元UXを確定し、合流・共有Claim・切断循環・明示的に閉じた子孫の小さいテストデータをテスト内で作る。demo.jsonの意味やAPIを変更しない。

### 2：展開記録と表示導出

graph-stateのページ所属と純粋な表示導出を追加し、hookが取得結果を記録するよう切り替える。初期Graph・追加ページ・既存上限の動作を維持する。React標準stateを継続する。

### 3：表示の差分同期

Graphと一覧を同じ表示対象へ切り替える。差分削除・位置保存・選択の整合・Relation所属更新を追加する。テーマ・曲率・データの意味は変更しない。

### 4：開閉と通信・上限復旧

Entity詳細と一覧から開閉し、休止／復元・要求無効化・上限再試行・キャッシュ破棄を実装する。単一起点の探索でフェーズを完了する。

受け入れ検証:

- 単純な枝、起点の閉じる、孤立Entityの開閉。
- 合流先の保持、共有Claimの保持、切断された循環の除去。
- 再開時の受理済み子孫復元、明示的に閉じた子孫の非復元、復元で通信が発生しないこと。
- 複数ページのcursor維持、中断ページの非受理、再開後の「続きを表示」。
- 閉じる／休止中の遅い応答、素早い再開、中心変更、古いfinallyと新要求の競合。
- 新規ページと枝復元の上限拒否、閉じた後の再試行、キャッシュ破棄後の再取得。
- Relationの所属・異説ありの更新、詳細比較の維持、選択消失と一覧の同期。
- 残存Nodeの座標・pan/zoom保持、再表示座標、テーマ切替の回帰。

純粋関数・hook・コンポーネントのテストで共有と競合を検証する。Playwrightは実DBの既存fixtureで初期探索→追加展開→閉じる→再開→詳細・一覧の経路と回帰を検証する。実DBを止める必要のない通信競合・大きい上限ケースはテストで制御したAPI応答を用いる。typecheck / lint / test / Playwright / buildを実施する。
