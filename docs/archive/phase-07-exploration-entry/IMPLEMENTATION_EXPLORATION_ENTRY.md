# Phase 07：探索の入口・条件提示の再構成

2026-10-04。Phase 06の既存機能を使い、人物検索 → まず辿る → 必要なら条件調整、という入口へ整理した。DB・API・schema・データ・語彙は変更しない。[採用レビュー](../../design/EXPLORATION_ENTRY_AND_CONDITIONS_REVIEW.md)を基準にした。

## 以前の問題と採用した画面

左190pxに検索・全predicate・制作Roleが常時並び、名前を探す前から制作役割まで判断させていた。右300pxはRole・刊行物限定・複数Claim・Citationの読取時に折り返しが多い。検索語、起点、選択中対象、見る関係の位置づけが画面では曖昧だった。

左は人物検索に限定し、中央上部に起点、適用条件、条件編集の入口を置いた。未選択時には人物名・別名を検索して候補を選ぶ案内を示す。v2 badgeは「少数実データパイロット v2」とし、非網羅・資料の範囲という注意を維持する。制作Roleをサービスの入口として強調しない。

「見る関係を編集」からnative dialogを開く。Graphの縦領域を常時圧迫せず、確定／未適用を同時に見分けられる案を選んだ。Escape／キャンセルとフォーカス復帰を使える。背景操作は編集の間だけ止め、Graph自体は保持する。背景で既に始まっていた取得は通常どおり完了し得る。編集を開いたことによる取得・abortはない。

## stateとRoleの契約

- SearchPanelの検索語・検索結果は従来どおり独立。検索実行だけでGraphは変わらず、候補選択で既存chooseRootを呼ぶ。現在選択中Nodeは起点とは別に表示する。
- 有効条件はGraphStateのpredicates／contributionRoles。外側RelationFilterはeditingだけを持つ。内側ConditionEditorは開く度に有効条件からdraft／draftRolesを初期化する。
- 要約は有効条件のみを参照する。編集画面には「編集中・未適用」の別要約を示す。取消時はdraftごと破棄。再編集時に未適用変更を復元しない。
- 変更の適用時だけ正規化した条件をchangePredicatesへ渡す。同条件は適用を無効化。取得・世代番号・cursor・枝の再取得契約は変更しない。
- Roleはdraftの制作関与が有効な場合に追加導線から開く。無指定と指定のradioを分け、個別Roleチェックは指定時だけ表示する。空Roleでは制作関与が表示されない旨を明示する。他predicateは除外しない。
- 全Role指定は広いClaimを除くため「役割で絞らない」と同一ではない。Graph上部の要約には制作関与とRoleの作用対象を残す。制作関与を外した適用では既存正規化がRole条件を解除する。
- 新規表示文字列・要約はlib/i18n/exploration-entry.tsにまとめ、localeから解決できる境界を維持する。全面翻訳・言語切替を追加しない。

## 詳細とGraphの維持

「詳細を広く読む」で右を340〜480pxへ切り替える。検索・Graphを残す三列構成であり、別ページや全面モーダルへ詳細を移さない。右は独立してスクロールでき、Graphのモデル座標・pan/zoom・選択・受理ページは変えない。幅の減少で見切れる部分は手動pan/zoomや既存「全体を表示」で確認する。自動fitで利用者の視点を変えない。

1160×650等の低い画面では、説明・選択フィードバック・凡例・一覧の余白を調整してGraphを最低270px確保する。隣接一覧は維持し、短い画面ではスクロールして使う。

回帰確認で、保存済み位置が既存Nodeから200px以内なら再配置する旧処理が、変更後の画面高に応じた初期配置を復元時に動かすことを検出した。復元対象には保存座標を優先し、新規Nodeだけを追加配置する最小修正をGraphCanvasへ加えた。データ・受理範囲・開閉意図は変更しない。既存の全展開→閉じる→再開の厳密な座標比較で検証した。

## ブラウザ観察

v2実DBの長崎尚志からPLUTO／MASTERキートン／BILLY BATを辿り、他の人物へ展開。5件の受入Roleと広いClaimを詳細で確認した。初期にRoleチェックはなく、人物検索から無条件で一段階表示できる。Roleの編集導線は条件編集内で見つけられる。

取消／Escape後の通信件数・GraphのNode／Edge・モデル座標・pan/zoom・選択を厳密に比較。全Role指定では長崎尚志のClaimが6→3、役割無指定へ戻すと3→6となり、明示適用ごとに一回取得する。詳細幅の切替でも同じ状態を比較した。刊行物scopeを広げた詳細で読め、Nodeへ戻って別の枝を展開できる。

1160×650でも条件ダイアログ内をスクロールして全条件・適用操作へ到達でき、Escapeでも取消できる。既存ブラウンのダーク配色も目視確認した。

## 残る点と次フェーズ

名前を知らない利用者向けの開始例は未実装。条件は探索全体に作用し、適用時に開閉意図をリセットするため、編集内の説明は必要。部分Role条件が長い時は要約が折り返す。短い画面は詳細・隣接一覧のスクロールが必要で、幅変更時にはGraphの一部が見切れることがある。モーダル編集とGraph操作を同時に行う方式は採用していない。

一般Entity検索へ進む前には、対象種別・同名識別・検索limit・結果の補助情報・既存人物APIとの互換を決める必要がある。検索条件と探索条件を混同せず、検索対象が作品でも人物との関係を除外しない。制作の役割から人物職業を推測しない。

次は少量v2を使った利用者観察、または既存kindに限定した一般Entity検索の小さいフェーズが候補。名前が分かる対象からの入口を広げるなら後者が自然。開始例・プリセット・保存・taxonomy・データ増量は需要を確認してから扱う。
